## 1. 这个项目是什么

**Cairn**（cairn /kɛərn/，登山者沿途堆的石堆路标）。

个人自用的学习闭环工具：把文本 / 网页 / 视频采集进本地知识库，由 LLM 自动分类、摘要、结构化，形成可阅读、可检索、可生成学习页、可出题练习的知识资产，并用番茄钟记录学习时间。

一句话验收标准：**每天结束时，你能真的用它学点东西。**

## 2. 红线（任何会话都不得违反）

1. **不做多用户、账号、权限、云同步、移动端**
2. **不做番茄钟的应用锁定 / 网站拦截 / 白名单**（v2 再议）
3. **不引入多 Agent 框架**（LangGraph / CrewAI / AutoGen / DeerFlow 一律不用）。所谓"子 Agent"是按任务类型路由的固定 LLM 调用管线
4. **不引入 ORM 的对象关系自动映射**，用 Pydantic 模型 + `repo/` 薄封装（语义化方法，内部是可读的 SQL）。搜索与向量层本来就是 raw SQL
5. **不引入整包 UI 组件库**（Element / Ant / Naive 等），原生 CSS + 自建组件。富文本编辑器同理不引（Markdown 源码编辑是允许的）。**允许单点引入专用小库**（见 §2.1）
6. **不引入独立向量数据库**（Chroma / Qdrant / Milvus），向量与业务数据同库
7. **API Key 永不出现在前端、日志、异常栈、git 历史里**
8. **任何异步失败都必须落到 `agent_task` 表并在前端可见**，不许静默死亡
9. **新需求先记入 backlog，不进当前里程碑**

### 2.1 第 3–6 条的真实理由与解除条件

> 这四条不是"简单就是好"的口号，每条都有具体理由、具体代价、以及**明确的解除条件**。完整论述见 ADR-020。
> 想推翻其中任何一条，先读 ADR-020 的「代价」与「解除条件」，再判断是否真的命中。

| 限制 | 最硬的那个理由 | 我承认的代价 | 什么条件下解除 |
|---|---|---|---|
| 不多 Agent 框架 | 本项目的流程**没有分支**（输入→输出固定），框架的核心价值用不上；而调试时要穿过多层抽象 | 早期没有现成的状态可视化 | 出现"LLM 自主决定下一步做什么"的场景（如学习教练自选复习策略） |
| 不用 ORM 自动映射 | **FTS5 的 `MATCH`/`bm25()` 与 `vec0` 的 `MATCH ... k=` 是 ORM 死角**，项目的核心查询恰好全在这里 | 手写 SQL 易拼错、字段改动要改多处、无类型提示 | 出现大量多表 JOIN 与复杂关联的业务表（目前没有） |
| 不引整包 UI 库 | 本项目 7 个页面需要的控件（输入/按钮/Tab/列表/进度条/弹窗/Toast）**全是 HTML 原生**；真正需要组件库的数据表格、日期范围、可拖拽树、文件上传，一个都没有 | 按钮/弹窗/Toast 样式自写，多花约 2–3 天 | **单个控件**自写成本超过半天 → 只引那一个专用小库，不引整包 |
| 不引独立向量库 | 个人知识库三年约 2.4 万 chunk，sqlite-vec 在**几十万**量级仍是毫秒级；两份数据不同步是每天的运维负担 | 无法水平扩展、无法多进程并发写 | chunk 超过 50 万，或需要多人/多设备并发 |

### 5.1 信息冲突的裁决链（重要）

文档之间不可能永远一致。出现矛盾时**不许自行判断**，按下面顺序裁决，并把裁决结果回写：

```
L0  本文件 §2 红线 + §3 技术栈      ← 不可被任何文档覆盖
L1  contracts/数据契约、接口契约     ← 跨会话共享的事实，高于任何阶段说明
L2  contracts/决策记录（ADR）        ← 选型理由，想改必须先加新 ADR
L3  当前里程碑文档                   ← 本阶段的任务与实现细节
L4  其他里程碑文档                   ← 默认不读；M5 整合阶段例外
L5  archive/                        ← 永久失效，任何情况下不作为依据
```

**发现冲突时的标准动作**（不许跳过）：

1. **停手**，不改代码
2. 在 `HANDOFF.md` 的「待裁决冲突」区记一条：哪两份文档、哪一句、各自怎么说
3. 按上表定优先级，改低优先级的文档使其一致
4. 重新跑 `python tools/doc_check.py`
5. 只有 lint 通过后才继续写代码

> 理由：一旦允许"我觉得应该按 A 来"就地改代码，文档体系当场失效——因为下次没人知道代码到底服从谁。

### 5.2 文档自我失效约定

里程碑验收通过后，**在该文档标题下第一行盖一个完结章**：

```markdown
> ⚠️ 本里程碑已完结（tag `m1-done`）。本文档内容代表当时的实现意图，可能已与代码不符。
> 需要了解**现状**，请读代码与 `http://127.0.0.1:8756/docs`，不要读本文档。
```

旧文档主动退场，比留着等人误读安全。`doc_check.py` 会检测"已完结文档是否仍被当现状引用"。

### 5.3 自动校验

```bash
python tools/doc_check.py
```

检查：作用域声明是否齐全、ADR 引用是否存在、端点引用是否已登记、文档里新建的表是否已在数据契约登记、是否误引归档内容、已完结文档是否被当现状引用。

**每次改完文档都要跑，每次会话开场也要跑。** 它不阻止你读错，但它让"读错"和"写歪"立刻暴露。


## 6. 会话工作法

**开场三件事（顺序不可颠倒）**

1. 读 `00-总纲.md` 全文 + 当前里程碑文档全文。**到此为止**——不主动去翻其他里程碑或归档
2. `python tools/doc_check.py` 与 `cd backend && uv run python scripts/status.py` 各跑一次 —— **用事实确认状态，不信文档记述**
3. 读 `HANDOFF.md` 最后 2 条，确认上一会话留下的问题与待裁决冲突

**读取纪律（写给自己看的）**

- 需要接口细节 → 只打开 `contracts/接口契约.md` 的对应小节，不要通读
- 需要表结构 → 只打开 `contracts/数据契约.md` 的对应小节
- 想改技术选型 → 先读 `contracts/决策记录.md` 相关那条，看完"推翻成本"再决定
- 发现某份文档提到了别处的内容 → **不要顺着链接去读**，按 §5.1 走裁决流程
- 唯一例外：M5 整合阶段允许通读 M1–M4

**收尾三件事**

1. 跑本里程碑的 `scripts/verify_mN.py`，全绿才往下走
2. 在 `HANDOFF.md` 追加一条（模板见该文件）
3. `git commit`，message 用 `feat(Mn): Tn.x 描述`；里程碑验收通过则打 tag `mn-done`

**中断规则**：绝不在函数写到一半时结束会话。宁可多写 10 分钟收个尾。

## 7. 全局代码约定

| 项 | 规定 |
|---|---|
| 端点写法 | 用 `def` 不用 `async def`（DB 与模型推理都是同步阻塞，FastAPI 自动丢线程池） |
| 错误响应 | `{"error": {"code": "...", "message": "...", "detail": "..."}}` |
| 列表响应 | `{"items": [...], "total": n}` |
| 时间格式 | ISO 8601 带时区，如 `2026-11-05T20:30:00+08:00` |
| 中文写盘 | `json.dumps(..., ensure_ascii=False)` |
| 日志 | `logging` 按天滚动到 `data/logs/app.log`；每次 LLM 调用写 `llm_call_log` |
| Prompt | 全部放 `backend/app/prompts/*.md`，代码只引用文件名 |
| 文件长度 | 单文件 ≤300 行，超了拆 |
| 外部能力 | 一律走 adapter 基类 + 实现，便于替换与 mock |

**已知坑与记录**

- 本机访问 gyan.dev / GitHub Releases 只有 ~7KB/s，**直接下载 ffmpeg 静态包不可行**。以后装大体积工具统一走 `https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge`（实测 5MB/s）
- `winget install Gyan.FFmpeg` 在本机被拦截（需要提权），不要浪费时间重试
- 当前 ffmpeg 是 4.3.1（2020 年版本）。音频提取与 16k wav 转换已验证可用；若 M2 遇到新编码器不支持，再升级到 7.x 静态包
- ffmpeg 装在 Anaconda 的 `Library\bin` 下，**卸载 Anaconda 会连带丢失**。M5 打包时要把 ffmpeg 一起打进 `resources/`，不能依赖系统 PATH
- **PATH 里的 `git` 是 WorkBuddy 精简版**（`D:/workbuddy/resources/vendor/PortableGit`，2.55），
  **缺少 `git-remote-https`**，无法推送/拉取 https 远程。要用完整版：
  `"C:\Program Files\Git\cmd\git.exe"`（2.49）
- 本 shell 继承了代理 `http://127.0.0.1:3669`，访问 github.com 需要 20 秒以上；
  需要认证的 git 操作（push/fetch）在非交互会话里会卡住（GCM 弹窗起不来），
  **这类操作交给用户在普通终端或 GitHub Desktop 里执行**
- GitHub 凭据尚未缓存，首次推送会弹出浏览器登录
- **HuggingFace 直连不可用**：bge 模型与 whisper 模型都从 HF 下载，`.env` 里已预设 `HF_ENDPOINT=https://hf-mirror.com`，**不要删掉这一行**，否则 M3 的 embedding 模型下载会卡住
