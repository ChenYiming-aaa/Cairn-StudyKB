# 接口契约 v1.0

> **作用域**：只读本文件 + `00-总纲.md` + `决策记录.md`。**不要读** `milestones/*`（那是各阶段的任务说明，不是接口真相）。
> **冲突时**：本文件与任何里程碑文档冲突，**以本文件为准**。发现冲突不改代码，先在 `HANDOFF.md` 记一条待裁决。
> **唯一真相**：代码落地后本文件的权威性移交至 FastAPI 自动生成的 `/docs`（OpenAPI）。
> 迁移完成当天在此写明："⚠️ 唯一真相已迁移至 `http://127.0.0.1:8756/docs`，本文件仅做变更登记"。
> 前端只允许通过 `frontend/src/api/client.js` 调用，不得在组件里手写 URL。

## 1. 通用约定

- 前缀统一 `/api`
- 所有请求/响应 `Content-Type: application/json`，SSE 端点除外
- 错误统一：`{"error": {"code": "FETCH_BLOCKED", "message": "目标站点拒绝访问", "detail": "..."}}`
- 列表统一：`{"items": [...], "total": 123}`
- 耗时操作统一：先返回 `{"task_id": "uuid"}`，前端轮询 `GET /api/tasks/{id}`

## 3. 关键端点详细形状

### POST /api/knowledge

```json
// 请求
{ "title": "可选，缺省取正文首行前 40 字作占位标题", "raw_content": "必填", "source_type": "text" }
// 响应 201
{ "id": 12, "title": "...", "status": "pending", "chunk_count": 7, "duplicated": false }
// duplicated=true 时说明内容哈希撞上已有条目，此时 id 指向已有条目，不新建
```

### GET /api/knowledge

查询参数：`source_type` `category` `status` `q`（标题模糊） `tag`（标签精确匹配，走 `json_each`） `page`（默认1） `page_size`（默认20，上限100）

```json
{ "items": [{ "id": 12, "title": "...", "source_type": "web", "category": "学习方法",
              "tags": ["专注"], "status": "ready", "created_at": "..." }],
  "total": 37 }
```

### GET /api/knowledge/{id}

```json
{ "id": 12, "title": "...", "source_type": "web", "source_url": "https://...",
  "raw_content": "...", "summary": "...", "key_points": ["..."],
  "structured_note": "# ...", "note_edited": 0,
  "category": "学习方法", "tags": ["专注"], "status": "ready",
  "truncated": 0, "created_at": "...", "updated_at": "..." }
```

`note_edited=1` 时，前端在"重新整理"按钮旁提示"将覆盖你手动编辑的内容"。

> 创建时的 `title` 只是占位（正文首行前 40 字），整理成功后会被 Agent 生成的 ≤20 字标题重写。

### PATCH /api/knowledge/{id}

```json
// 请求（字段全部可选，只传要改的）
{ "title": "新标题（≤20 字，超长 422）", "category": "学习方法", "tags": ["专注"],
  "structured_note": "# 一级标题\n\n## 二级标题\n- 要点" }
// 响应 200
{ "id": 12, "updated_at": "...", "note_edited": 1, "note_chunk_count": 3 }
```

**副作用（必须实现）**：请求里带了 `structured_note` 时，后端要

1. 把 `note_edited` 置 1
2. 删除该条目 `source='note'` 的 chunk，用同一个 chunker 重新切块写入
3. 不触发重新整理，不覆盖其他字段

> 用户手写的内容必须能被检索到，所以 note 也要进 chunk。这是刻意的设计，见数据契约 §6。

### POST /api/knowledge/{id}/organize

```
→ 202 { "task_id": "uuid" }
```

- 未配置 Key → 400 `LLM_NO_KEY`（**不派发注定失败的任务**）
- 条目已在整理中 → 409 `ITEM_BUSY`，不重复派发
- 条目不存在 → 404 `ITEM_NOT_FOUND`
- 条目 `status` 先置 `organizing`，任务结束后由 Agent 置 `ready` 或 `failed`
- 成功时同时**重写 `title`**（Agent 生成，≤20 字）；手填标题也会被覆盖
- `note_edited=1` 时前端必须先确认「将覆盖手改内容与标题」，再发请求（数据契约 §3）

### POST /api/knowledge/organize-pending

```
?limit=20（默认 20，上限 100）
→ 200 { "items": [{ "item_id": 12, "task_id": "uuid" }], "total": 1 }
```

只挑 `status='pending'` 的条目，逐条派发独立任务。返回的 `items` 为空表示没有待处理条目。

### GET /api/knowledge/{id}/mindmap

```
?theme=light|dark   （默认 light）
Content-Type: image/svg+xml
```

返回纯 SVG 片段，**不含 `<script>`、不含任何外链**，可直接 `<img src>` / 内联嵌入。

- 数据来源：`structured_note` 的 Markdown 标题层级，**不经 LLM**
- 每次现场生成，不缓存（笔记一改就得跟着变）
- 无标题时退化：以条目 `title` 为根、`key_points` 为一级子节点
- 条目不存在 → 404 `ITEM_NOT_FOUND`；`structured_note` 为空 → 返回单节点 SVG，不报错

### POST /api/ingest/url

```json
// 请求
{ "url": "https://...", "force": false }
// 响应 202
{ "task_id": "uuid", "existing_item_id": null }
// 若该 URL 已存在且 force=false，直接返回 { "task_id": null, "existing_item_id": 12 }
```

错误码：`FETCH_TIMEOUT` `FETCH_BLOCKED` `FETCH_EMPTY` `FETCH_INVALID` `FETCH_DNS` `URL_INVALID`

### POST /api/ingest/video

```json
{ "url": "https://...", "model": "small", "language": "zh" }
→ 202 { "task_id": "uuid" }
```

任务 `stage` 依次为 `metadata` → `downloading` → `transcribing` → `saving`。
错误码：`TRANSCRIBE_NO_FFMPEG` `TRANSCRIBE_YTDLP_FAIL` `TRANSCRIBE_NO_AUDIO` `TRANSCRIBE_MODEL_FAIL` `TRANSCRIBE_UNSUPPORTED`

### GET /api/tasks/{id}

```json
{ "id": "uuid", "type": "transcribe_video", "status": "running", "progress": 42,
  "stage": "transcribing", "error_code": null, "error_msg": null,
  "output_json": null, "created_at": "...", "updated_at": "..." }
```

### GET /api/search

```json
// ?q=番茄钟&limit=20
{ "items": [{ "chunk_id": 88, "item_id": 12, "item_title": "...",
              "snippet": "...前后各 60 字...", "match_type": "fts" }],
  "total": 4, "fallback": "none" }
// match_type: fts | like | vector
// fallback: none | like_short_query | vector_disabled
```

### POST /api/ask（SSE）

```json
// 请求
{ "question": "...", "limit": 8 }
// SSE 事件序列
data: {"type":"sources","sources":[{"n":1,"item_id":12,"item_title":"...","chunk_id":88}]}
data: {"type":"delta","text":"番茄钟应"}
data: {"type":"delta","text":"该绑定..."}
data: {"type":"done","usage":{"prompt_tokens":1200,"completion_tokens":180}}
```

检索为空时**不发 sources 为空的事件**，直接：
`data: {"type":"no_result","message":"知识库中没有找到相关内容"}` 然后 `done`。**此时不得调用 LLM。**

### POST /api/html/generate

```json
{ "item_ids": [12, 15], "title": "学习方法专题" }
→ 201 { "id": 3, "title": "...", "size_bytes": 24567 }
```

### POST /api/quiz/generate（SSE）

```json
{ "item_id": 12, "types": ["single","boolean"], "difficulty": "understand", "count": 5 }
// count 上限 20
data: {"type":"question","index":0,"question":{"id":31,"type":"single","question":"...",
        "options":["A....","B...."],"answer":"B","explanation":"...","source_item_id":12}}
data: {"type":"question","index":1,"question":{...}}
data: {"type":"skip","index":2,"reason":"json_parse_failed"}
data: {"type":"done","count":4,"skipped":1}
```

### POST /api/quiz/submit

```json
{ "answers": [{ "question_id": 31, "user_answer": "B", "duration_ms": 8200 }] }
→ { "items": [{ "question_id": 31, "is_correct": true, "correct_answer": "B",
                "explanation": "...", "feedback": null }],
    "correct_count": 3, "total": 5, "accuracy": 0.6 }
// 简答批改失败时 is_correct = null，feedback = "批改服务不可用，已标记待人工判断"
```

### POST /api/session/start

```json
{ "target_type": "item", "target_id": 12, "planned_seconds": 1500 }
→ 201 { "id": 7, "start_time": "...", "planned_seconds": 1500, "status": "running" }
// 同一时刻只允许一个 running session；已有则返回 409 SESSION_ALREADY_RUNNING 并带上现有 id
```

### GET /api/session/current

```json
{ "session": { "id": 7, "start_time": "...", "duration_seconds": 320, "status": "running" } }
// 或 { "session": null }
```

### GET /api/stats/today

```json
{ "pending_items": 3, "due_reviews": 5, "focus_seconds": 4500, "sessions": 3,
  "accuracy_today": 0.72, "categories": [{"name":"学习方法","count":8}] }
```

## 4. 前端调用约定

- `client.js` 暴露 `get/post/patch/del`，自动拼接 baseUrl（优先级：`window.api?.baseUrl` > `import.meta.env.VITE_API_BASE` > 空串）
  - **空串的含义**：开发期由 Vite 的 `server.proxy['/api'] → 127.0.0.1:8756` 反代，前端走同源，不依赖 CORS
  - 生产（Electron `file://`）必须由 preload 注入 `window.api.baseUrl`，否则相对路径解析到 `file://` 会失败
- 统一处理 `error.code`，按前缀映射提示：`FETCH_*` → 采集失败类文案，`LLM_*` → 模型调用失败类文案
- SSE 用 `fetch` + `ReadableStream` 解析（**不用 EventSource**，因为需要 POST 与自定义头），封装成 `streamSSE(path, body, onEvent)`
- 轮询任务用 1.5s 间隔、指数退避到 5s，最多 20 分钟；组件卸载必须清定时器
