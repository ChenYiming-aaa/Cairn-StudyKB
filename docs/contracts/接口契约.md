> **作用域**：只读本文件 + `00-总纲.md` + `决策记录.md`。**不要读** `milestones/*`（那是各阶段的任务说明，不是接口真相）。

## 1. 通用约定

- 前缀统一 `/api`
- 所有请求/响应 `Content-Type: application/json`，SSE 端点除外
- 错误统一：`{"error": {"code": "FETCH_BLOCKED", "message": "目标站点拒绝访问", "detail": "..."}}`
- 列表统一：`{"items": [...], "total": 123}`
- 耗时操作统一：先返回 `{"task_id": "uuid"}`，前端轮询 `GET /api/tasks/{id}`

## 3. 关键端点详细形状

### POST /api/knowledge

```json
// 请求
{ "title": "可选，缺省取正文首行前 40 字作占位标题", "raw_content": "必填", "source_type": "text" }
// 响应 201
{ "id": 12, "title": "...", "status": "pending", "chunk_count": 7, "duplicated": false }
// duplicated=true 时说明内容哈希撞上已有条目，此时 id 指向已有条目，不新建
```

### GET /api/knowledge

查询参数：`source_type` `category` `status` `q`（标题模糊） `tag`（标签精确匹配，走 `json_each`） `page`（默认1） `page_size`（默认20，上限100）

```json
{ "items": [{ "id": 12, "title": "...", "source_type": "web", "category": "学习方法",
              "tags": ["专注"], "status": "ready", "created_at": "..." }],
  "total": 37 }
```

### GET /api/knowledge/categories

左侧分类树专用：全库聚合，**不设条数上限**（此前前端取前 100 条自行聚合，破百后计数偏低）。

```json
{ "categories": [{ "name": "学习方法", "count": 12,
                   "tags": [{ "name": "间隔重复", "count": 5 }] }],
  "counts": { "total": 37, "pending": 4, "organizing": 1 } }
```

- `category` 为空或 NULL 的条目归入 `未分类`，`tags` 为空数组
- 排序：分类按 `count` 降序后按名称；标签同理
- 标签来自 `json_each(tags)`，非法 JSON 视为空数组
- `counts.organizing > 0` 是前端决定「是否继续轮询刷新」的依据

### GET /api/knowledge/{id}

```json
{ "id": 12, "title": "...", "source_type": "web", "source_url": "https://...",
  "raw_content": "...", "summary": "...", "key_points": ["..."],
  "structured_note": "# ...", "note_edited": 0,
  "category": "学习方法", "tags": ["专注"], "status": "ready",
  "truncated": 0, "created_at": "...", "updated_at": "..." }
```

`note_edited=1` 时，前端在"重新整理"按钮旁提示"将覆盖你手动编辑的内容"。

> 创建时的 `title` 只是占位（正文首行前 40 字），整理成功后会被 Agent 生成的 ≤20 字标题重写。

### PATCH /api/knowledge/{id}

```json
// 请求（字段全部可选，只传要改的）
{ "title": "新标题（≤20 字，超长 422）", "category": "学习方法", "tags": ["专注"],
  "structured_note": "# 一级标题\n\n## 二级标题\n- 要点" }
// 响应 200
{ "id": 12, "updated_at": "...", "note_edited": 1, "note_chunk_count": 3 }
```

**副作用（必须实现）**：请求里带了 `structured_note` 时，后端要

1. 把 `note_edited` 置 1
2. 删除该条目 `source='note'` 的 chunk，用同一个 chunker 重新切块写入
3. 不触发重新整理，不覆盖其他字段

> 用户手写的内容必须能被检索到，所以 note 也要进 chunk。这是刻意的设计，见数据契约 §6。

### POST /api/knowledge/{id}/organize

```
→ 202 { "task_id": "uuid" }
```

- 未配置 Key → 400 `LLM_NO_KEY`（**不派发注定失败的任务**）
- 条目已在整理中 → 409 `ITEM_BUSY`，不重复派发
- 条目不存在 → 404 `ITEM_NOT_FOUND`
- 条目 `status` 先置 `organizing`，任务结束后由 Agent 置 `ready` 或 `failed`
- 成功时同时**重写 `title`**（Agent 生成，≤20 字）；手填标题也会被覆盖
- `note_edited=1` 时前端必须先确认「将覆盖手改内容与标题」，再发请求（数据契约 §3）

### POST /api/knowledge/organize-pending

```
?limit=20（默认 20，上限 100）
→ 200 { "items": [{ "item_id": 12, "task_id": "uuid" }], "total": 1 }
```

只挑 `status='pending'` 的条目，逐条派发独立任务。返回的 `items` 为空表示没有待处理条目。

### GET /api/knowledge/{id}/mindmap

```
?theme=light|dark   （默认 light）
Content-Type: image/svg+xml
```

返回纯 SVG 片段，**不含 `<script>`、不含任何外链**，可直接 `<img src>` / 内联嵌入。

- 数据来源：`structured_note` 的 Markdown 标题层级，**不经 LLM**
- 每次现场生成，不缓存（笔记一改就得跟着变）
- 无标题时退化：以条目 `title` 为根、`key_points` 为一级子节点
- 条目不存在 → 404 `ITEM_NOT_FOUND`；`structured_note` 为空 → 返回单节点 SVG，不报错

### GET /api/env/check

```json
{ "ffmpeg":   {"ok": true,  "detail": "4.3.1"},
  "whisper":  {"ok": false, "detail": "模型 small 未下载", "hint": "首次转录会自动下载（约 500MB）"},
  "embedding":{"ok": false, "detail": "未加载", "hint": "M3 首次使用自动下载"},
  "sqlite_vec":{"ok": false,"detail": "未安装（可选）", "hint": "M3 需要时 uv add sqlite-vec"},
  "llm":      {"ok": true,  "detail": "deepseek-flash"} }
```

- 失败项额外带 `code`；缺 ffmpeg 时 `code` 必须为 `TRANSCRIBE_NO_FFMPEG`（M2 §5 DoD）
- `hint` 是给人看的一句话，前端原样显示；不返回任何 Key 内容
- 只读探测：不加载模型、不下载模型

### POST /api/ingest/url

```json
// 请求
{ "url": "https://...", "force": false }
// 响应 202
{ "task_id": "uuid", "existing_item_id": null }
// 若该 URL 已存在且 force=false，直接返回 { "task_id": null, "existing_item_id": 12 }
```

- `force=true`：派任务重新抓取，**只覆盖正文** `raw_content` 并重建 `source='raw'` 的 chunk、状态回 `pending`；
  标题、分类、标签、摘要、`structured_note`、`note_edited` 一律不动（2026-11-06 裁决）。
- 任务 `type` 为 `fetch_url`，`stage` 依次 `fetching` → `saving`，`progress` 取固定值 10 / 50 / 90。
- `output_json`：`{"item_id": 12, "duplicated": false, "existing_item_id": null, "chunk_count": 3}`；
  同内容不同 URL 时 `duplicated=true` 且 `existing_item_id` 指向已有条目，**不新建**。
- **成功与否看正文，不看状态码**：知乎专栏页返回 403 却带完整正文，正文够 200 字就入库；
  只有 `404/410` 无条件判 `FETCH_NOT_FOUND`（那才是真没有页面）。
- **浏览器降级**：httpx 抓取报 `FETCH_BLOCKED` / `FETCH_EMPTY` 时，自动改用真实浏览器渲染
  再抓一次（知乎这类拦 TLS 指纹、或纯 JS 渲染的站点靠这条）。其余错误（超时 / DNS /
  404 / 非网页）不降级 —— 换浏览器也一样，只是把 30 秒拖成 60 秒。
  浏览器用本机的 Edge/Chrome（`BROWSER_CHANNEL`，默认 `msedge`），不额外下载 Chromium。
  降级成功时多花 3–5 秒；降级也失败时，取信息量大的那个错误上报。

错误码：`FETCH_TIMEOUT` `FETCH_BLOCKED` `FETCH_EMPTY` `FETCH_INVALID` `FETCH_DNS` `FETCH_NOT_FOUND`
`FETCH_LOGIN_REQUIRED` `FETCH_BROWSER_UNAVAILABLE` `URL_INVALID`

### POST /api/ingest/video

```json
// 请求（model / language 可省，默认 small / zh）
{ "url": "https://...", "model": "small", "language": "zh", "force": false }
// 响应 202
{ "task_id": "uuid", "existing_item_id": null }
// 若该 URL 已存在且 force=false，直接返回 { "task_id": null, "existing_item_id": 12 }
```

- 任务 `type` 为 `transcribe_video`，`stage` 依次为 `metadata`(0–5) → `downloading`(5–30)
  → `transcribing`(30–95) → `saving`(95–100)；`progress` 单调不减。
- **字幕优先**：`metadata` 阶段若该视频有中/英字幕（`subtitles` 优先于 `automatic_captions`，
  简体优先于繁体），直接取字幕入库，跳过 `downloading` 与 `transcribing`——
  `stage` 会是 `metadata` → `saving`。字幕链任何一步失败（无字幕 / 需登录 / 格式不认 /
  下载失败 / 解析为空）都静默退回语音识别，**不会让任务失败**。
  B 站字幕必须登录：在采集面板点「站点登录 → B 站」即可。登录助手把 cookie 导出成
  `cookies.txt`，路径规则与 `YTDLP_COOKIES` 一致（配了就用配置的路径，否则 `data/cookies.txt`），
  导出后立即生效，不需要重启。
- `output_json`：`{"item_id": 12, "duplicated": false, "existing_item_id": null,
  "chunk_count": 4, "duration": 312, "segment_count": 87, "language": "zh",
  "source": "asr"}`；`source` 为 `asr`（语音识别）或 `subtitle`（现成字幕）。
  `raw_content` 每行形如 `[mm:ss] 文本`，超过 1 小时用 `[h:mm:ss]`。
- **繁简归一（仅 `source=asr`）**：识别结果在拼行前按汉字段做一次繁→简转换，
  标点、英文、数字、时间戳不动（ADR-025）。`source=subtitle` 保留字幕原文，不做转换。
- 无音轨但有字幕的视频可以入库；既无音轨也无字幕才报 `TRANSCRIBE_NO_AUDIO`。
- **链接归一化**：入库前先收敛成「单条视频」的规范地址，同一视频的不同分享形式不会重复入库。
  - 抖音聚合页 `douyin.com/jingxuan?modal_id=<id>` → `douyin.com/video/<id>`
  - 抖音图文笔记 `douyin.com/note/<id>` → 保留原样，直接报 `TRANSCRIBE_UNSUPPORTED`
  - B 站去掉 `t` / `spm_id_from` / `vd_source` 等追踪参数，**保留分 P 的 `p`**
  - `youtu.be/<id>` → `youtube.com/watch?v=<id>`；`v.douyin.com`、`b23.tv` 短链先跟随跳转
  - 入库后 `source_url` 是归一化后的地址
- **抖音单独一条通道**：详情接口要 `a_bogus` 签名（签名在页面自己的 JS 里），
  yt-dlp 因此报 `Fresh cookies (not necessarily logged in) are needed`。
  实现改为用浏览器打开视频页、截获页面自己发出的 `aweme/detail` 响应拿媒体直链，
  再下 mp4 → ffmpeg 抽音轨 → 识别，`stage` 仍是标准的四阶段。
  这条通道需要 playwright 与可用浏览器，缺失时报 `TRANSCRIBE_BROWSER_UNAVAILABLE`。
- `source_type="video"`，标题取视频标题（截断 100 字）；抖音取文案第一段（`#` 之前），
  避免标题被一串话题标签占满。
- `force=true` 语义同 `/api/ingest/url`：**只覆盖正文**，标题/分类/标签/笔记不动。
- 去重规则与网页一致：同 URL 直接回 `existing_item_id`；同内容不同 URL 撞 `content_hash`
  时 `duplicated=true` 且不新建。

错误码：`TRANSCRIBE_NO_FFMPEG` `TRANSCRIBE_YTDLP_FAIL` `TRANSCRIBE_NO_AUDIO`
`TRANSCRIBE_MODEL_FAIL` `TRANSCRIBE_UNSUPPORTED` `TRANSCRIBE_BLOCKED`
`TRANSCRIBE_NOT_FOUND` `TRANSCRIBE_EMPTY` `TRANSCRIBE_BROWSER_UNAVAILABLE` `URL_INVALID`

### GET /api/auth/status

```json
// 200
{ "browser_available": true,
  "cookie_file": "…/data/cookies.txt",     // 没导出过则为空串
  "sites": {
    "bilibili": { "label": "B 站", "logged_in": true },
    "zhihu":    { "label": "知乎", "logged_in": false }
  },
  "login": { "status": "idle", "site": "", "message": "" } }
```

- 只读 cookies.txt 判断登录态，**不启动浏览器**，可以每 1–2 秒轮询。
- `login.status` ∈ `idle` / `running` / `success` / `failed`；`message` 是给人看的进度或原因。
- 判据是登录后才出现的 cookie（B 站 `SESSDATA`、知乎 `z_c0`），不是"有没有 cookie"。

### POST /api/auth/login/{site}

```json
// site ∈ bilibili / zhihu
→ 200 { "status": "running", "site": "bilibili", "message": "请在弹出的窗口里登录B 站" }
```

- 起一个后台线程弹出**独立**的浏览器窗口（不是用户日常那个），用户在里面登录；
  登录成功后自动把 cookie 导出成 Netscape `cookies.txt`，yt-dlp 与网页抓取立刻可用，
  **不需要改 `.env`、不需要重启**。
- 接口立即返回，进度靠 `GET /api/auth/status` 的 `login` 字段追。
- 同一时间只允许一个登录窗口（同一个 profile 被两个实例打开会直接崩）；
  上一轮还在 `running` 时再调用，原样返回当前状态。
- 超时 5 分钟；用户关掉窗口视为放弃，`login.status` 变 `failed`。
- 不支持的站点 → 404 `SITE_UNKNOWN`。
- 未安装 playwright 时 → 200 但 `login.status="failed"`，`browser_available=false`。

### POST /api/tasks/{id}/retry

```json
→ 202 { "task_id": "新的 uuid" }
```

- 只有 `failed` 可以重试，用原任务的 `type` 与 `input_json` **新建一条任务**；
  原任务保留失败现场（`error_code` / `progress`），便于排障。
- 任务不存在 → 404 `TASK_NOT_FOUND`；状态不是 failed → 409 `TASK_NOT_RETRYABLE`；
  类型未登记执行器 → 400 `TASK_TYPE_UNSUPPORTED`。

## 4. 前端调用约定

- `client.js` 暴露 `get/post/patch/del`，自动拼接 baseUrl（优先级：`window.api?.baseUrl` > `import.meta.env.VITE_API_BASE` > 空串）
  - **空串的含义**：开发期由 Vite 的 `server.proxy['/api'] → 127.0.0.1:8756` 反代，前端走同源，不依赖 CORS
  - 生产（Electron `file://`）必须由 preload 注入 `window.api.baseUrl`，否则相对路径解析到 `file://` 会失败
- 统一处理 `error.code`，按前缀映射提示：`FETCH_*` → 采集失败类文案，`LLM_*` → 模型调用失败类文案
- SSE 用 `fetch` + `ReadableStream` 解析（**不用 EventSource**，因为需要 POST 与自定义头），封装成 `streamSSE(path, body, onEvent)`
- 轮询任务用 1.5s 间隔、指数退避到 5s，最多 20 分钟；组件卸载必须清定时器
