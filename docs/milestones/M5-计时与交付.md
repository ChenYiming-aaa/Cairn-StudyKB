## 1. 本里程碑不可让步的约束

1. 计时以 **`start_time` 时间戳**为准，**不许**用 `setInterval` 累加计数（后台标签页会掉帧）
2. 刷新/重启后必须能恢复进行中的 session
3. 同一时刻**只允许一个** running session
4. 数据目录必须是 `%APPDATA%/Cairn`，**不是安装目录**（否则卸载即丢数据）
5. 模型与临时文件也放数据目录，不放安装目录
6. 端口必须随机探测，**不许硬编码**
7. 打包用 `--onedir`，不用 `--onefile`

## 6. 本里程碑技术细节

### 6.1 计时：只用时间戳

```js
// 状态只存三个时间点，不存"还剩多少秒"
state = { startTime, pausedAccum, pausedAt, planned }

get elapsed() {
  const now = state.pausedAt ?? Date.now();
  return (now - state.startTime) / 1000 + state.pausedAccum;
}
remaining = planned - elapsed
```

- `setInterval` **只负责触发重算与渲染**（1s），不负责累加
- 暂停：`pausedAccum += (now - startTime)/1000`；恢复：`startTime = now; pausedAt = null`
- 后端 `study_session.duration_seconds` 用同样的口径在结束时一次性算好

### 6.2 刷新与重启恢复

- 前端挂载时 `GET /api/session/current`，有 running（或 paused）就续上
- 每 15 秒 `POST /api/session/{id}/heartbeat` 卷一次账（防止强杀进程丢时长）。
  **用 POST 不用 PATCH**：闭窗兜底要走 `navigator.sendBeacon`，它只能发 POST（2026-11-08 实测后定）
- `beforeunload` 里同步发一次 `navigator.sendBeacon`（异步 fetch 会被中断）
- 后端启动时把**会话开始**超过 4 小时仍 `running`/`paused` 的 session 标为 `abandoned`，
  时长按 `planned_seconds` 封顶（判据用 `created_at` 不用 `start_time`：心跳会把锚点一直往前挪）

### 6.3 Electron 主进程

实现见 `desktop/main.js`。四件事的骨架没变，但落地时有五处**与设计稿不同**，都是实测后改的：

| 设计稿 | 实际做法 | 原因 |
|---|---|---|
| `preload.js` 注入 `baseUrl` | **不做 preload** | 页面与 `/api` 同源，前端全用相对路径（契约 §4）。注入一个永远用不上的全局变量只会多一层要维护的配置 |
| 握手失败 `app.quit()` | 加载 `error.html` 兜底页 | 直接退出的结果是窗口闪一下或留个白窗，用户拿不到"日志在哪"这个唯一能自救的信息 |
| 无 CSP | 主进程 `onHeadersReceived` 注入 | 不塞进 `index.html` 是因为那会把 vite dev 的内联 HMR 脚本一起拦掉。`style-src` 必须留 `'unsafe-inline'`（模板里有 `style="width:80%"` 这类静态属性） |
| 无单实例限制 | `requestSingleInstanceLock` | 第二次双击会把已有窗口叫到前面，否则会多起一个后端白占端口 |
| 无退出兜底 | `before-quit` + `process.on('exit')` 双保险 | 中途崩溃的路径上也要按进程树杀 |

```js
// 数据目录必须是 %APPDATA%/Cairn。app.getPath('userData') 取的是 package.json 的
// `name`（cairn-desktop），**不是** productName —— 不显式改名，数据会落在
// %APPDATA%/cairn-desktop，卸载重装就"丢数据"了。
app.setName('Cairn')

const isDev = !app.isPackaged
const child = isDev
  ? spawn('uv', ['run','python','-m','app','--port',String(port)], { cwd: BACKEND_DIR })
  : spawn(path.join(process.resourcesPath,'backend','cairn-backend.exe'),
          ['--port',String(port),'--data-dir',app.getPath('userData')],
          { windowsHide: true, env: { ...process.env, CAIRN_WEB_DIR: path.join(process.resourcesPath,'web'),
                                      PYTHONIOENCODING: 'utf-8' } })
```

**握手用 HTTP 轮询，不用 stdout 读 `READY`。** 原因：打包成 windowed exe 后 `sys.stdout` 是 `None`，读不到输出（ADR-016）。

> **dev 与打包后的数据目录不同**：dev 不传 `--data-dir`，仍用项目的 `data/`（不搬开发期已有的库）；
> 打包后固定 `%APPDATA%/Cairn`。两条路读同一份 `.env` 规则：dev 读项目根 `.env`，
> 打包后读 `%APPDATA%/Cairn/.env`（T5.7 的首次引导往这里写 Key）。

热路径日志一律写文件（`%APPDATA%/Cairn/logs/shell.log`，dev 写 `desktop/_smoke/shell.log`），
`main.js` 第一行就写 `主进程已加载` —— 打包后如果连这行都没有，问题不在启动逻辑，
而在"主进程根本没加载"。

### 6.3.1 本机验证 Electron 前必须知道的一条

WorkBuddy 的 shell 里常驻 `ELECTRON_RUN_AS_NODE=1`。带着它启动 `electron.exe` 或打包后的
`Cairn.exe`，Electron 会退化成纯 Node 跑 `main.js`，报
`Cannot read properties of undefined (reading 'isPackaged')`，**不写任何日志**，进程还挂着不退出。
看起来极像"打包坏了"，实际是环境变量。启动一律用 `env -u ELECTRON_RUN_AS_NODE <exe>`。

### 6.4 为什么"先打空壳包"必须提前

打包失败**几乎从不是代码问题**，而是：

- PyInstaller 没带上 `templates/` `prompts/` → 运行时 `FileNotFoundError`
- `sys._MEIPASS` 路径没兼容 → 同上
- windowed 模式 `stdout=None` → 打印就崩
- 数据库路径写到了 `C:\Program Files\...`（无写权限）→ 启动即 500
- Defender 拦截未签名 exe
- 端口冲突、子进程残留

这些在 M1 就能用一个"只有 `/api/health` 的空壳"提前暴露。**成本 2 小时，省下的是一整天的排查。**

```python
def resource_path(rel: str) -> Path:
    base = Path(getattr(sys, "_MEIPASS", Path(__file__).parent))
    return base / rel

DATA_DIR = Path(args.data_dir or os.getenv("DATA_DIR", "./data"))
# 所有可写的东西（data.db / models / logs / tmp）一律在 DATA_DIR 下
# 所有只读的东西（templates / prompts）走 resource_path()
```

### 6.5 打包命令（实际用的，不是草稿）

```bash
# 后端：走 spec，参数都在 backend/cairn-backend.spec 里
cd backend && uv run pyinstaller --noconfirm --distpath build/dist --workpath build/work cairn-backend.spec
```

`--add-data` 只写 `templates` / `prompts` **是不够的**。2026-11-08 实测踩到：
`app/db/migrate.py` 会 `SCHEMA_FILE.read_text()` 读 `app/db/schema.sql`，PyInstaller 的静态分析
只跟 import，跟不到这种路径，结果**全新安装第一次启动**直接
`FileNotFoundError: _internal/app/db/schema.sql`。
已经装过库的机器反而看不出问题（日志是"数据库已是 v2，跳过建表"），所以这个坑只在
"别人的机器上第一次跑"时才炸 —— 正是 DoD 里最容易漏的那一条。

现在 spec 按后缀收全 `app/` 下所有 `*.sql/*.html/*.md/*.txt/*.json`，以后加资源不用回头改。

```bash
# 桌面端
cd desktop && npm run pack   # electron-builder --dir，只出可执行目录，验流程用
cd desktop && npm run dist   # 出 NSIS 安装包
```

两条环境前提（本机实测，见 §7）：
- npm 必须 `--registry=https://registry.npmmirror.com`（直连卡 19 分钟，镜像 38 秒）；
- electron-builder 二进制要 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。

electron-builder 配置在 `desktop/package.json` 的 `build` 字段：`extraResources` 把
`backend/build/dist/cairn-backend` → `resources/backend`、`frontend/dist` → `resources/web`、
`desktop/resources/ffmpeg` → `resources/ffmpeg`；`asar: true`，`appId: "com.cairn.app"`，
`productName: "Cairn"`，`nsis: { oneClick: false, allowToChangeInstallationDirectory: true,
deleteAppDataOnUninstall: false }`（最后一项是"卸载重装数据还在"的开关，**不能动**）。

ffmpeg 用 `python tools/prepare_ffmpeg.py` 从本机复制（Anaconda 那份是共享库构建，
`ffmpeg.exe` 只有 350KB，7 个 `av*/sw*` DLL 共 74MB 全都要带）。脚本会用**干净 PATH**
跑一次 `ffmpeg -version` 自证不缺 DLL。

### 6.6 统计口径（必须写死在文档里，否则每次算得不一样）

| 指标 | 口径 |
|---|---|
| 今日待整理 | `knowledge_item WHERE status='pending' AND date(created_at, 'localtime') = date('now','localtime')`（另给 `pending_total` = 全库待整理，因为昨天的没整理完不算今日新增） |
| 今日待复习 | `review_item WHERE due_at <= now` 总条数（不限今日新增） |
| 本周专注时长 | 本周一 00:00 起，`status='done'` 的 `duration_seconds` 之和（`abandoned` 不计） |
| 连续学习天数 | 从今天往前推，每天至少有一条 `done` session 的连续天数。**今天还没学不算断**，从昨天起算（否则每天零点一过就归零，2026-11-08 补的澄清） |
| 正确率 | `is_correct=1` 的数量 / `is_correct IS NOT NULL` 的数量（**NULL 不计入分母**） |
| 分类分布 | `GROUP BY category` 取前 8 |

`verify_m5.py` 要用同一套口径算一遍，和接口返回值比对。

## 7. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 打包后白屏 | 后端没起来就建窗口 / `baseUrl` 是 undefined | 检查 `waitHealthy` 是否真的 await；preload 是否被 `contextIsolation` 挡住 |
| 打包后 `FileNotFoundError: templates/` | `--add-data` 漏了或路径分隔符写成 `/` | Windows 用 `;` 分隔；用 `resource_path()` 读 |
| 打包后启动即 500，日志 `unable to open database file` | 数据目录不可写 | 确认 `--data-dir` 指向 `%APPDATA%`；不要用 `Path.cwd()` |
| 双击没反应 | windowed 模式下异常被吞 | 写文件日志；临时换成 console 模式复现一次 |
| 双击完全没反应、日志一行都没有 | 环境里带 `ELECTRON_RUN_AS_NODE=1`（本机 shell 默认就有） | `env -u ELECTRON_RUN_AS_NODE` 再启动；真机用户不会有这个变量 |
| 首次安装启动即 `FileNotFoundError: .../app/db/schema.sql` | spec 只 add-data 了 templates/prompts | 见 §6.5：按后缀收全 `app/**/*.sql` |
| 重打时报 `EBUSY: ... app.asar` | 上一版 app.asar 被本机某个进程锁住（查不出是谁，能读不能删） | 换一个**全新的空输出目录**；同一目录重打必挂 |
| Defender 报毒 | 未签名 + 单文件自解压 | 用 onedir；README 说明；必要时加排除项 |
| 关窗口后进程还在 | 没 kill 子进程 | `before-quit` + `exit` 双保险；任务管理器验证 |
| 系统时间改回后待复习消失 | due 用本地时间算 | 统一 UTC，Python 侧比较 |
| 计时器跳秒/漂移 | 用计数器累加 | 改时间戳推算 |
| 换机器后模型重新下载 | 模型在安装目录 | 移到 `%APPDATA%/Cairn/models/` |
