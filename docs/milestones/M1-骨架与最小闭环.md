## 1. 本里程碑不可让步的约束

1. Python **3.12**，uv 管理，不用 3.13
2. **不用 ORM 的对象关系自动映射**；Pydantic 做模型 + `repo/` 薄封装，内部是可读的 SQL（理由与解除条件见 ADR-020）
3. 所有路由用 **`def` 不用 `async def`**（除 SSE）
4. `chunk_fts` 建表**必须** `tokenize='trigram'`，建错要重灌数据
5. LLM 的 Key 只从 `.env` 读，不许出现在代码、日志、前端
6. 前端**不引 UI 组件库**，先写 `styles/tokens.css` 再写页面
7. 整理任务的失败必须落到 `agent_task`，前端能看到原因

## 6. 本里程碑技术细节（照着写，别自己发挥）

### 6.1 环境初始化

```bash
uv python install 3.12
uv venv --python 3.12
uv add fastapi "uvicorn[standard]" pydantic httpx jinja2 markdown pygments python-dotenv
```

### 6.2 SQLite 连接策略

**每请求新建连接**，不要全局单例（线程池里会撞 `check_same_thread`）：

```python
def get_conn():
    conn = sqlite3.connect(DB_PATH, timeout=10)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys=ON")
    return conn
```

- WAL 只需在建库时设一次：`PRAGMA journal_mode=WAL`
- 必须开 `foreign_keys=ON`，而且**每个连接都要开**（PRAGMA 是连接级的）
- 写操作失败 `database is locked` → 先确认 timeout=10 生效，再考虑串行化

### 6.3 `extract_json()` 的实现顺序

1. 直接 `json.loads`
2. 失败 → 用正则剥掉 ```json ... ``` 围栏再试
3. 失败 → 从左到右找第一个 `{`，向右做括号配对（注意跳过字符串内的括号），截取到匹配的 `}` 再试
4. 仍失败 → 抛 `LLM_BAD_JSON`，**由调用方决定是否重试**

不要用"找第一个 `{` 到最后一个 `}`"这种粗暴做法，遇到 `{"a":1} 补充说明 {"b":2}` 会解析错。

### 6.4 切块算法

```
按 \n\s*\n 分段 → 每段再按 。！？；\n 切句
累加句子直到 >= 600 字 → 输出一块
下一块从上一块末尾回退 80 字开始（重叠）
单块硬上限 900 字
```

要求：`chunker.split(text) -> list[str]` 是**纯函数**，不带 IO，方便单测与将来替换。

### 6.5 整理 Agent 的 prompt 骨架

`prompts/organize.md` 必须包含：
- 角色：中文知识整理助手
- 输入：正文
- 输出：**只输出 JSON，不要任何解释文字，不要 Markdown 围栏**
- schema：`{"category": str, "tags": [str], "summary": str(120字内), "key_points": [str](3-6条), "structured_note": str(Markdown)}`
- 约束：`category` 用 2-6 个汉字的名词；`tags` 3-6 个；不许编造正文没有的信息

调用后如果 `key_points` 长度 < 2 或 `summary` 为空，视为质量不合格，**重试一次**。

### 6.6 送模型的截断

原文 > 8000 字时：取前 7000 字 + 末 1000 字，中间用 `\n\n[内容过长，已省略中间部分]\n\n` 连接，并把 `truncated` 置 1。

### 6.8 开发期 CORS

```python
allow_origins=["http://localhost:5173", "http://127.0.0.1:5173"]
```

生产环境 Electron 里是同源（`file://` 加载），不需要放宽。**不要写 `allow_origins=["*"]`**。

### 6.9 笔记编辑器（Markdown 源码 + 实时预览）

**不引富文本编辑器**（ADR-018）。组件结构：

```
┌─ 工具栏：编辑 / 预览 / 分屏 ─ 保存 ─ 已修改•
├─ 左：<textarea> 绑 v-model        右：渲染后的 HTML
```

- 预览渲染：前端用 `marked` + `dompurify`（两个都是十年老库，纯 JS 无重依赖）
- 防抖 500ms 再渲染，不要每键入一次就渲染
- 保存调 `PATCH /api/knowledge/{id}`，body 只带 `structured_note`
- 后端收到 `structured_note` 后必须：置 `note_edited=1` → 删 `source='note'` 的 chunk → 用同一 chunker 重新切块写入（见数据契约 §6）
- 有未保存修改时切换 Tab 或切换条目要拦截确认
- "重新整理"按钮：`note_edited=1` 时先弹确认"将覆盖你手动编辑的内容"，用户取消则不发请求

**为什么要让 note 进 chunk**：用户手写的内容如果搜不到，整个知识库的可信度就崩了。代价只是一个字段 + 一个函数，收益很大。

### 6.10 切块函数要能被两处复用

`chunker.split(text)` 必须同时服务于 `raw_content` 与 `structured_note`，不要在路由里各写一套。调用方只负责传 `source` 标记。

## 7. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| `no such tokenizer: trigram` | SQLite < 3.34 | 升级 Python（3.12 自带 3.45+）；确认 `sqlite3.sqlite_version` |
| `SQLite objects created in a thread...` | 全局单例连接跨线程共用 | 改成每请求新建连接 |
| `database is locked` | 并发写 | WAL + `timeout=10`；写操作串行 |
| JSON 里中文变 `\u4e2d` | 用了默认 `ensure_ascii=True` | 所有 `json.dumps` 加 `ensure_ascii=False` |
| 整理老是失败但没报错 | 线程里抛异常被吞 | 检查 `tasks.py` 是否 `try/except` 后写库；`agent_task` 里应有 `error_msg` |
| 前端请求 404 / CORS 报错 | Vite 未配 proxy 或后端 CORS 未开 | 开发期在 `vite.config.js` 配 `server.proxy['/api'] → 8756` |
| 前端白屏无报错 | `api/client.js` 里同步抛错 | 打开浏览器 console；检查 baseUrl 是否 `undefined` |
| 分类树不更新 | 分类是动态聚合的，加了缓存 | 新增/整理成功后必须刷新分类聚合（不要缓存超过一次请求） |
