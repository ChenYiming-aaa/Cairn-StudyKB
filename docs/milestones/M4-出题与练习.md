## 3. 目标与验收场景

## 6. 本里程碑技术细节

### 6.1 出题 prompt 骨架（`prompts/quiz.md`）

必须包含：

- 角色：中文出题助手
- 输入：材料正文（≤6000 字）
- 输出：**只输出 JSON 数组**，不要围栏不要解释
- 每题 schema：
  ```json
  {"type":"single|multiple|boolean|short",
   "question":"题干",
   "options":["A. ...","B. ..."],      // short 类型省略或为空
   "answer":"B",                       // multiple 为 ["A","C"]；boolean 为 true/false
   "explanation":"为什么这样选，指出依据在材料哪句",
   "difficulty":"basic|understand|apply"}
  ```
- 硬约束：题干与选项只能用材料里出现过的信息；每题必须能从材料找到依据
- 数量：严格生成 `{count}` 道，题型在 `{types}` 之内

### 6.2 为什么用"单次调用 + 增量括号扫描"

不要"一题一次调用"（慢、贵、风格不一致），也不要"整包等完再拆"（没有流式效果）。

做法：一次调用，`chat_stream` 边收边扫描缓冲区：

```python
def iter_objects(buf):
    """从 buf 中抽出所有已完整的顶层 {...}，返回 (对象字符串, 剩余 buf)"""
    depth, start, in_str, esc = 0, -1, False, False
    for i, ch in enumerate(buf):
        if in_str:
            if esc: esc = False
            elif ch == '\\': esc = True
            elif ch == '"': in_str = False
            continue
        if ch == '"': in_str = True
        elif ch == '{':
            if depth == 0: start = i
            depth += 1
        elif ch == '}':
            depth -= 1
            if depth == 0 and start >= 0:
                yield buf[start:i+1]
                buf = buf[i+1:]
                # 继续扫剩余部分
```

**必须**处理字符串内的 `{}`（`in_str` 状态），否则题干里出现 `{}` 就错位。

每抽出一个对象 → 校验字段（`type`/`question`/`answer` 必有）→ 补 `id` → `fingerprint` 去重入库 → 立即 `data: {"type":"question",...}` 推给前端。

抽不出来 / 解析失败 → `data: {"type":"skip","index":n,"reason":"json_parse_failed"}`，继续。

### 6.3 指纹

```python
fp = sha256(f"{item_id}|{type}|{re.sub(r'\s+','',question)}".encode()).hexdigest()
```

入库用 `INSERT ... ON CONFLICT(fingerprint) DO NOTHING`，然后查回已有 id。**同一个 item 反复出题不会无限膨胀题目表**。

### 6.4 判分

```python
def grade_objective(q, user):
    if q["type"] == "multiple":
        return set(user or []) == set(q["answer"])
    if q["type"] == "boolean":
        return bool(user) == bool(q["answer"])
    return str(user).strip().upper() == str(q["answer"]).strip().upper()
```

多选按集合比较，忽略顺序；单选做大小写与空白归一。

简答：

```python
# grader prompt 输出：{"score":0.0-1.0, "correct":bool, "feedback":str, "missing":[str]}
try:
    r = llm.chat_json("grader", payload, timeout=60)
    is_correct = 1 if r["score"] >= 0.6 else 0
    feedback = r["feedback"]
except (TimeoutError, LLMBadJSON):
    is_correct, feedback = None, "批改服务不可用，已标记待人工判断"
```

**`None` 不能落成 0**，否则用户会被冤枉。

### 6.5 复习间隔

```python
def advance(review, correct):
    if not correct:
        review.interval_days = 1
        review.lapses += 1
    elif review.interval_days < 7:
        review.interval_days = min(review.interval_days * 2, 7)
    else:
        review.interval_days = 15
    review.due_at = (datetime.now(timezone.utc)
                     + timedelta(days=review.interval_days)).isoformat()
```

- 首次答错：`interval=1, lapses=1`
- 1→2→4→7：因为 `min(x*2, 7)`，1→2→4→7，符合契约
- **UTC 存储**，比较用 `datetime.fromisoformat()` 转成 aware datetime 再比，不要 SQL 里比字符串

### 6.6 前端练习页状态机

```
idle → generating（收到第一题前）→ answering（逐题作答）→ submitting → result
```

- 生成过程中允许"停止生成"，已收到的题保留
- 作答时不能回看已答题目（防止改答案），但结果页可以全览
- 提交时一次性把所有答案发给 `/api/quiz/submit`，后端批量判分；简答题可能慢，用 loading + 分题回填

## 6.7 实施偏差（2026-11-07，T4.1–T4.4）

| 原计划 | 实际 | 原因 |
|---|---|---|
| 材料取"正文前 ≤6000 字" | 按 `chunk` **等距抽样**覆盖全文，仍 ≤6000 字 | 用户裁决：视频转录/长文的前 6000 字常是开场，题目会全挤在开头 |
| 补生成只写在 §7 排障表 | 已实现：首轮不足时逐题补生成（`count=1` + 已出题干），最多补 `count` 次，一次补不出来就停 | 用户裁决本轮就做，否则「5 道」「20 道」全靠模型自觉 |
| `llm.chat_stream` 默认 `max_tokens=4096` | 出题调用抬到 **8192**（`quizzer.MAX_TOKENS`） | 20 题约 4k+ token，顶到 4096 会把末题截断成坏 JSON，全落 skip 反而更贵 |
| 总纲 §7「端点用 `def`」 | `/api/quiz/generate` 用 `async def` | SSE 必须异步生成器，与 `ask.py` 同一条例外；`/api/quiz/submit` 仍是 `def` |
| 判分只在后端 | 题面事件里带 `answer`/`explanation`（契约原本就这么写） | 前端要"答完一题立刻知道对错和解析"；`submit` 仍会**重新判分**，前端改答案骗不到自己 |
| grader 拿整篇材料 | 只给 2500 字抽样节选（`grader.GRADER_MATERIAL`） | 批改只需核对要点，全文既慢又贵 |

**简答判错的口径**：`score >= 0.6` 判对；`feedback` 为空视为"没批改"，同样落 NULL。

| 原计划 | 实际 | 原因 |

| `due_at` 用 SQL 区间比较 | `due_at <= now` 在 **Python 侧**过滤（取全表 → 转 aware → 比较） | UTC 与 `+08:00` 字典序不可比（数据契约 §3 裁决）；个人库几百行，全表扫无所谓 |
| 前端 `Practice.vue` 自己管作答状态 | 拆出 `components/QuizRunner.vue`（作答/交卷/结果），练习页与复习页共用 | 两处作答逻辑必须一致，尤其是本地判分与"待人工判断"的显示 |

**已知取舍**：`is_correct IS NULL` 的题既不排期也不进错题本 —— 不猜对错是 §1 约束 3 的直接推论，

## 6.10 缺陷修正（2026-11-08 真跑暴露：选项双重编号）

**症状**：真模型出 15 题，界面每个选项渲染成「A. A. 在即将忘记的那一刻复习」。

**根因**（两层，缺一不可）

| 层 | 事实 |
|---|---|
| prompt | `prompts/quiz.md` 把「`options` 文本自带 “A. ” “B. ” 前缀」写成硬要求，示例也是 `["A. 选项一"]` |
| 前端 | `QuizRunner.vue` 用 `letterOf(index)` 自己画字母徽标，选项文字原样输出 |

两层都没错，合起来就是双份编号。契约里的示例同样写着 `"options":["A....","B...."]`，
所以"带前缀"从头到尾都被当成正确形状。

**为什么验收没抓到**
- `verify_m4.py` 的 fixture **自己就用带前缀的选项**（`q_obj(options=("A. 注意力留在当前这一轮", ...))`），
  等于把缺陷写进了"正常数据"；而且没有任何一条断言检查过 option 文本的形状
- `e2e/m4_quiz.py` 只看卡片数量、判定文案、分数，不看选项文字
- 假流全用手写 JSON，真模型的"额外加前缀"倾向只能靠真跑发现

**修法**（字母只由界面给，数据层只存裸文本）

- 新增 `repo/questions.strip_option_prefix()` / `clean_options()`：剥 `A.` `B、` `(C)` `D）` `A：`
  这类前缀，**只认大写 A–Z + 分隔符**——`e.g.` / `3.5 倍` / `A/B 测试` / `Anki 软件` 都不动
- 生成侧 `quizzer._options()` 过一遍 → 新题入库就是裸文本
- 读取侧 `row_to_question()` 也过一遍 → 缺陷期入库的老题**不用改库**，接口吐出来就是干净的
- `prompts/quiz.md`：删掉"自带前缀"要求，改成"只写内容本身，序号由界面加"，并说明写了会显示成「A. A. …」
- 契约示例改成裸文本 + 补一条形状规则（见 `接口契约.md` 的 generate 段）

**回归**（`verify_m4.py` 2b 组，6 条）
- 边界：11 种前缀形态剥掉、4 种"看着像前缀但不是"的原样保留
- `emit` 出去的 options 裸文本、answer 字母不受影响、**库里存的也是裸文本**（不是只在 API 层剥）
- 整个选项只有一个 `"A."` → 剥成空被丢掉，答案越界 → 该题 `bad_options` 跳过，不错位判分
- 老数据（payload 带前缀）`row_to_question()` 读出来已剥
- `e2e/m4_quiz.py` 加两条 DOM 断言：`.opt-text` 不自带字母前缀、`.opt-key` 从 A 起连续

## 7. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 流式一题都不出 | 括号扫描把字符串里的 `{` 算进去了 | 检查 `in_str` 状态机；单测一段含 `{}` 的题干 |
| 模型只给 3 题（要 5 题） | 模型偷懒 | 在 `done` 事件里带 `count` 与 `requested`；不足时**逐题补生成**（再调一次，prompt 只要 1 题，带上已出题干避免重复） |
| 题干里出现 `"answer": "B"` 之类原文 | 模型把材料原文当自己输出 | 解析后校验 `options` 长度与 `answer` 合法性，不合法则跳过 |
| 多选题全判错 | 用了 `==` 比较列表 | 改 `set()` 比较 |
| 简答题全部"待人工判断" | grader 超时阈值太短 / Key 欠费 | 超时设 60s；`llm.error_from` 已区分 `LLM_TIMEOUT`（超时）与 `LLM_QUOTA`（402/429），grader 按码给不同 feedback（2026-11-08） |
| 待复习永远为空 | `due_at` 存了本地时间却用 UTC 比较 | 统一 UTC；`verify_m4.py` 用时间旅行断言 |
| 答对一次间隔却跳了两格 | 前端交卷后又手动调了 `/api/review/{id}/result` | `submit` 已经推进过；`/result` 只给人工裁定用 |
| 错题本比预期少 | 它只收「最近一次仍答错」的题，复习答对就移出 | 要看历史去查 `quiz_attempt` |
| 简答题答过却一直不回来复习 | 批改失败落 `is_correct IS NULL`，刻意不排期 | 修好 Key 后重新答一次，或人工裁定后 `/result` 上报 |
| 题目表爆炸 | fingerprint 归一化不一致 | 归一化函数只写一处，出入库共用 |
| 20 题请求很慢 | 单次调用输出太长 | 上限就 20；超过 10 题时在 UI 提示"约需 30-60 秒" |
| 选项显示成「A. A. …」 | 模型给的 option 文本自己带了 `"A. "`，界面又画了一层徽标 | 后端已两侧都剥（`strip_option_prefix`）；若再现，先看是不是新加的渲染路径没过 `row_to_question()` |
