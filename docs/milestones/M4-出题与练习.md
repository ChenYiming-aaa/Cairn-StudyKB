## 1. 本里程碑不可让步的约束

1. 出题**只依据给定材料**，prompt 里必须写死"不许编造原文没有的信息"

6. 复习间隔用固定规则（1→2→4→7→15），**不实现 SM-2 / FSRS**
7. `due_at` 统一用 **UTC** 存储，比较在 Python 侧做，不要靠 SQL 字符串比较

## 3. 目标与验收场景

**一句话**：能被自己考，答错的东西会自己回来找你。

**验收场景 A**：选一条 ready 条目 → 单选题、理解难度、5 道 → 题面**逐题浮现**（能看到打字效果）→ 每答完一题立即知道对错和解析 → 最后看到 4/5、正确率 80%。

**验收场景 B**：答错 2 题 → 打开"今日待复习"→ 空的（因为 due 是明天）→ 把系统时间改到明天 → 出现这 2 题 → 重做 → 答对 → 间隔变 2 天。

**验收场景 C**：简答题作答 → 得到具体反馈（"你提到了 X，但漏了 Y"），不是干巴巴的"回答正确"。

## 6. 本里程碑技术细节

### 6.1 出题 prompt 骨架（`prompts/quiz.md`）

必须包含：

- 角色：中文出题助手
- 输入：材料正文（≤6000 字）
- 输出：**只输出 JSON 数组**，不要围栏不要解释
- 每题 schema：
  ```json
  {"type":"single|multiple|boolean|short",
   "question":"题干",
   "options":["A. ...","B. ..."],      // short 类型省略或为空
   "answer":"B",                       // multiple 为 ["A","C"]；boolean 为 true/false
   "explanation":"为什么这样选，指出依据在材料哪句",
   "difficulty":"basic|understand|apply"}
  ```
- 硬约束：题干与选项只能用材料里出现过的信息；每题必须能从材料找到依据
- 数量：严格生成 `{count}` 道，题型在 `{types}` 之内

### 6.2 为什么用"单次调用 + 增量括号扫描"

不要"一题一次调用"（慢、贵、风格不一致），也不要"整包等完再拆"（没有流式效果）。

做法：一次调用，`chat_stream` 边收边扫描缓冲区：

```python
def iter_objects(buf):
    """从 buf 中抽出所有已完整的顶层 {...}，返回 (对象字符串, 剩余 buf)"""
    depth, start, in_str, esc = 0, -1, False, False
    for i, ch in enumerate(buf):
        if in_str:
            if esc: esc = False
            elif ch == '\\': esc = True
            elif ch == '"': in_str = False
            continue
        if ch == '"': in_str = True
        elif ch == '{':
            if depth == 0: start = i
            depth += 1
        elif ch == '}':
            depth -= 1
            if depth == 0 and start >= 0:
                yield buf[start:i+1]
                buf = buf[i+1:]
                # 继续扫剩余部分
```

**必须**处理字符串内的 `{}`（`in_str` 状态），否则题干里出现 `{}` 就错位。

每抽出一个对象 → 校验字段（`type`/`question`/`answer` 必有）→ 补 `id` → `fingerprint` 去重入库 → 立即 `data: {"type":"question",...}` 推给前端。

抽不出来 / 解析失败 → `data: {"type":"skip","index":n,"reason":"json_parse_failed"}`，继续。

### 6.3 指纹

```python
fp = sha256(f"{item_id}|{type}|{re.sub(r'\s+','',question)}".encode()).hexdigest()
```

入库用 `INSERT ... ON CONFLICT(fingerprint) DO NOTHING`，然后查回已有 id。**同一个 item 反复出题不会无限膨胀题目表**。

### 6.4 判分

```python
def grade_objective(q, user):
    if q["type"] == "multiple":
        return set(user or []) == set(q["answer"])
    if q["type"] == "boolean":
        return bool(user) == bool(q["answer"])
    return str(user).strip().upper() == str(q["answer"]).strip().upper()
```

多选按集合比较，忽略顺序；单选做大小写与空白归一。

简答：

```python
# grader prompt 输出：{"score":0.0-1.0, "correct":bool, "feedback":str, "missing":[str]}
try:
    r = llm.chat_json("grader", payload, timeout=60)
    is_correct = 1 if r["score"] >= 0.6 else 0
    feedback = r["feedback"]
except (TimeoutError, LLMBadJSON):
    is_correct, feedback = None, "批改服务不可用，已标记待人工判断"
```

**`None` 不能落成 0**，否则用户会被冤枉。

### 6.5 复习间隔

```python
def advance(review, correct):
    if not correct:
        review.interval_days = 1
        review.lapses += 1
    elif review.interval_days < 7:
        review.interval_days = min(review.interval_days * 2, 7)
    else:
        review.interval_days = 15
    review.due_at = (datetime.now(timezone.utc)
                     + timedelta(days=review.interval_days)).isoformat()
```

- 首次答错：`interval=1, lapses=1`
- 1→2→4→7：因为 `min(x*2, 7)`，1→2→4→7，符合契约
- **UTC 存储**，比较用 `datetime.fromisoformat()` 转成 aware datetime 再比，不要 SQL 里比字符串

### 6.6 前端练习页状态机

```
idle → generating（收到第一题前）→ answering（逐题作答）→ submitting → result
```

- 生成过程中允许"停止生成"，已收到的题保留
- 作答时不能回看已答题目（防止改答案），但结果页可以全览
- 提交时一次性把所有答案发给 `/api/quiz/submit`，后端批量判分；简答题可能慢，用 loading + 分题回填

## 7. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 流式一题都不出 | 括号扫描把字符串里的 `{` 算进去了 | 检查 `in_str` 状态机；单测一段含 `{}` 的题干 |
| 模型只给 3 题（要 5 题） | 模型偷懒 | 在 `done` 事件里带 `count` 与 `requested`；不足时**逐题补生成**（再调一次，prompt 只要 1 题，带上已出题干避免重复） |
| 题干里出现 `"answer": "B"` 之类原文 | 模型把材料原文当自己输出 | 解析后校验 `options` 长度与 `answer` 合法性，不合法则跳过 |
| 多选题全判错 | 用了 `==` 比较列表 | 改 `set()` 比较 |
| 简答题全部"待人工判断" | grader 超时阈值太短 / Key 欠费 | 超时设 60s；区分错误码 `LLM_TIMEOUT` 与 `LLM_QUOTA` 给不同提示 |
| 待复习永远为空 | `due_at` 存了本地时间却用 UTC 比较 | 统一 UTC；`verify_m4.py` 用时间旅行断言 |
| 题目表爆炸 | fingerprint 归一化不一致 | 归一化函数只写一处，出入库共用 |
| 20 题请求很慢 | 单次调用输出太长 | 上限就 20；超过 10 题时在 UI 提示"约需 30-60 秒" |
