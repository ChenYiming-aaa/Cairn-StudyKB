# 从源码运行与打包

> **作用域**：开发/构建说明（依赖、启动命令、打包、验收脚本、静态演示包）。
> 只影响开发流程，不约束接口与数据形状。
> **不要读**：只想使用 Cairn 的话看根目录 [README](../../README.md)。

## 依赖

- Python 3.12（用 [uv](https://docs.astral.sh/uv/) 管理）
- Node 20+
- ffmpeg（可选，只在测视频采集时需要）

## 起开发环境

```bash
# 后端（默认 127.0.0.1:8756）
cd backend
cp ../.env.example ../.env      # 填 LLM_API_KEY
uv sync
uv run python -m app

# 前端（默认 5173，/api 反代到 8756）
cd frontend
npm install
npm run dev

# 想换数据目录：--data-dir 用**绝对路径**
#   相对路径是按「项目根」解析的，不是按当前目录 —— 写 ../data/tmp/x 会落到项目根外面
uv run python -m app --data-dir C:/Users/你/Desktop/tmp/cairn-scratch

# 桌面壳（dev 模式加载 vite 页面）
cd desktop
npm install
npm start
```

## 打安装包

先确认版本号四处一致（**版本只从这里改，别手改文件**）：

```bash
python tools/bump_version.py                 # 看现状（四处：pyproject / app/version.py / 两个 package.json）
python tools/bump_version.py --check         # 不一致就 exit 1（verify_m8 §5.2 也会跑它）
python tools/bump_version.py --to 0.2.0      # 一次改完四处
```

会先把 ffmpeg 复制进 `desktop/resources/`：

```bash
cd backend && uv run pyinstaller --noconfirm --distpath build/dist --workpath build/work cairn-backend.spec
cd ../desktop && npm install && npm run dist     # 产物在 desktop/release/
```

`cairn-backend.spec` 在 Analysis 之前会写一份 `backend/app/_build_info.py`（`COMMIT` + `BUILT_AT`，
gitignored），**这是关于页"提交 / 构建时间"的唯一来源** —— 运行时读的是包内文件，不是环境变量
（环境变量活不过构建机那条命令，装机版会永远显示"源码运行"，见 `M8-补充记录.md` §六 6.1）。
所以：**改完代码要重新打包才会更新构建信息**，源码直跑永远显示 null（这是对的）。

打包产物目录：`directories.output` 默认 `release/`，多打几次用 `--config.directories.output=release-m8x`
换新目录 —— 同一目录重复打包会撞上 `app.asar` 被占用（EBUSY）。

## 验收脚本

真调模型，会自己建临时数据目录，不碰你的库：

```bash
cd backend
uv run python scripts/verify_m1.py    # 53/53
uv run python scripts/verify_m2.py    # 118/118
uv run python scripts/verify_m3.py    # 61/61
uv run python scripts/verify_m4.py    # 69/69
uv run python scripts/verify_m5.py    # 57/57
uv run python scripts/verify_m6.py    # 83/83
uv run python scripts/verify_m8.py    # 106/106（§1 协议 38 + §3 下载 36 + §5 更新 32）
uv run python scripts/verify_m10.py   # 151/151（七组；模型打桩，缺 samples/ 时整段 SKIP）
uv run python scripts/verify_m11.py   # 61/61（pdf 11 / locate 15 / assets 19 / ui 16）
```

一条命令把上面全跑一遍（外加 m7、m9），任一脚本非 0 就停并打印它最后 30 行：

```bash
python tools/regress.py              # 全跑，约 10–20 分钟（波动全在 m9 的真识别）
python tools/regress.py --from 9     # 从 m9 开始
python tools/regress.py --only 7,9   # 只跑指定几个
```

`verify_m9.py` 九组共 305 条，缺样本时是 SKIP + WARN（退出码仍是 0），
`--only layout|extract|...` 可单跑某组。

界面层只有 `verify_m7.py`（Playwright + 真起后端），它测的是后端吐的 `dist`，
所以**先构建前端**；机器上要有 Edge 或 playwright 自带的 chromium：

```bash
cd frontend && npm run build
cd ../backend && uv run python scripts/verify_m7.py            # 93/93
uv run python scripts/verify_m7.py --shots ../docs/images       # 顺带重拍 README 截图
```

### 更新器端到端（M8 T8.5）

`verify_m8` 只验形状与常量（不装东西、不联网）。**真机行为**是另一个脚本，需要先装一个包：

```bash
# 1) 打一个旧版本的包（演示"0.1.9 发现 0.2.0"）：bump --to 0.1.9 → 打包 → /S 安装
# 2) 再打目标版本（bump --to 0.2.0 → 打包），把它的 setup.exe 当更新载荷
cd backend
uv run python ../tools/e2e_update.py \
    --exe "D:/知识库/Cairn/Cairn.exe" \
    --asset "../desktop/release/Cairn-0.2.0-setup.exe" \
    --version 0.2.0 --fake-version 0.2.1 --only all
```

**不想动自己那份安装**（推荐）：加 `--install-dir` 与 `--user-data-dir`。前者让"装完"这一步
用 `/S /D=<目录>` 落在同一处（不给的话 NSIS 会装到 `%LOCALAPPDATA%\Programs\Cairn`，多出一份），
后者把被测实例的库指到独立目录（壳认 Chromium 的 `--user-data-dir`，并当 `--data-dir` 传给后端）：

```bash
python tools/e2e_update.py \
    --exe "D:/cairn-t930/Cairn.exe" --install-dir "D:/cairn-t930" \
    --user-data-dir "D:/cairn-t930-userdata" \
    --asset "desktop/release-v030a1/Cairn-0.3.0-alpha.1-setup.exe" \
    --version 0.3.0-alpha.1 --only all
```

四幕：① 断网给人话 ② 取消下载文件删净 ③ 下载→起安装器→壳退出→无孤儿 `cairn-backend.exe`
④ 真 GitHub 判定 + 关于页构建信息。`--only offline|cancel|install|real` 可单跑。

### 干净机走查（M8 T8.8）

没有第二台机器时，用 `tools/e2e_clean.py` 在本机**模拟**一台干净机：把已装目录整份复制到临时目录、
用户数据目录指到全新目录（`--user-data-dir`）、`PATH` 削到只剩 `System32`。它会真下 262 MB 组件、
真下 92 MB 模型、真调模型问答，**约 8 分钟**跑完 28 条断言。

```bash
python tools/e2e_clean.py --src "desktop/release-m81/win-unpacked" --work "D:/cairn-t882"
```

它不替代真机：不走 NSIS 安装那一步，也只用本机的 Key（只复制 `.env`，不读内容）。

两个前提：**关掉正在运行的 Cairn**（单实例锁），以及 `%TEMP%\cairn-update` 会被脚本清空。
"发现新版本"走本地假 API（`CAIRN_UPDATE_API_BASE`，响应形状与 GitHub 一致）——
0.2.0 的 Release 要到 T8.7 才建，真 API 今天只会回答"已是最新"。
装成 0.2.0 之后想再验一次，用 `--fake-version 0.2.1`（文件名跟假版本走，内容还是本地真包）。

### 可选组件（M8）

向量 / 语音 / 浏览器三个重组件在 M8 起是独立包（`backend/components/<id>/entry.py`），
主程序通过管道驱动。源码运行**默认仍走本进程内的库**（本机装了 torch 就照旧，验收脚本不受影响）。

```bash
cd backend
uv run python components/embed/entry.py --selftest   # 起子进程握手 + 跑一次最小任务
CAIRN_COMPONENT_MODE=process uv run python scripts/verify_m8.py   # 强制走组件进程
CAIRN_COMPONENT_MODE=local   uv run python scripts/verify_m8.py   # 强制走本进程内库
CAIRN_COMPONENT_MODE=none    uv run python scripts/verify_m1.py   # 模拟"什么都没装"的机器
```

`CAIRN_COMPONENT_MODE` 只给开发和验收用，默认 `auto`（装了组件用组件，否则用本机库）。
同类的还有一个 `CAIRN_COMPONENT_BASE_URL`：把下载源整体指到别处（验收脚本用它起本地
HTTP 服务器，才能真测断点续传与坏包）。**生产路径不读它**，正常安装永远走
`repo + release_tag + asset` 拼出的 GitHub 直链。

组件下载慢的话，在 设置 → 下载 → 下载源 里填镜像前缀（如 `https://ghfast.top/`），
它会被拼在直链前面。**默认留空 = 直连 GitHub**：不替用户把流量导去第三方。
配置项是 `settings.json` 的 `components.mirror`。
判定顺序与理由见 `app/services/components.py` 顶部与 `M8-补充记录.md` §1.3 D1。
`none` 是给「无组件回归」用的：源码态永远能 import 到 torch，没有它就模拟不出冻结包的形态；
`verify_m8` 自己**不**支持 `none`（它验的是协议往返，没有子进程可跑会直接 `exit 2`）。

打三个组件包（产物在 `desktop/release-components/`，sha256 与体积回写 `app/components.json`）：

```bash
cd backend
uv run python ../tools/build_components.py                 # 三个全打，含自检
uv run python ../tools/build_components.py --only browser  # 只打一个
uv run python ../tools/build_components.py --selftest-only # 只跑已有产物的自检
```

组件自检要模型：`embed` 用 bge（92 MB）、`asr` 用 whisper tiny（75 MB）。脚本默认
`CAIRN_MODELS_DIR=<项目>/data/models`，没有就会从 `hf-mirror.com` 下 —— 打包机器上先跑过一次就都有了。
`browser` 自检用 `data:` 地址，不联网，但需要本机有 Edge/Chrome（或打包时 `playwright install chromium`）。

以上除 `verify_m7` 外验的都是接口层。**安装版（Electron + 打包后端 + 用户真实库）要另跑一遍手工清单**，
见 [`真机实测-v0.1.0.md`](真机实测-v0.1.0.md)；其中「界面对不对得上库」用
`python tools/audit_kb.py` 对账（只读 `%APPDATA%\Cairn\data.db`）。

## 静态演示包（github.io）

README 里那个在线试用是**静态站**：用 `VITE_DEMO=1` 构建，网络层换成
`frontend/src/demo/fixtures.json`（真跑一遍整理/问答/出题后抓下来的响应），
生成类操作返回 `DEMO_OFFLINE`。

**2026-11-14 起多了一条「自己跑」的口子**：`/try` 页让访客填自己的模型 Key，
浏览器直发服务商（DeepSeek / OpenAI / DashScope 都回 CORS 头；智谱不回，所以没进预设）。
那条路上**一行假数据都没有** —— 提示词是构建时 `vite.config.js` 从 `backend/app/prompts/*.md`
读进来注入的常量（`__DEMO_PROMPTS__`），Key 只进本机 localStorage。
`VITE_DEMO !== '1'` 时这个常量是 `null`、路由数组为空，Rollup 会把 `Try.vue` 与提示词
整个摇掉 —— 正式包里查不到它们（`grep -rl 整理成笔记 dist/assets` 应为空）。

```bash
cd frontend
VITE_DEMO=1 npx vite build --base=./ --outDir dist-demo   # 产物可直接丢任何静态托管
npm run lint                                              # dist-demo 已在 ignores 里
cd .. && python tools/walk_demo.py                        # 走查（静态数据，不花钱）
python tools/walk_try.py                                  # 走查试用页（真调用，约 3.3k token）
```

`walk_demo.py` 自带本地服务（给 `.mjs` 送 `text/javascript`，否则 pdf.js 的 worker 被拒载、
canvas 一张都不画）；`--url` 可直接跑线上站。`walk_try.py` 的 Key 从项目根 `.env` 读
或 `--key` 给，改过 `demo/llm.js` / `demo/useTry.js` / 提示词时手动跑一次 ——
它是唯一能验出「服务端行为变化」（CORS、`response_format` 不支持）的手段，离线夹具验不出来。

改了后端响应结构要重新抓 fixture，否则演示页会和真实接口漂移。抓取入口已经是脚本：
`python tools/capture_demo.py`（旧 6 条笔记原样灌库 + 真上传 PDF / Word / 试卷三条，
`--with-files` 才会重传原件，约 2–3 分钟，需要 `.env` 里有可用的 Key）。

### 发布到 Pages 的三个前提（2026-11-08 踩过）

1. **仓库必须 Public**。GitHub 免费账号的私有仓库不支持 Pages，`Settings → Pages` 里
   要么没有 Source 选项、要么提示升级 —— 这种情况下 workflow 跑完也拿不到站点，
   访问 `https://<user>.github.io/<repo>/` 一律 **404**。
   判断方法：未登录访问仓库首页，404 就是私有（公开仓库返回 200）。
2. **`Settings → Pages → Source` 必须选 `GitHub Actions`**，不是 `Deploy from a branch`。
   选分支的话 Pages 会去找仓库根目录的 `index.html`，本项目没有，同样 404。
3. **首次发布要手动跑一次**：`Actions → demo-pages → Run workflow`。
   workflow 的 `paths` 只匹配 `frontend/**` 与本文件，纯文档提交不会触发重建。

## 目录结构

```text
backend/    FastAPI 后端：SQLite + FTS5 + sqlite-vec，服务层在 app/services
frontend/   Vue 3 + Vite，hash 路由（Electron 用 file:// 加载不会 404）
desktop/    Electron 主进程、NSIS 打包配置、图标
tools/      文档一致性检查、图标生成、ffmpeg 准备、版本号改写（bump_version.py）、
            一条命令回归（regress.py）、安装版实测对账（audit_kb.py）、
            演示站数据抓取与走查（capture_demo.py / walk_demo.py / walk_try.py）
docs/       用户向图片（images/）+ 开发文档（dev/：总纲、台账、契约、里程碑）
```

接口契约、数据契约、里程碑台账都在本目录，代码层面的约定以那份为准。
