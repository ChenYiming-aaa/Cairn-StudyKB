## 0. 一页结论

v0.1.0 的问题不是「功能不够」，是**功能都在、但用起来不像一个成品**：没有设置入口、侧栏把人淹了、安装包 426 MB、配模型只能手改 `.env`、文案是开发者口吻。

v0.2 拆成三个里程碑，**每个都能独立交付、独立回滚**：

| 里程碑 | 解决什么 | 结束时能做什么 | tag |
|---|---|---|---|
| **M6 设置与个性化** | 用户提的第 1 点 | 齿轮打开设置窗口：双 provider + 探测模型 + 每任务模型/思考强度（实时生效）+ 6 套配色 × 明暗 + 关于页 | `m6-done` |
| **M7 布局与文案** | 第 2、4 点 | 侧栏可收可拖、知识库左栏按「分类/标签/状态」重组、全站文案换成同类知识库的语气 | `m7-done` |
| **M8 体积与更新** | 第 3 点 + 自查更新 | 安装包 426 MB → **≤175 MB**（-59%，2026-11-10 由 170 上调；实测 172），向量/语音/浏览器三个重组件按需下载卸载；设置里能检查并安装 GitHub 最新版 | `m8-done` → **v0.2.0 发布** |

三个里程碑严格串行（M7 会改 M6 建好的设置窗口布局；M8 的下载中心挂在 M6 的窗口里）。**但每个里程碑内部的任务可以逐个会话执行，不必一次做完。**

**必须接受的一个事实**：v0.1.0 的用户没有更新器。所以 v0.2.0 是**最后一次需要手动下载安装包**，之后才能「设置里点检查更新」。这句话要写进 release notes。

## 1. 现状体检（都是实测，不是感觉）

| 项 | 实测值 | 问题 |
|---|---|---|
| 安装包 | 426 MB（`Cairn-0.1.0-setup.exe`） | 用户第一反应是「是不是下错了」 |
| 后端解包 | 965 MB | `torch` 367 MB、`playwright` 104 MB、`av.libs` 65 MB、`ctranslate2` 61 MB、`scipy` 52 MB、`transformers` 48 MB、`onnxruntime` 38 MB |
| ffmpeg | 74 MB（随包） | 必需，保留 |
| LLM 配置 | 全局一套：`LLM_BASE_URL` / `LLM_MODEL` / `LLM_EFFORT` 三个 `.env` 键，所有任务共用 | 整理想用便宜模型、问答想用强模型，做不到 |
| `reasoning_effort` | `llm.py:_payload()` **无条件**塞进请求体 | 多数第三方 OpenAI 兼容服务会因此 400 —— 现在接非 DeepSeek 服务大概率直接挂 |
| 设置入口 | 无。只有首次引导页 + 顶栏「环境待配置」黄点 | 配过之后再也进不去 |
| 侧栏 | 4 处：知识库分类树、问答历史抽屉、学习页选择器、练习配置栏 | 只有问答抽屉能收，其余固定宽度、不可调、不记忆 |
| 知识库左栏 | 一级分类 + **全部标签平铺**（截图里 40+ 行） | 条目一多就没法用；没有搜索、没有折叠、没有状态筛选 |
| 主题 | `tokens.css` 单套写死，`:root` 里直接是纸石色 | 无明暗、无换色 |
| 更新 | 无。`desktop/package.json` 的 publish 指向 `example.invalid` | 用户只能自己去 GitHub 翻 |
| 版本元数据 | 三处 0.1.0 手写，没有版本端点 | 更新器没有比较基准 |
| 文案 | 混杂：「条目 / 内容 / 资料」「整理 / 结构化」「任务 / 作业」并存 | 读起来像内部工具 |

## 2. 要你拍板的四件事

其余我都按推荐方案写进任务里了，只有这四条影响面大、返工贵，先定：

| # | 议题 | 我的推荐 | 备选 |
|---|---|---|---|
| **D1** | 顶栏导航现在 7 项（知识库/仪表盘/检索问答/学习页/练习/复习/任务）+ 连接状态 + 计时 + 采集 | **导航收成 5 项**：知识库 · 检索 · 学习 · 练习 · 复习；「仪表盘」变成知识库页顶部一个卡片入口，「任务」挪到右侧图标区（和连接状态、设置同组） | 保留 7 项，只做换行/缩放 |
| **D2** | 配色选哪几套（都取自你 `dsh-ui-ux-pro-max` 的调色板） | 6 套：纸石绿（现有默认）、暖墨、书卷、石板蓝、学习紫、效率青。见 M6 §3 | 只留 3 套（纸石绿 / 暖墨 / 石板蓝） |

> 默认按推荐执行；你不表态我就按推荐的来，并在 HANDOFF 里记一句「按推荐默认执行」。

## 4. 每个会话怎么开

给每个任务单独开会话，开场三件事照旧（读总纲 + 当前里程碑 + `doc_check.py`），然后再补一句：

```
本轮只做 T6.3（LLM 路由改造）。任务定义在 docs/dev/milestones/M6-设置与个性化.md
的 T6.3 小节。做完跑该任务的验收项 + verify_m1.py，然后写 HANDOFF 一条、commit、
push。不要顺手改 M7/M8 的东西。
```

**一次只做一个任务**是这条计划能走完的前提。任务定义里已经写清「涉及文件 / 实现要点 / 验收 / 不要做什么」，不需要临场设计。

## 5. 版本升级流程（这次要走完整一遍）

```
T6.0 基线          → tag m6-wip
T6.1 契约+ADR      → doc_check 通过，单独 commit
T6.2–T6.9 实现     → 每任务一 commit，全部 push
                    → verify_m6 + m1..m5 全绿 → tag m6-done
T7.x 实现          → 同上 → tag m7-done
T8.1 瘦身          → 打一版 0.2.0-alpha 安装包，测降级路径
T8.2 组件包        → 上传 Release 草稿（tag `components-v1`）
T8.5–T8.7          → 0.2.0 安装包 + release notes + README/CHANGELOG
                    → tag v0.2.0 → 上传 → 更新演示站 → 更新 HANDOFF
```

硬规矩（沿用现有约定，不改）：

1. **每次 commit 都 push**，用完整版 git（`C:\Program Files\Git\cmd\git.exe`），push 前不要设 `GCM_INTERACTIVE=never`
2. **动了 `config.py` / 配置加载，必须重跑 `verify_m1..m5`**（M6 必然动，别只跑 m6）
3. 每个里程碑验收后更新四处：`README.md`、`00-总纲.md` 里程碑表、对应里程碑文档、`HANDOFF.md`
4. 验收时 **FAIL 只报不修**，修之前先问方案

## 6. 不做什么（这一版明确排除）

- 不做多主题市场 / 自定义配色编辑器（只给 6 套预设）
- 不做多语言（中文一套，术语统一就够）
- 不做云同步、账号、团队（红线 1）
- 不做代码签名（要买证书，另立事项）
- 不做「静默后台升级」为默认（无签名 + 静默覆盖，出问题无法排查）
- 不引 UI 组件库、不引 ORM、不引向量库（红线 3–6）
