# 功能价值审计（2026-11-17）

审计对象：Cairn-StudyKB 当前源码（v0.4 开发中）。范围限定在**已经存在**的用户可见功能，
判据是「它有没有兑现自己声称的任务」，不评价「还能不能做得更多」，不提出全新功能。

已知前提（不作为缺陷）：单用户、本地、无账号、无云同步、无商业化。不考虑增长与留存。

三条检验的基准链路：**内容进库 → 整理 → 检索 / 复习 / 出题**。

## 二、四问检验：判定为有问题的条目

### A1 采集后不整理，但 README 说「自动分类、写摘要和整理笔记」

- **功能**：#1–#6 采集（全部五种来源），与 #18/#19 整理
- **声称任务**：README `README.md:35` ——「链接丢进去 → **自动抽正文、由模型分类、写摘要和整理笔记** → 之后能按语义搜出来」
- **判定**：任务对齐不足（宣称与行为断裂，且是首次使用路径上的第一道坎）
- **证据**
  - `README.md:35` 把「自动抽正文」和「由模型分类、写摘要和整理笔记」并列在同一句连动结构里
  - 整理任务的提交点只有两处：`backend/app/routers/knowledge.py:228`（单条）、`:255`（批量）。
    采集链路（`services/ingest_file.py`、`services/web_ingest.py`）里没有任何 `organize` 提交
  - `services/tasks.py:18` 的 `EMBED_AFTER = {"organize", "fetch_url", "transcribe_video"}` 说明采集任务
    结束时只补索引，不接整理
  - 界面上整理是一个显式按钮：`frontend/src/components/ItemList.vue:107-115`「开始整理 N 条」
- **后果**：用户按 README 的叙述把链接丢进去，以为等一会儿就能搜到语义结果、能出题；
  实际那条内容是 `pending`，摘要空白、笔记空白、问答检索不到（chunk 只有 raw），
  必须先注意到列表顶部那个「开始整理 12 条」的按钮。**首次使用最容易在这里以为「模型不好用」**，
  而不是「我少点了一下」。
- **最小收敛动作**：二选一，别两头含糊。
  ① 采集成功后自动排队一条 `organize`（`tasks.py` 里把 `organize` 接进 `EMBED_AFTER` 同级的位置），
  README 保持原叙述；② 保留手动，把 README:35 改成「丢进去 → 自动抽正文；你点一下整理，模型再分类、写摘要和笔记」。
  推荐 ①：单条整理本来就是一步的事，让用户为它做一次决策没有收益。

### A2 整理产出的笔记，出题时完全不读

- **功能**：#14 整理笔记、#26 出题
- **声称任务**：「让模型整理成可检索、可复习的知识资产」（`README.md:8`）——
  整理的价值应该落在「能复习」上，而不只是「能读」
- **判定**：任务对齐不足（断裂点在结构化中间层）
- **证据**
  - 整理写 `structured_note` 并重建 `source='note'` 的 chunk：`services/agents/organizer.py:180-185`
  - 出题取材料时**只读 raw**：`services/agents/quizzer.py:91-95`，
    `SELECT content FROM chunk WHERE item_id=? AND source='raw'`，兜底也是 `raw_content`
  - 摘要面板没有任何出口：`frontend/src/components/SummaryPane.vue` 全文无 `@click` / `button`
    （grep `button|@click|emit` 零命中）
- **证据（2026-11-17 更正）**：本节初稿写「必须去练习页重新选一次材料」，**这是错的**。
  详情页头部早有「练这条」（`ItemDetail.vue:288-290, 337`，`status === 'ready'` 时显示），
  跳 `/practice?item=<id>`，练习页在 `loadItems` 里消费一次该参数并选中
  （`Practice.vue:39-41, 174-183`）。所以「换页 + 重选」这条代价不存在。
  断裂只剩前半截：**出题不读笔记**。教训与项目里那条一致——判据自己也会错，
  写「用户要多点几步」之前先按名字搜一遍按钮。
  - 要用这条出题，只能去练习页重新选一次材料：`frontend/src/views/Practice.vue:355-370`
- **后果**：用户花一次模型调用拿到带标题层级的笔记，然后**发现这份笔记对复习和出题零贡献**——
  出题仍然从原文重新理解一遍，模型可能给出和笔记不一致的要点。更实际的一步代价：
  看完整理笔记想「考考自己」，得离开详情页、进练习、在可能几十条里再找到同一条。
  整理 → 卡片的链路没有接上，整理的价值被砍在「读」这一半。
- **最小收敛动作**：
  ① `SummaryPane` 底部加一个「用这条出题」，带 `item_id` 跳 `/practice`，练习页读 query 自动选中；
  ② `quizzer.material_for_item` 改成优先 `source='note'`、raw 兜底（笔记更短、更结构化，
  出题质量通常更好，也省 token）。两件事都不大，但必须一起做——只做 ① 只是少点两下，
  模型还是在读原文。

### A3「今日待复习」实际只是错题复习，一次答对的题永不回来

- **功能**：#32 今日待复习
- **声称任务**：`README.md:75`「答错的题按 1 → 2 → 4 → 7 → 15 天回来，到期出现在这里」、
  页面副标题「在忘记之前告诉我该复习什么」（导航「复习」的心智）
- **判定**：任务对齐不足（覆盖范围比声称的窄，且窄在关键处）
- **证据**
  - `backend/app/db/repo/review.py:44-49`：`next_interval` 只有「错→1」「对→翻倍封顶 7→15」两档，
    唯一的输入是 `correct` 布尔值。**没有难度、没有反应时间、没有作答次数**——
    它兑现了「答错会回来」，没有兑现「在忘记之前」（遗忘曲线需要每题的个体参数）
  - `backend/app/db/repo/review.py:73-74`：
    ```python
    if current is None and correct:
        return None
    ```
    首次答对 → 不建 `review_item` → **这题永远不进复习队列**
  - `backend/app/routers/review.py:66-67` 注释把这个决定写明了：「从没答错过，答对了没必要复习」
  - `frontend/src/views/Review.vue:226` 副标题只讲「答错的题按 1→2→4→7→15 回来」；
    `:284` 空态写「去练习里答错几道，明天它们就回到这里」
- **后果**：两类用户会被误导。
  ① 以为系统在管全部知识：实际只管错题；新学的、一次就答对的（正是最该在遗忘点再确认的）
  不会出现，「今日待复习 0」不等于「没有该复习的」。
  ② 期望间隔会随表现变化：实际只有对/错两档，同一题连续答对最终停在 15 天，
  无论它多难或多易。**这两点都不是 bug，是范围比名字小**——但名字叫「复习」，
  用户在错误预期下评估这个功能。
- **最小收敛动作**（不必上 SM-2/FSRS，那与本项目的克制原则冲突）：
  ① 首次答对也建队列行、`interval=2`（只改 `apply` 里那个 `return None`）；
  ② 或者把页面文案与导航改名「错题复习」，两处（`Review.vue:226`、`:284`）统一口径。
  推荐 ①：改动量极小，且「答对一次就再也不提」是当前最反直觉的一件事。

### A4 三处「搜标题」+ 一处全文检索，能力边界各不相同

- **功能**：#11 列表标题搜索、#23 全文搜索、以及学习页/练习页两个同形输入框
- **声称任务**：「记得某个词，找出它在哪」
- **判定**：功能冗余（同一句「搜…」在不同页面有不同范围，用户无法预判）
- **证据**
  - `frontend/src/components/ItemList.vue:93-100` 占位「搜索标题」→ 后端 `q`
  - `backend/app/db/repo/items.py:156-158`：`where.append("title LIKE ?")` —— **只搜标题**，
    且被当前分类/状态筛选一并收窄
  - `frontend/src/views/HtmlPages.vue:184-190` 占位「搜标题…」→ 同一个 `q`
  - `frontend/src/views/Practice.vue:358-364` 占位「搜标题…」→ 同一个 `q`
  - `frontend/src/views/Ask.vue` 的搜索走 `/api/search` → `services/retriever.py` 的
    FTS5 / LIKE / 向量融合，**搜正文**
  - `frontend/src/components/CategoryTree.vue:126-132` 占位「筛选分类或标签」——纯前端过滤分类名
- **后果**：四个输入框长得像同一件事（三个还都是 `type="search"` 的圆角框），
  能力分三档：分类名过滤 / 标题 LIKE / 正文全文。用户在「练习」页搜一个正文里的术语、
  得到空结果，会判断「我库里没有这条」，而其实检索页能搜到。
  **这不是说合并成一个搜索，而是三处「搜标题」不该长得和全文检索一样。**
- **最小收敛动作**：抽一个 `TitleFilter` 组件给三处复用，统一占位「搜标题」+
  统一一行灰字提示「只搜标题；找正文用「检索」」，并把提示做成可点跳转。
  判据是「用户在空结果时知道下一步去哪」，不是「框长得一样」。

### A5「学习」这个导航位装的是一台导出机

- **功能**：#25 学习页
- **声称任务**：`frontend/src/views/HtmlPages.vue:160` 自述「挑几条内容生成一份学习页：
  单个文件，断网也能打开，可以拿去分享或存档」
- **判定**：功能本身没问题，**命名与导航位错位**（连带一次价值到达延迟）
- **证据**
  - 导航第五项：「学习」`frontend/src/App.vue:188`
  - 该页实际流程是「多选 → 填标题 → 生成 → 预览 → 下载」：`HtmlPages.vue:28-91`
  - 渲染只吃 `summary / key_points / structured_note`：`services/renderer.py`，
    即它是**同一份数据的第三种视图 + 导出**
- **后果**：用户点「学习」期待的是「学什么、从哪开始」，拿到的是「选几条，导出」。
  这是主导航五个位置之一，成本不只是取名——它占掉了「今天学什么」这个位置本该有的东西
  （现有替代是首页「今日」条 + 复习页，两处分散）。
- **最小收敛动作**：改名「导出」（页面标题同步），入口下移到知识库详情的「导出学习页」按钮 +
  保留现有生成能力。**不建议删**——它是唯一能把多篇装订成可离线单文件的东西，
  有独特能力，只是不该占主导航。腾出的位置留给「复习」上移，或直接留白。

### A6 详情页三个页签是同一份数据的三种视图

- **功能**：#13 摘要与要点、#14 整理笔记、#16 思维导图
- **声称任务**：分别是「先看总结」「拿到结构化笔记」「一眼看出骨架」
- **判定**：功能冗余（视图冗余，非能力冗余）
- **证据**
  - `frontend/src/components/ItemDetail.vue:50-56` 四个页签：
    摘要与要点 / 整理笔记 / 原文 / 思维导图
  - 三者同源：`summary + key_points`（`:280` 附近的摘要）、`structured_note`（笔记）、
    `services/mindmap.py:1`「structured_note 的标题层级 → 树 → 纯 Python 手写 SVG」——
    导图是**笔记的另一种渲染**，不产生新信息
  - 导图没有独立入口，只在详情页内：`knowledge.py:267` 注明「现场生成，不落库、不缓存」
- **后果**：用户读完摘要（3 行）→ 想看细节 → 切笔记 → 想看结构 → 切导图，
  三次页签切换读的是同一份内容的不同排版。这是**低成本高感知**的堆砌：
  它没让任何任务更快，只是让详情页看起来更丰富。导图本身有价值（看清层级），
  但它不值得和「原文」并列成一级页签。
- **最小收敛动作**：导图降为笔记页签里的一个折叠块（或标题栏右侧一个「看结构」开关），
  页签从 4 个回到 3 个。判据：任何一级页签都应该是「一种不同的内容」，不是「同一种内容的另一种画法」。

### A7 从「装进来」到「做出第一张卡」要走 6 个手动步骤

- **功能**：#1 采集 → #18 整理 → #26 出题 → #28 作答 整条首次链路
- **声称任务**：`README.md:35` 那条链路的演示承诺
- **判定**：价值到达延迟
- **证据**（按用户实际动作数）
  1. 打开采集面板，贴链接（必要）
  2. 等抓取结束（自动，但要等，且要自己回来）
  3. **去列表找到那条内容 / 或注意到「开始整理 N 条」**（非必要：一条内容为什么需要被「找」）
  4. **点整理，等模型**（可由采集自动触发，见 A1）
  5. **切到练习页**（非必要）
  6. **在材料列表里再选一次同一条**（非必要，重复决策）
  7. 选题型/题数，点出题
  8. 作答
- **后果**：第 3、4、5、6 步都是「为了让系统工作」而非「为了学习」的动作。
  首次使用的价值到达被拉长到分钟级，中间任何一步（尤其第 4 步等模型）都可能让人离开。
- **最小收敛动作**：A1（自动整理）+ A2（详情页直接出题、带着 item_id 跳）两件做完，
  这条链路降到 4 步（贴链接 → 等 → 点出题 → 作答）。不需要新增任何界面。

### A8 试卷从导入到「做这份卷子」还要再选一次

### A9 任务中心把一个单人本地库的内部队列摊给用户看

- **功能**：#35 任务中心
- **声称任务**：看后台在干什么、失败的重试一次
- **判定**：功能堆砌信号（主流程外露，维护成本高）
- **证据**
  - `frontend/src/views/Tasks.vue:32-40`：`TYPE_TEXT` 5 种内部任务类型
    （`fetch_url / transcribe_video / organize / index_embed / component_install`），
    另有 `STAGE_TEXT` 5 个阶段（`fetching / saving / metadata / downloading / transcribing`）
  - 列表是「最近 50 条」并按 type 平铺
- **后果**：用户为了确认「我刚贴的链接好了没」，要读懂「建立搜索索引」和「网页采集」的区别。
  单人本地库同时通常只有 1 条在跑，50 条平铺列表是给机器状态看的，不是给人的。
  **但它是唯一能看到失败原因的地方**，所以不能删。
- **最小收敛动作**：按「我做的事」聚合（收内容 / 整理 / 装组件），同一件事的
  `fetch_url + index_embed` 合成一行显示；展开才看内部阶段。判据：
  用户的问题永远是「我刚才那件事成了没」，不是「队列里有几个任务」。

## 四、功能堆砌症状扫描

| 症状 | 是否命中 | 定位 |
|---|---|---|
| 数量与效果背离 | **命中** | 41 项功能，但「整理完一篇文章 → 得到一张会回来找我的卡」仍需 6 步（A7），比只有采集+练习时的步数没减少，只是多了中间层 |
| 同类能力重复 | **命中** | 三处「搜标题」（A4）、详情页三视图同源（A6）、复习队列与错题本对同一批题各有口径（见下） |
| 主流程被边缘功能拉长 | **命中** | 任务中心外露 5 种内部任务类型（A9）；设置里「模型」页签同时承载服务配置、Key、探测、四任务×模型×思考强度矩阵（`SettingsDialog.vue:22`），是最高频页签里塞了最低频配置 |
| 维护成本信号 | **部分命中（待验证）** | 检索有 FTS / LIKE / vec0 / numpy 四路召回 + `_guarded` + `_like` + `_vector_numpy` 三层兜底（`retriever.py:68-210`）。对几百条的个人库，`_vector_numpy` 这条路径可能从未在生产中生效过 |

第四项标「待验证」的理由：它是否算堆砌，取决于兜底路径有没有真的救过场。需要的数据是
`chunk_vec` 存在但 `vec0` 查询失败的次数（`retriever.py:183` 那条 warning）——
本地日志里若有记录，这条兜底就是承重的；若从没出现，它是纯维护成本。

**复习队列 vs 错题本**（未单列为 A 条，因为口径是分别定义过的）：
`repo/review.py:122-129` 的 `due` 与 `:168-188` 的 `wrong` 是两条独立查询。
`wrong` 认的是「最近一次作答明确答错」，`due` 认的是「`due_at <= now`」。
后果是同一道错题**今天出现在「今日待复习」，明天仍出现在「错题本」**，
两个 tab 里都能开始一轮练习，按钮文案不同（「开始复习」/「练这些错题」），
底层都是同一个 `QuizRunner`。这不算错——「到期的」与「还没弄懂的」是两个真实概念——
但用户看到的是两个入口通向同一件事，且**两处的计数会不一致**（一个是到期数，一个是错题数），
`:229-235` 把它们并排显示却没有解释差异。
判据建议：保留两个 tab，但把数字旁的关系写清（「其中 N 题今天到期」），
别让「错题 12 / 今日待复习 3」看起来像统计错误。
