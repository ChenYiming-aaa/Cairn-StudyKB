# M6 · 设置与个性化

> **作用域**：本里程碑自包含。做 M6 的任何一个任务，读本文件 + `00-总纲.md` 即可，不必读 M7/M8。
> **前置**：v0.1.0 已发布，`verify_m1..m5` 全绿（T6.0 会重跑确认）。
> **出口**：齿轮打开设置窗口 → 双 provider、探测模型、四类任务各自的模型与思考强度、6 套配色 × 明暗、关于页（含更新占位）。
> **对应需求**：用户第 1 点（设置页）+ 第 4 点的一部分（语气）。

## 1. 边界与约束

**做**

- 一个模态设置窗口（不是新页面），四个 tab：模型 / 外观 / 下载（M8 填充）/ 关于
- 两套 provider：`deepseek`（默认，预填）与 `custom`（任意 OpenAI 兼容）
- 探测：能列出对方模型列表，能判断 Key 是否可用
- 四类任务（整理 / 问答 / 出题 / 批改）各自可指定 provider、模型、思考强度，**改完下一次调用就生效**
- 6 套配色 + 明暗 + 跟随系统；首屏不闪
- 关于页：版本号、GitHub 四个链接、检查更新按钮（M8 接真逻辑）

**不做**

- 不做通用配置编辑器（`FFMPEG_DIR`、`BROWSER_CHANNEL` 这类仍只在 `.env`）
- 不做多套 provider 无限添加（就两个槽位，够用且 UI 简单）
- 不做配色自定义编辑器
- 不做多语言

**红线提醒**

- Key 绝不回显、绝不进日志、绝不进前端状态（红线 7）。前端只能拿到 `has_key: true/false`
- Key 只写 `.env`；其余配置只写 `settings.json`。两处都由 `prefs` 统一读写，不许别处直接读文件
- 单文件 ≤ 300 行

## 2. 数据设计

### 2.1 三个存储位置，职责不重叠

| 内容 | 位置 | 理由 |
|---|---|---|
| 密钥 | `.env` 的 `LLM_API_KEY` / `ALT_API_KEY` | 沿用红线 7 与现有 `env_store`，不把密钥写进 JSON |
| 其余全部配置 | `%APPDATA%/Cairn/settings.json` | 用户可查看、可备份、可手改；不需要迁移脚本 |
| 界面宽度/折叠等纯 UI 状态 | `localStorage` | 与设备绑定，没必要进后端 |

### 2.2 `settings.json` 结构（数据契约要登记这一节）

```json
{
  "version": 1,
  "llm": {
    "active": "deepseek",
    "providers": {
      "deepseek": {
        "label": "DeepSeek", "base_url": "https://api.deepseek.com",
        "key_env": "LLM_API_KEY", "supports_effort": true,
        "models": ["deepseek-flash", "deepseek-reasoner"]
      },
      "custom": {
        "label": "OpenAI 兼容", "base_url": "",
        "key_env": "ALT_API_KEY", "supports_effort": false,
        "models": []
      }
    },
    "tasks": {
      "organizer": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "asker":     {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "quizzer":   {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "grader":    {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"}
    }
  },
  "appearance": {"theme": "paper", "mode": "system"},
  "components": {}
}
```

规则：

- **缺省即合并**：读的时候用「默认值 ← 文件」深合并，文件里少了哪个键就补默认值。绝不因为用户手改坏一个键就整份作废
- **损坏即备份**：JSON 解析失败 → 把原文件改名成 `settings.json.bad-<时间戳>`，用默认值继续跑，日志记一条 WARN
- **原子写**：先写 `settings.json.tmp` 再 `os.replace`，避免断电写半截
- `tasks[*].model` 为空串 = 用 provider 的默认（`models[0]`）
- `effort` 取值 `none|low|medium|high`，映射到请求体 `reasoning_effort`

### 2.3 端点（T6.1 必须先登记进接口契约）

| 方法 | 路径（省略 `/api` 前缀） | 说明 |
|---|---|---|
| GET | `settings` | 全量配置 + 每个 provider 的 `has_key`；**不含任何密钥** |
| PATCH | `settings` | 局部更新（appearance / tasks / active），返回更新后全量 |
| POST | `settings/probe` | `{provider, base_url?, api_key?}` → `{ok, models[], latency_ms, error_code?, hint?}` |
| POST | `settings/llm` | 写 provider 的 key/base_url + 落盘 `.env`，热加载 |
| GET | `version` | `{version, commit, built_at}`（T8.6 补，M6 先立形状） |

`settings` 的响应示例（前端唯一数据源）：

```json
{
  "llm": {"active": "deepseek", "providers": {"deepseek": {"label": "DeepSeek", "base_url": "...", "has_key": true, "supports_effort": true, "models": [...]}, "custom": {...}}, "tasks": {...}},
  "appearance": {"theme": "paper", "mode": "system"},
  "env_file": "C:\\Users\\x\\AppData\\Roaming\\Cairn\\.env"
}
```

## 3. 主题（T6.7 的输入，先定死）

6 套全部取自 `dsh-ui-ux-pro-max` 的 192 套调色板（`data/index.json` 的 `domains.color`，按 Product Type 索引），**不自己编色**：

| id | 名称 | 来源调色板 | Primary | Accent | Background |
|---|---|---|---|---|---|
| `paper` | 纸石绿（默认） | 现有 `tokens.css`（保留） | `#3F6F5F` | `#B8791F` | `#F6F5F1` |
| `notes` | 暖墨 | Notes & Writing App | `#78716C` | `#D97706` | `#FFFBEB` |
| `bread` | 书卷 | Book & Reading Tracker | `#78716C` / Secondary `#92400E` | `#D97706` | `#FFFBEB` |
| `docs` | 石板蓝 | Knowledge Base/Documentation | `#475569` | `#2563EB` | `#F8FAFC` |
| `study` | 学习紫 | Flashcard & Study Tool | `#7C3AED` | `#059669`（正确色） | `#FAF5FF` |
| `teal` | 效率青 | Productivity Tool | `#0D9488` | `#EA580C` | `#F0FDFA` |

**语义令牌映射规则**（6 套都按这套推，不允许每套单独拍脑袋）：

| Cairn 变量 | 取值规则 |
|---|---|
| `--c-primary` | 调色板 `Primary` |
| `--c-primary-soft` | `Primary` 与 `Background` 按 8% : 92% 混合（选中态底色） |
| `--c-success` | `study` 用调色板 `Accent`；其余用统一 `#3F8F5F`（纸石绿沿用现值） |
| `--c-warning` | 调色板 `Accent`（暖墨/书卷/效率青都是琥珀橙，正好） |
| `--c-danger` | 调色板 `Destructive`（统一 `#DC2626`） |
| `--c-text-1` | 调色板 `Foreground` |
| `--c-text-2` | 调色板 `Muted Foreground`（`#475569`） |
| `--c-text-3` | `text-2` 与 `Background` 按 45% : 55% 混合 |
| `--c-bg-0` | `Background`（页面底） |
| `--c-bg-1` | `Card`（面板） |
| `--c-bg-2` | `Muted`（悬停/凹陷） |
| `--c-border` | 调色板 `Border`；若为 `rgba(...)` 则按底色转成实色 |

**暗色派生规则**（`[data-mode="dark"]` 覆盖同名变量）：

- `bg-0` = `Background` 色相、饱和度不变、明度压到 12%；`bg-1` = 16%；`bg-2` = 20%
- `text-1` = 92% 明度、饱和度降到 10%；`text-2` = 72%；`text-3` = 54%
- `primary` 明度提到 65%（暗底下按钮才够亮），`primary-soft` = primary 12% + bg-1 88%
- `border` = 白色 10% 叠加在 bg-1 上（实色，不用 rgba，避免嵌套背景露底）
- **硬标准**：`text-1` on `bg-1` ≥ 4.5:1；按钮文字 on `primary` ≥ 4.5:1；`text-3` ≥ 3:1。`tools/check_contrast.py` 全过才算完

**实现要点**

- `tokens.css` 拆成两段：`:root` 只留间距/字号/圆角/字体/尺寸；配色全部进 `[data-theme="x"]` 与 `[data-theme="x"][data-mode="dark"]`
- `index.html` 里内联 6 行脚本，在应用挂载前读 `localStorage['cairn.theme']` 写到 `<html>` 的 `data-*`，否则刷新会白闪一帧
- `useTheme()`（`composables/useTheme.js`）：`theme` / `mode` / `resolvedMode`（system 时监听 `matchMedia('(prefers-color-scheme: dark)')`），切主题即时写 DOM + localStorage，并 PATCH 到后端（跨设备/重装保留）
- 思维导图 SVG 与学习页 HTML 有各自的 theme 参数（`mindmapUrl(id, theme)`），要跟着换：把 `'light'|'dark'` 传到后端，别让它独立判断

### T6.3 LLM 路由改造

- `services/llm.py`：新增 `resolve(agent) -> Profile(provider, model, effort, base_url, api_key, supports_effort)`

  - `_headers()` 用 profile 的 key；缺 key 仍抛 `LLM_NO_KEY`，但 message 要指明是哪个 provider
  - `_write_log()` 记录**实际使用的** model 与 effort（现在记的是全局 `cfg.llm_model`，会失真）
  - `chat()` / `chat_stream()` 开头解析一次，流中途不再变（避免同一个回答用两个模型）
- 兼容性兜底：收到 HTTP 400 且错误体里出现 `reasoning_effort` / `unsupported` 时，自动去掉该字段重试一次，并在响应里留 `hint`（只重试一次，不递归）
- 断言：假 base_url 下断言 payload 有/无 `reasoning_effort`；`llm_call_log` 的 model 与 UI 选择一致

## 5. 排障表

| 现象 | 先查 |
|---|---|
| 改了模型但调用还走旧的 | `prefs` 缓存没失效（mtime 精度）；或 `os.environ` 里残留旧 key（`env_store` 的写法要照抄） |
| 第三方服务 400 | 先看 payload 有没有 `reasoning_effort`；再看 base_url 要不要带 `/v1` |
| 探测成功但问答失败 | 模型列表里是别名（如 `deepseek-chat`），实际对话要走另一个名字；让用户手输覆盖 |
| 主题切换后部分区域不跟着变 | 组件里写死了颜色（`tokens.css` 注释禁止过，但仍有违规），查 `grep '#[0-9a-fA-F]\{6\}' frontend/src` |
| 刷新白闪 | `index.html` 内联脚本没生效，或被 CSP 拦（CSP 只放 `'self'`，内联脚本需要 `hash` 或挪到外部小文件） |
