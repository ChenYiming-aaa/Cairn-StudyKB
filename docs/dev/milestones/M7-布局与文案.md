## 1. 诊断：截图里到底哪里难看

用户给的截图（知识库页，1280 宽）：

1. **左栏 40+ 行、全部展开**：一级分类 2 个（学习方法 3、时间管理 1），底下却挂了 40 个标签，每个占一整行。标签数量线性增长，分类再多一点就彻底不可用
2. **一个标签只有 1 条也占一整行**：信息密度极低，视觉噪音极大
3. **没有排序/过滤**：标签按字典序或插入序排，用户找不到「我常用的那几个」
4. **三栏都是死的**：左 232px、中 320px、不可拖、不可收。窗口一小就挤压详情
5. **右半边大片留白**：未选中条目时的空状态只有两行灰字，没有给下一步
6. **顶栏 7 个导航 + 3 个控件**，1280 宽下靠得很紧

结论：不是「配色难看」，是**缺少信息分层**。同类产品（Obsidian / 思源 / Notion / flomo）的做法一致：**默认收起、只露高频、可搜索、可整栏折叠**。

## 2. 目标结构（知识库左栏）

```
┌─────────────────────────┐
│ 🔍 筛选分类或标签        │  ← 输入即过滤（只筛树，不搜内容）
├─────────────────────────┤
│ 全部条目              128│  ← 固定顶部
│ 待整理                 6│  ← 状态快筛（原来只靠颜色小点暗示）
│ 整理中                 0│
├─────────────────────────┤
│ 分类                  ▾ │  ← 区块可整体折叠
│  ▾ 学习方法            3│
│  ▸ 时间管理            1│  ← 一级分类默认收起，只显示计数
│  ▸ 写作                2│
│    显示全部 12 个分类 ▾ │
├─────────────────────────┤
│ 常用标签              ▾ │  ← 默认只显示 Top 8（按计数降序）
│ #记忆保持 12  #费曼 9   │  ← chip 云，两列，不再一行一个
│ #间隔重复 8   #任务拆解 5│
│    显示全部 43 个标签 ▾ │
└─────────────────────────┘
```

规则：

- **分类**：一级默认收起；展开后显示该类下的标签（最多 6 个 + 「更多 N 个」）。分类数 > 10 时折叠，先显示 10 个
- **标签**：独立区块，按全库计数排序，默认 8 个，chip 两列，点选即筛
- **状态**：把「待整理/整理中」从颜色小点升级为可点筛选；有数量时才显示
- **搜索**：只过滤树里的名字，不触发检索（检索在中间的条目搜索框）
- **空态**：没有分类时给一句话 + 一个动作（「采集第一条内容」）

## 3. 布局原语（T7.0，所有页面共用）

### 3.1 状态与持久化

`composables/useLayout.js` 管三类状态，全部写 `localStorage`：

| 键 | 含义 | 默认 |
|---|---|---|
| `cairn.layout.sidebar` | 左栏宽度 + 折叠态 | `232` / 展开 |
| `cairn.layout.list` | 条目列表宽度 + 折叠态 | `320` / 展开 |
| `cairn.layout.panels` | 其它侧栏各自的折叠态（问答历史、学习页选择器、练习配置） | 展开 |

写入方式是**直接改 CSS 变量**（`document.documentElement.style.setProperty('--w-sidebar', ...)`），不靠 prop 逐层传，避免 7 个页面各改一遍。

### 3.2 组件

| 组件 | 职责 | Props |
|---|---|---|
| `SidePanel.vue` | 统一包壳：宽度、拖拽手柄、折叠动画、折叠后的窄条（rail） | `side`、`storageKey`、`min`、`max`、`rail`（是否支持收成 44px 图标条）、`title` |
| `SplitHandle.vue` | 拖拽分隔条：pointer events、双击复位、键盘 ←→ 微调 ±8px | `storageKey`、`min`、`max` |
| `RailToggle.vue` | 折叠/展开按钮（顶栏与侧栏内各一个位置，状态同一个） | `target` |

用户给的第 2 点里说「参考同类型个人知识库」，落实成三条明确行为：

1. **能收**：左栏可收成 44px 窄条（只留图标：全部条目 / 分类 / 标签 / 待整理），再点展开
2. **能拖**：展开态下拖右边缘，200–320px；双击手柄回到默认宽
3. **能记**：刷新、切页、重启都保持；`Ctrl+B` 收/展左栏，`Ctrl+Shift+B` 收/展条目列表

### 3.3 三栏的响应式下限

| 窗口宽 | 行为 |
|---|---|
| ≥ 1200 | 三栏 |
| 1000–1200 | 左栏自动收成 rail（用户手动展开过则不再自动收） |
| < 1000 | 左栏收 rail + 条目列表浮层化（点条目后覆盖详情） |

窗口最小宽 960（`main.js` 已定），下限就是 960。

## 5. 排障表

| 现象 | 先查 |
|---|---|
| 折叠后内容不重排 | `.workspace` 用的是固定 px 而不是变量；或 JS 改的是组件内 style 而 CSS 读的是 `:root` |
| 拖拽时选中文字 | `SplitHandle` 没在 `pointerdown` 里 `preventDefault` + 加 `user-select: none` |
| 宽度刷新丢失 | `localStorage` 键名与 `useLayout` 里不一致；或写了但没在 `onMounted` 读 |
| `Ctrl+B` 被浏览器占用 | Electron 下没事；dev 在 Chrome 里会和书签栏冲突，用 `preventDefault` 并接受 dev 差异 |
| 文案替换后测试挂了 | 测试里断言了中文文案。改成断言 `data-testid`，不要断言句子 |
