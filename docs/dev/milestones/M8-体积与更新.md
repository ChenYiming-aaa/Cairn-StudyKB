## 1. 体积账（先算清楚，再定目标）

实测：安装包 426,428,660 B，后端解包 965 MB，ffmpeg 74 MB。

按实测压缩率反推（后端 0.34、ffmpeg 0.38），Electron 壳约占 70 MB：

> ⚠️ **这张表是"动手前的估算"，其中 Electron 那行已被实测推翻**：压缩率 0.34 是按 Python
> 包多的后端算的，Electron 的 `Cairn.exe`（249 MB）压缩率只有 ~0.35 但基数大得多，
> 所以壳实际是 **355 MB 解包 / ~124 MB 压缩**。其余各行基本准确。保留原表是为了记住
> 「170 MB 这个目标是怎么来的」—— 它建立在一个错误的 Electron 估值上（见下方结论）。

| 组成 | 解包 | 压缩后 | 处理 |
|---|---|---|---|
| Electron 运行时 | ~230 MB（**实测 355 MB**） | ~70 MB（**实测 ~124 MB**） | 动不了 |
| `torch` | 367 MB | ~125 MB | **组件 embed** |
| `transformers` | 48 MB | ~16 MB | **组件 embed** |
| `scipy` + `scipy.libs` | 72 MB | ~24 MB | **组件 embed** |
| `sklearn` | 13 MB | ~4 MB | **组件 embed** |
| `ctranslate2` + `av.libs` + `onnxruntime` + `faster_whisper` | 165 MB | ~56 MB | **组件 asr** |
| `playwright`（含驱动） | 104 MB | ~35 MB | **组件 browser** |
| ffmpeg | 74 MB | ~28 MB | 暂时保留（视频是核心功能，拆了会加摩擦） |
| 其余（fastapi / uvicorn / trafilatura / yt-dlp / numpy / sqlite_vec …） | 176 MB | ~60 MB | 基础包 |

**结论（实测，2026-11-10 T8.1 落地后）**

| 版本 | 安装包 | 装完磁盘 |
|---|---|---|
| v0.1.0 | 426 MB | ~1.4 GB |
| v0.2.0 实测 | **172 MB**（目标 ≤175 MB ✅） | **474 MB**（含 ffmpeg；不含组件） |
| 三个组件全装后 | 额外 **411 MB** 下载（解包 1.08 GB） | ~1.5 GB（回到今天，但用户是自己选的） |

> **目标从 ≤170 MB 改成 ≤175 MB（2026-11-10 裁决）**：172 MB 里约 **124 MB 是 Electron 45.2.3
> 本身**（`Cairn.exe` 249 MB 解包），任务书这里写的「Electron ~230 MB」是旧版本的记忆，
> 实测 355 MB。后端从 965 MB 压到 90 MB 只换来 10 MB 安装包体积 —— 差的 2 MB 全在壳上，
> 继续压只能删 Electron 的 DLL 或换 ffmpeg 构建，两条都是**拿真能力换 1.2% 的体积**，
> 不值得。完整理由与「什么时候该重开」见 `M8-补充记录.md` §三 1.1。
> 真正的下一个大头是把 ffmpeg（28 MB 压缩）也组件化 —— **v0.2.0 不做**，记 backlog。

## 2. 组件化设计

### 2.1 为什么是「独立 exe + 行分隔 JSON」，不是「动态 import」

主程序是 PyInstaller 冻结的，Python 3.12 解释器在 `_internal` 里。要让 `torch` 变成可选，只有两条路：

1. 把 wheel 装到用户目录，再往 `sys.path` 里塞 —— 依赖解释器 ABI 完全一致，torch 的 DLL 加载路径还很挑，失败率不可控
2. **每个重组件自己打成独立 onedir + 自己的 exe**，主程序只通过管道与之对话

第 2 条是唯一可靠的。代价是三个 Python 运行时（每份约 15 MB 冗余），换来的好处是：组件崩了不拖垮主程序、组件可单独升级、卸载就是删目录。

**关键利好**：三个重依赖**现在就已经是懒导入 + 有降级路径**（`embedder.get_model()`、`transcriber._whisper()`、`browser.py` 的 `try: from playwright...`）。也就是说 M8 不需要新造降级逻辑，只需要把「import 失败」换成「组件不存在」，降级行为保持一模一样。

### 2.2 三个组件

| id | 名称 | 内容 | 解包 | 下载 | 缺了会怎样 |
|---|---|---|---|---|---|
| `embed` | 向量检索 | torch / transformers / sentence_transformers / scipy / sklearn / hf_xet | ~520 MB → **实测 690 MB** | ~190 MB → **实测 262 MB** | 检索退化为纯全文（**现有行为**）；设置页显示「未安装」，问答页顶部一行提示 |
| `asr` | 视频转录 | ctranslate2 / av / onnxruntime / faster_whisper | ~165 MB → **实测 257 MB** | ~60 MB → **实测 100 MB** | 视频入库时提示「未安装转录组件」（新增错误码 `COMPONENT_MISSING`）；有字幕的视频仍可用 |
| `browser` | 网页渲染 | playwright + 驱动 | ~104 MB → **实测 134 MB** | ~38 MB → **实测 49 MB** | 知乎这类需要浏览器的站点提示装组件（**现有** `FETCH_BROWSER_UNAVAILABLE`） |

> 三个实测值都比原估的大，原因写在 `M8-补充记录.md` §2.1：每个组件还要带一份 Python
> 运行时（~20 MB）+ numpy（28 MB），`embed` 更是光 `torch/lib/torch_cpu.dll` 就 309 MB。
> **`app/components.json` 里的 size / sha256 是打包脚本回写的实测值**，下载中心照它显示。

模型文件（bge 100 MB、whisper 500 MB）**不在组件包里**，仍是首次使用时从 `hf-mirror.com` 下载到 `data/models/`。组件包只带运行时代码。

### 2.3 协议（`components/protocol.md`，随 T8.0 落地）

一行一个 JSON 对象，stdin 进、stdout 出；stdout 只许放协议行，日志一律走 stderr（主程序转到 `shell.log`）。

```jsonc
// 请求
{"id": 1, "op": "encode", "kind": "doc", "texts": ["...", "..."]}
// 响应
{"id": 1, "ok": true, "vectors": [[0.01, ...]], "dim": 512}

// 长任务：先回若干进度事件，再回结果
{"id": 2, "event": "progress", "pct": 42}
{"id": 2, "ok": true, "segments": [...]}

// 出错
{"id": 2, "ok": false, "code": "ASR_FAILED", "message": "..."}
```

- `id` 单调递增，主程序据此配对（组件内部串行处理，不做并发）
- 启动握手：`{"op":"hello"}` → `{"ok":true,"component":"embed","version":"0.2.0","min_app_version":"0.2.0"}`
- 超时：`encode` 120s、`transcribe` 无上限但每 30s 必须有一个 progress、`hello` 10s
- 崩溃：进程退出码非 0 → 记 `agent_task`（红线 8）→ 下一次调用时重启一次，连续两次失败则标记组件「异常」，UI 给「重新安装」

`ComponentClient`（`services/components.py`）：

- `available(id) -> bool`：目录存在 + `hello` 成功（结果缓存 30s）
- `call(id, op, payload, on_progress=None, timeout=...)`：懒启动 + 保活（空转 10 分钟自杀）
- `install(id)` / `uninstall(id)` / `status(id)`
- 并发：每个组件一个进程 + 一把锁，同一时刻只处理一个请求（embedding 是批量的，够用）

### 2.4 主包瘦身（`backend/cairn-backend.spec`）

- `excludes` 追加：`torch`、`transformers`、`sentence_transformers`、`scipy`、`sklearn`、`faster_whisper`、`ctranslate2`、`av`、`onnxruntime`、`playwright`、`hf_xet`
- **删掉**这三行对应的 `collect_data_files`（现在会主动把它们的资源收进来）：`faster_whisper`、`playwright`、`onnxruntime`
- 保留 `numpy`（`transcriber` 用它处理音频、`retriever` 用它做精排）
- 保留 `sqlite_vec`、`zhconv`、`trafilatura`、`yt_dlp`
- ⚠️ **不许**为了省体积排除 `torch.distributed` 之外的任何 torch 子模块（那条历史坑在 spec 注释里，v0.1.0 踩过：排除后 torch 半初始化，同进程再 import 一律抛）
- 改完先跑 `verify_m1..m7`（在「无组件」状态下），全绿再打包
- 额外两条（实测才发现的，任务书原来没写）：
  - **babel 的 locale-data 只留 6 个**（`root/en/en_US/zh/zh_Hans/zh_Hant`）：它是
    `courlan`（trafilatura 的依赖）捎进来的，全量 31 MB，占瘦身后解包的 1/4；
  - **`electronLanguages: ["zh-CN","en-US"]`**（`desktop/package.json`）：Electron 自带
    50 个语言包共 49 MB，比后端整个 `_internal` 的一半还大。

## 3. 下载中心

### 3.1 清单（`backend/app/components.json`，随主包发布）

```json
{
  "manifest_version": 1,
  "min_app_version": "0.2.0",
  "release_tag": "components-v1",
  "repo": "ChenYiming-aaa/Cairn-StudyKB",
  "components": [
    {"id": "embed", "name": "向量检索", "size": 199000000, "sha256": "…",
     "asset": "cairn-embed-0.2.0.zip", "unpack_dir": "embed",
     "why": "让问答能按意思找，而不只是按字面。不装也能用，搜得糙一点。"}
  ]
}
```

- 下载地址不写死 URL，由 `repo + release_tag + asset` 拼 GitHub Releases 的直链，换仓库/换 tag 只改一处
- `sha256` 必填；`size` 用于进度条与断点续传校验

### 3.2 端点（T6.1 里的 §components 占位，在 T8.3 补全）

| 方法 | 路径（省略 `/api` 前缀） | 说明 |
|---|---|---|
| GET | `components` | 每个组件的状态：`installed` / `missing` / `downloading` / `broken` + 版本 + 占用磁盘 |
| POST | `components/{id}/install` | 起一个后台下载任务，立即返回 `{task_id}` |
| DELETE | `components/{id}` | 停止进程 → 删目录 → 返回释放的空间 |
| GET | `components/{id}/progress` | 轮询用：`{status, got, total, pct, error_code}` |

任务复用现有 `agent_task` 表（`type=component_install`），失败可见、可重试（红线 8）。

### 3.3 下载实现要点

- `httpx.stream` + `Range` 头断点续传，写 `components/<id>.part`，完成后校验 sha256 再 `os.replace`
- 解压用 `zipfile`，**解压到临时目录再整体改名**，中途失败不留半个目录
- 下载源可用性：GitHub Releases 在国内可能很慢。**加一个镜像前缀配置**（`settings.json` 的 `components.mirror`，默认空），文档里给 `https://ghfast.top/` 之类作为可选，默认不走第三方镜像（诚实：不偷偷改用户流量）
- 卸载前先 `ComponentClient.stop(id)`，Windows 下文件被占用会删不掉（v0.1.0 的 `app.asar` 已被锁过，有前车之鉴）

### 3.4 UI

- 设置窗口「下载」tab：三张卡（名称 / 一句话说明 / 大小 / 状态 / 主按钮），下载中显示进度条 + 「取消」
- 欢迎页（`Setup.vue`）第 3 步改成「选装」：三条勾选，`embed` 默认勾上并标「推荐」，其余不勾；底部一行「都可以跳过，之后在 设置 → 下载 里装」
- 问答页顶部：`embed` 未安装时一行提示条「当前是纯文字检索，装了向量组件能按意思搜」+ 「去安装」

## 4. 检查更新与自动更新

### 4.1 为什么自己写，不用 electron-updater

- `electron-updater` 依赖发布时生成 `latest.yml`，且对 `oneClick: false` 的辅助式安装器支持有限
- 项目没有代码签名，静默升级出问题后无法排查
- 自己写只需要 GitHub 公开 API + 下载 + 起安装器，约 200 行，行为完全可控

### 4.2 流程

```
设置 → 关于 → 检查更新
  → main: GET https://api.github.com/repos/<repo>/releases/latest
  → 比 semver（忽略 v 前缀，支持 prerelease 开关）
  → 有新版本：显示版本号 + 更新说明（release body 前 20 行）+ 「下载」
  → 下载：到 %TEMP%/cairn-update/Cairn-<ver>-setup.exe，进度经 IPC 推给窗口
  → 校验：优先用 Release 里的 .sha256 附件；没有则只校验大小并明说
  → 「打开安装程序」：killBackend() → spawn(installer) → app.exit(0)
```

要点：

- 更新检查**只在打包后**跑（`app.isPackaged`），dev 下直接返回「开发模式不检查」
- 网络请求用 `net`/`https`（主进程），不走渲染进程，避免 CSP 与代理设置差异
- 失败必须给人话：「连不上 GitHub，请检查网络或代理」+「手动下载」链接（不能只留一个红叉）
- 下载支持取消（`AbortController` 等价物：`req.destroy()`），半截文件删掉
- 安装器路径参数：辅助式安装器直接运行即可（**不要** `/S`，静默安装不在 M8 默认行为里）
- 已知限制写进 UI：「应用未签名，安装时 Windows 可能提示，选择『更多信息 → 仍要运行』」

### 4.3 需要的 Electron 改动

| 文件 | 改动 |
|---|---|
| `desktop/updater.js`（新） | `checkForUpdate()` / `download(assetUrl, onProgress)` / `installAndQuit()` |
| `desktop/semver.js`（新） | 版本比较（纯函数，`node` 可直接跑单测；语义见 `verify_m8` §5.4 的九条边界） |
| `desktop/preload.js`（新） | `contextBridge.exposeInMainWorld('cairn', { update: {...}, app: { version, isPackaged, platform } })` |
| `desktop/main.js` | 注册 `ipcMain.handle('update:check' / 'update:download' / 'update:cancel' / 'update:install')`；`webPreferences.preload` 指向新文件；IPC 校验来源、不收渲染进程传的 URL |
| `desktop/package.json` | `files` 加上 `preload.js`、`updater.js`、`semver.js`；版本号 0.2.0；`publish` 改成真实 provider（github）以便将来生成 `latest.yml` |

**验收用的开关**：`CAIRN_UPDATE_API_BASE` 把 API 基址整体指向别处（`tools/e2e_update.py` 用本地
HTTP 服务模拟 GitHub，因为 0.2.0 的 Release 要到 T8.7 才建）。与 `CAIRN_COMPONENT_BASE_URL`
同一类：**生产不读**，默认 `https://api.github.com`。

**安全**：preload 只暴露三个方法 + 两个只读字段，不暴露 `ipcRenderer` 本身；主进程侧对所有入参做类型与来源校验。

### 4.4 版本元数据

- `GET version` 返回 `{version, commit, built_at}`：`version` 打包时由 spec/构建脚本注入（`app/version.py` 生成，避免运行时读不到 `pyproject.toml`），`commit` 取构建时的 `git rev-parse --short HEAD`，`built_at` 取构建时间
- 三处版本号（`backend/pyproject.toml`、`frontend/package.json`、`desktop/package.json`）统一 0.2.0，由 `tools/bump_version.py` 一次改完
- 关于页显示的版本必须与安装包文件名一致（`Cairn-0.2.0-setup.exe`）

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 组件包 PyInstaller 收不全依赖 | 装完跑不起来 | 每个组件必须过 `--selftest`；打包脚本把 `collect_data_files` 显式列出，不靠静态分析 |
| 主包 excludes 误伤 | 组件在时不崩、不在时崩 | T8.1 先在「无组件」状态下跑全部老验收；每个降级点都要有断言，不靠眼力 |
| GitHub 下载慢 | 装不上 | 镜像配置项 + 明确写「默认不走第三方镜像」；失败给手动下载链接 |
| 组件版本与主程序漂移 | 协议不兼容 | 握手时比 `min_app_version`，不匹配就判「需更新」，拒绝启动 |
| 更新器把用户搞丢数据 | 高 | 安装器不动 `%APPDATA%/Cairn`（NSIS `deleteAppDataOnUninstall=false` 已设）；更新从来不动数据目录 |
| 无签名 + SmartScreen | 用户以为中毒 | UI 与 README 都写清路径；不做成「静默」 |
