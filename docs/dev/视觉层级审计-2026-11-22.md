> **作用域**：`frontend/src/` 8 个路由界面（知识库 / 仪表盘 / 检索问答 / 练习 / 复习 / 任务中心 /
> 学习页 / 试卷复核）+ 引导页 + 设置弹窗 + 详情、采集两个面板，明暗两种模式；
> 只调字号 / 字重 / 颜色 / 间距这四类视觉重量，不改文案措辞（文案另见
> `文案与信息布局瘦身-2026-11-22.md`）。

**与 `视觉与动效一致性审计-2026-11-17.md` 的分工**：那一份问「同一个意思有没有两种做法」（token 收敛、动效克制）；

两者会碰到同一批文件，但判据不同：那份按「值是否重复」判，这份按「层级是否成立」判。

## 0. 一句话结论

**页面上大部分「名字」被当成了「注释」。**

三个层次同时塌了一层：页面标题靠浏览器默认样式（没人定义过）、区块名用最淡的字色最小的字号（比它管着的内容还淡）、
两者之间的中间层（面板名、字段标签）全部落在 `fs-xs + text-3`。于是界面上真正在响的只有两类东西：
**内容正文**，以及**重复了 N 遍的彩色徽标**——后者其实是背景，不是重点。

修复方式不是把字调大，而是**把每一层「该有多响」写下来**：本轮共 7 条，11 个文件，+97 / −99 行，
其中 4 条（H1 / H2 / H6 / H7）是把散成 2–4 种写法的同一角色收成 1–2 档，
3 条（H3 / H4 / H5）是纠正「谁该更响」的判断错误。

## 1. 怎么测的

不靠读 CSS，也不靠看截图下结论——这三类判断用眼睛都不可靠：

1. **逐页截图**：`VITE_DEMO=1` 构建 → 本地静态服务 → Playwright 1440×900，8 个路由 × 明暗 = 16 张，
   另拍「选中一条内容」的详情态与设置弹窗（`tmp/visual-audit/shoot.py`，一次性脚本，不入 `tools/`）。
2. **遍历计算样式**：在渲染后的页面上走一遍所有可见文本节点，收集
   `(font-size, font-weight, color, line-height)` 四元组，统计「每页有多少种文本样式」与「每种出现几次」。
3. **量落点**：读各页 `.page-title` 的 bounding box，比各页面的标题是否落在同一位置。

第 2 步是这份审计真正的依据。1px 的字号差、400/600 的字重差，人眼分辨不出来，
**但它在统计里是一个独立的样式**——「同一角色有几种写法」只能这样数出来。

改完把同一套脚本再跑一遍，逐页对照（9 个路由 × 明暗 × 改前改后 = 36 张）。
三个脚本（`shoot.py` / `measure.py` / `rhythm.py`）与截图都放在 `tmp/visual-audit/`，随 `tmp/` 被 git 忽略——它们是**一次性的**，不进 `tools/`：以后界面结构一变就要重写，留在仓库里只会变成没人跑的死脚本。真要复现，按上面三步各写二十来行即可。

### 改前的统计（知识库页，1440×900）

| 事实 | 数字 |
| --- | --- |
| 页面上不同的文本样式（字号 × 字重 × 色 × 行高） | **39 种** |
| 出现最多的一种 | `12px / 400 / text-3`，**68 次** |
| 正文主色 `13px / 400 / text-1` | **9 次** |
| 条形、角标、图标字符（10px 与 11px） | 12 次 |

**全页最响的一档，是最弱的那一档出现的 7.5 倍。** 这不是配色问题——`text-3` 的对比度是达标的（AA 4.5:1）——
而是**「辅助信息」在数量上压过了「内容」**：列表只有 9 条标题，而围绕它们的说明、计数、单位、快捷键有 60 多处。
层级不是靠颜色对比度建立的，是靠「谁多、谁少，谁先、谁后」。

## 2. 问题清单

### H1 · 页面标题从来没被定义过，它现在的样子是 `<h1>` 的浏览器默认

- **位置**：`views/Dashboard.vue` / `Ask.vue` / `HtmlPages.vue` / `Practice.vue` / `Review.vue` 各自的 scoped 里
  各写了一份 `.page-title`（`fs-xl` + `text-1`，**没有 font-weight**）；`views/Tasks.vue` 用 `<h2>` + `fs-lg`；
  `views/Setup.vue` 手写 `20px / 600`；`components/TitleEditor.vue` 手写 `20px / 600`；`ExamReview.vue` 用 `.head h2`。
- **实测**：5 个页面的标题字重是 **700**，来源是 UA 对 `<h1>` 的 `bold`；两处手写的是 **600**。
  副题更乱：`Ask` 是 `fs-xs`，其余 5 页是 `fs-sm`。
- **判据**：`Microsoft YaHei` 只有 Regular / Bold 两档，600 与 700 在 Windows 上落到**同一个字形**——
  所以这不是「看起来不一样」，而是「**没有决定过**」。没有决定过的样式，下一次新增页面就会再抄出一份。
- **改法**：`app.css` 出唯一的 `.page-title` / `.page-sub`，显式写 `font-weight: 600`；
  7 个视图删掉自己的副本（模板类名不变，只删 CSS）。`Tasks` 的 `<h2>` 换成 `<h1 class="page-title">`，
  `ExamReview` 的 `.head h2` 同理。
- **观感变化**：Windows 上**零像素差别**（600/700 同字形）；macOS 上页标题从 Bold 变 Semibold，与 `Setup`、`TitleEditor` 一致。

### H2 · 「区块名」被当成注释用 —— 比它管着的内容还淡（**本轮最主要的一条**）

- **位置与实测**：

  | 区块名 | 改前 | 它在管的内容 |
  | --- | --- | --- |
  | 详情「摘要 / 要点」`SummaryPane.vue` | `12px / 400 / text-3` + 0.08em 字距 | 15px 宋体正文 |
  | 检索「来源 / 问答历史」`Ask.vue` | `13px / 400 / text-2` | 13px 正文 |
  | 练习「题型 / 难度 / 题数」`Practice.vue` | `12px / 600 / text-3` | 13px 选项 |
  | 设置分区 `SettingsDialog.vue` | `14px / 600 / text-1` | 表单 |
  | 侧栏「分类 / 常用标签」 | `12px / 400 / text-3` | 13px 条目 |
  | 侧栏「工作区」 | `12px / 600 / text-2` | 13px 条目 |

  同一个角色 **4 种写法**（12/400、12/600、13/400、14/600），跨 `text-3 → text-1` 三档颜色。
  而侧栏三个分组里只有「工作区」是对的——**这一档在代码里已经存在，只是另外两个没跟上**。
- **为什么这是硬伤**：区块名是「这一块叫什么」，它必须**强于**它下面的正文，否则读者先读到内容、再回头猜这块是什么。
  详情页最典型：`摘要` 比正文小 3px 且淡两档，读起来是正文的脚注。
- **改法**：定两档，各自只有一处定义。
  - **页内区块标题** `13px / 600 / text-1`（与正文同号同色，只加粗）→ `SummaryPane` 的 `.block-title`、`Ask` 的 `.section-title`。
  - **侧栏分组标题** `12px / 600 / text-2 / 0.06em`（沿用 `WorkspaceBar.vue` 的 `.ws-title`，它就是那条已有证据）
    → `CategorySection` / `TagCloud` 的 `.section-head`。
  - 设置弹窗的分区保持 `14px / 600`：弹窗内部空间更大，分区比页内高半档是合理的，不并进来。

### H3 · 常态徽标用成功色：颜色不标例外，标的是全部

- **位置**：`app.css` 的 `.badge-ready`（`StatusBadge.vue` 的「已整理」、`Tasks.vue` 的「完成」共用）。
- **实测**：知识库列表 **9 行 9 个**绿胶囊；任务中心 **12 行 12 个**。
- **判据**：一个信号在同一屏出现 N 次且取值相同，它就不再是信号，而是**底色**。
  代价是具体的：每行的标题（`13px / 400 / text-1`）旁边都挂着一个同等饱和度的绿块，视线先落在绿块上。
- **改法**：`badge-ready` 改中性（`text-2 / bg-2 / border`），与「待整理」同档。
  四种状态收敛为 **2 中性（待整理、已整理）+ 2 有色（整理中的琥珀、失败的朱红）**——
  **颜色只标例外**。徽标文字对比度实测 `6.17:1`（`verify_m7` 第 13 组，要求 ≥4.5）。

### H4 · 空态用 14px/400 说话

- **位置**：`app.css` 的 `.state-title`（14 个使用点：列表空态、详情空态、问答引导、复习空态、出题未开始…）。
- **实测**：一整屏空白里唯一的一句话是 `14px / 400 / text-1`，与正文同号同重，只是颜色深一点。
  视觉上读作「这块被禁用了」，而不是「这里现在没有东西，但你可以做点什么」。
- **改法**：`fs-lg / 600`（16px 加粗）。空态是**一屏的中心**，它需要一个标题的重量。

### H5 · 仪表盘的数字是「标签 + 一段留白」

- **位置**：`views/Dashboard.vue` 的 `.card-value`（30px / 400）、`.card-label`（12px / 400 / text-3）。
- **实测**：30px 的汉字在 400 字重下，笔画粗细与 12px 的标签相当；四张卡的标签和说明又同为 12/400/text-3，
  一张卡里三行字**只有数字在区分**，而数字本身没有重量。
- **改法**：数字 `600`、标签 `600`（标签仍是 `text-3`，靠字重而不是颜色提起来）。
  副题（`card-sub`）保持 400——它是第三层，不该跟着粗。

### H6 · 面板名 / 字段标签 / 说明文字三层同一个色

- **位置**：`app.css` 的 `.panel-name`（`12px / text-3`，用于「出题配置」「内容选择」）、
  `Practice.vue` 的 `.cfg-title`（`12px / 600 / text-3`）、面板内的 `.note` 类说明（`12px / text-3`）。
- **实测**：练习页左栏一列里，「出题配置」（面板名）、「从哪条材料出题」（字段标签）、
  「这是一份试卷，题目、选项、题号都按原卷来」（说明）**三层全是 12px 灰**，只有字重差一档。
- **改法**：`.panel-name` → `fs-sm / 600 / text-1`（它是这一列的标题）；`.cfg-title` → 保持 12px，
  颜色提到 `text-2`。三层变成 `13/600/深` → `12/600/中` → `12/400/浅`。

### H7 · 「页面第一眼」的落点不一致

- **位置**：`views/Tasks.vue`——`<h2>任务中心</h2>` + 一行小字**按基线横排在同一行**，
  容器 `padding: var(--space-6)`（其余页面是 `16px 24px 32px`）。
- **实测**（改前，1440×900）：标题落点

  | 页面 | 标题 | x, y | 副题 y |
  | --- | --- | --- | --- |
  | 仪表盘 / 练习 / 复习 / 学习页 | 20px | 24, **68** | 100 |
  | 任务中心 | **16px** | 24, **76** | 108（同一行） |
  | 检索问答 | 20px | 314, 76 | 108（居中单列，刻意不同） |

  换页时标题会跳 **8px** 且缩一号——八页里唯一一页的「第一眼」长得不一样。
- **改法**：`Tasks` 改成 `<div>` 包 `<h1 class="page-title">` + `<p class="page-sub">`，容器内边距对齐其余页面。
  改后落点 `24, 68`，与其它四页完全一致（`tmp/visual-audit/rhythm.py` 实测）。

| 项 | 为什么不做 |

| 改 `--fs-xs/sm/md` 的 12 / 13 / 14 三档本身 | 三档只差 1px，确实分辨不出，但它是**全局比例**：动 1px 会牵动每一页的换行与 `verify_m7` 的落点断言。本轮只解决「同一角色多种写法」，比例问题另开一版 |

## 6. 这套审计的方法教训

1. **「同一角色有几种写法」只能数，不能看。** 12px 与 13px、400 与 600 在 1440 宽的截图里是同一个灰点。
   遍历计算样式拿到四元组之后，「39 种文本样式」与「4 种区块标题写法」才是可数的——这两个数字是整份报告的地基。
2. **判「谁该更响」要看出现次数，不看饱和度。** 9/9 的绿徽标看起来是强调，统计一数就知道它是底色。
   同理，改前那个 `12px/text-3 × 68` 也不是「配色太淡」的证据，而是「辅助信息比内容多 7.5 倍」的证据——
   **这两句话指向的改法完全不同**。
3. **字重的改动在 Windows 上可能是零像素。** 600 与 700 在 Microsoft YaHei 下同字形，
   所以「统一页标题字重」这条在本机截图里证明不了任何东西；能证明的是「它从 UA 默认变成了显式值」。
   报告里要把这两件事分开写，否则下次有人拿截图问「你说改了，改在哪」。
4. **向已有的正确写法靠，不向自己的偏好靠。** 侧栏分组标题这一档早在 `WorkspaceBar` 里就是对的
   （12/600/text-2），本轮只是把另外两个分组拉过来；区块标题则没有现成的正确样本，才新定一档。
   这和上一轮动效审计「0.32 那个值有注释支撑，不要统一到 0.42」是同一条纪律。
