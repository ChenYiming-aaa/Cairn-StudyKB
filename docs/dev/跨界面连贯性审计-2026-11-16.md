> **范围**：六条核心任务流的**跨界连贯性**（入口一致 / 上下文传递 / 返回路径 / 中断恢复 / 术语一致）。
> 不评视觉还原度，不把"多一次点击"当断点。

## 任务流 1 · 首次使用

- **路径**：启动 →（缺 Key）引导页 → 去知识库（空库）→ ＋采集内容 → 粘贴 → 「已存进知识库」→ 落在该条详情（待整理）→ 点「开始整理」→ 已整理

### 断点 1-1 · 第一次整理被关窗/重启打断，内容永久卡「整理中」

- **断点**：第 5 步「开始整理」跑到一半关窗（或后端重启/崩溃）。这是全线**第一次**遇到的长任务（10–30 s），首用者最容易在这时把窗口关掉。
- **症状**：重开后徽标一直是「整理中」（脉冲点一直闪），右上按钮固定「整理中…」且禁用；
  同一条调用 `POST /api/knowledge/{id}/organize` 直接回 **409 ITEM_BUSY（实测）**。
  任务中心里那条是「失败 · 服务重启，任务中断」，但内容页没有任何一句话指向它 —— 用户只有"等"（永远等不到）和"删了重传"两条路，而删了重传会重跑一遍读字。
- **位置**
  - `backend/app/main.py:69` → `services/tasks.py:33 recover_stale_tasks()`
  - `backend/app/db/repo/tasks.py:88 mark_stale_running_failed()`：只把 `agent_task` 置 failed，**不回滚 `knowledge_item.status`**
  - `backend/app/routers/knowledge.py:244`（`ITEM_BUSY`）、`services/agents/organizer.py:_mark_failed()`（正常失败会落 failed，但进程死掉时这段代码不执行）
  - `frontend/src/components/ItemDetail.vue`（`busy` → 按钮禁用）、`views/Knowledge.vue:171 scheduleIfBusy`（150 s 后停止轮询，徽标永远停住）
- **最小改动**：`recover_stale_tasks()` 的同一事务里补一句
  `UPDATE knowledge_item SET status='pending' WHERE status='organizing'`；
  更精确的版本是只回滚被标 failed 的 `type='organize'` 任务的 `input_json.item_id`。
  前端第二步再加：`failed` 徽标旁一句「上次整理被中断，点重试」。

## 任务流 2 · 日常录入 → 今日概览 → 任务 → 回概览

- **路径**：知识库顶部「今日」条 → 待整理 / 待复习 → 列表或复习页 → 干活 → 回来看概览

### 断点 2-1 · 「今日」条的数字不跟着同页动作变，一屏三处数字互相打脸

- **断点**：第 3 步之后——采集入库、点「开始整理 N 条」、批量移入、结束一轮专注。**都不影响顶部那条**。
- **症状【实测】**：采集前「顶部 待整理·全库 1 / 左栏 待整理 1 / 列表 2 条」；粘贴入库后变成
  **「顶部 1 / 左栏 2 / 列表 3 条」**。用户刚看到「已存进知识库」的提示，抬头数字没动，会判断"这条没进库"或"计数坏了"。
  整理完 12 条同理：左栏「待整理 0」、顶部仍「待整理·全库 12」。
  专注更直接：结果卡写「+25 分钟」，同屏顶部写「专注 0 秒」。
- **位置**
  - `frontend/src/components/TodayBar.vue:31-38`：只有 `onMounted` 一次 `api.statsToday()`
  - `frontend/src/views/Knowledge.vue:197 refreshAll()`：只刷树/列表/工作区/详情，**不碰 TodayBar**
  - `frontend/src/composables/useTimer.js:164 finish()`：结束即落库，但没有 `requestRefresh()`
- **最小改动**：抽一个模块级 `useToday()`（`today` ref + `loadToday()`），TodayBar 只负责渲染；
  `Knowledge.refreshAll()`、`useTimer.finish()`、采集 `saved` 各调一次 `loadToday()`。
  **不要**在 TodayBar 里 `watch(refreshTick)` + 让 `refreshAll` 再 `requestRefresh()` —— 会自激成死循环。

### 断点 2-2 · 仪表盘那张卡的数是「今天新增」，落点是「全库」

- **断点**：知识库「详情 →」进仪表盘 → 点「今日待整理」。
- **症状**：卡上写 3，点进去列表 47 条、左栏「待整理 47」。用户第一反应是"筛选没生效"。
  （顶部今日条已经用「待整理·全库」把范围标出来了，仪表盘这张卡没标，两处同名不同数。）
- **位置**：`backend/app/db/repo/stats.py:today()`（`pending_items` = 今天新增，`pending_total` = 全库）；
  `frontend/src/views/Dashboard.vue:87`（落点 `/?status=pending`）
- **最小改动**：主数换成 `pending_total`，标签按规范写「待整理·全库」，副标题留「今天新增 N 条」。
  一行数据 + 一行文案，与今日条口径对齐；不要为此加后端参数。

## 任务流 3 · 检索使用

- **路径**：检索 → 搜关键词 → 命中 / 零命中 / 降级提示 → 点结果回原文 → 回检索

### 断点 3-1 · 跨页一次，搜索词和结果清单全没了

- **断点**：第 4 步——点一条命中跳到知识库看原文，再点顶栏「检索」回来。
- **症状【实测】**：搜「审计」→ 命中 1 段 → 点进去正确落在该条「原文」页签 → 点「检索」回来：
  输入框空、结果列表空、页面回到初始文案「试着问一个具体问题」。要接着看第二条命中，得把词再打一遍、再搜一次。
  正在比较的三五条结果也一起消失（问答那条还能从「历史」抽屉找回，**原文命中没有任何历史**）。
- **位置**：`frontend/src/views/Ask.vue:24,34-38`（`question / hits / hitsQuery / tab` 全是组件内 ref）；路由切页即卸载
- **最小改动**：照 `utils/noteDraft.js` 那套写法，把 `{question, tab, hitsQuery, hits}` 按会话存 `sessionStorage`（`cairn.ask.state`），
  `onMounted` 回填；`openItemAt` 跳走前落一次即可，无需新接口。

### 断点 3-2 · 问答零命中是一句死话，同页另一个页签却给了两个出口

- **断点**：第 3 步——问答页问了一个库里没有的问题。
- **症状【实测】**：页面只剩一行「知识库中没有找到相关内容」，**整页没有任何可点的下一步**
  （当时的按钮清单只有导航、问答/原文命中、历史、提问）。
  用户的合理动作是"那我采一条进来"，但这里没有入口；他得自己想到去顶栏「＋ 采集内容」，且那句话不会带过去。
  同一页的「原文命中」零命中反而给了「改成问答 / 采集这条内容」两个按钮 —— 两条路的能力不对等。
- **位置**：`frontend/src/views/Ask.vue:414-434`（`no_result` 只渲染 `article.answer`）、`468-475`（原文命中的出口）
- **最小改动**：在 `answer.dim` 下面复用同一组按钮：`switchTab('search')`（带原词）+ `openPaste(question.value)`。
  文案照 468 那组，不新造说法。

## 任务流 4 · 复习闭环

- **路径**：复习队列 → 开始复习 → 逐题作答 → 交卷判分 / 待人工判断 → 结果页 → 回队列看剩余

### 断点 4-1 · 交卷成功那一刻，结果页整块消失

- **断点**：第 5 步——最后一道点「交卷并看结果」。**到期题都在这批里时必现**（最常见的形态）。
- **症状【实测】**：4 题全到期 → 交卷 → 2.5 s 后 DOM 里 `score` 0 个、`review-q` 0 个；
  页面已经变成「今天没有到期的题 / 去练习里答错几道」。只有一条 3 秒就消失的 toast「本轮复习完成：4/4」。
  用户拿不到：哪几题错了、每题讲解、以及「待人工判断」那两题的就地裁定按钮（只能再去页签里找）。
  这一轮等于"做完就没了"，与"回到队列看剩余"的预期相反。
- **原因链**：`QuizRunner` 交卷 → `emit('finished')` → `Review.onFinished` 调 `loadDue()`
  → 后端已把这些题的 `due_at` 推到明天（`repo/review.py:apply`）→ `items` 变空/变少
  → `questions` computed 归零 → 模板 `v-if="practicing && questions.length"` 整块卸载。
- **位置**：`frontend/src/views/Review.vue:49,158-163,210`
- **最小改动**：把「这一批题」与「队列」拆开：`startPractice()` 时快照 `runItems = items`，QuizRunner 吃快照；
  `onFinished` **不再** `loadDue()`，只置 `finished=true`；用户点「回到复习列表」（`onRestart`）时才 `loadDue()` 并清快照。

### 断点 4-2 · 有剩余到期题时，结果页留下来了，但每道题的题干是空的

- **断点**：同上一步，但队列里还有剩（例如 21 题到期、一批 20 题）。
- **症状【实测】**：结果页在（`20 / 20`、正确率 100%），20 行全是「✓ 1. ←（题干为空） / 你的答案 A / 正确答案 A / 解析 N」。
  用户能看到对错，但不知道对错的是哪道题，也没法用它回顾（见截图 `tmp/audit-run/review-after-submit-20.png`）。
- **原因**：`QuizRunner.questionOf()` 在 `props.questions` 里按 id 找题，而它已被 `loadDue()` 换成剩下的那 1 题。
- **位置**：`frontend/src/components/QuizRunner.vue:144-145,313-353`；根因同 4-1
- **最小改动**：与 4-1 **同一处改动**（快照）同时修好两种情形；不额外加代码。

### 断点 4-3 · 答到一半点一下导航就清零，没有任何提示

- **断点**：第 3 步——答题中途点了顶栏任一导航（或关窗、F5）。
- **症状【实测】**：答到「第 3 / 20 题」点「知识库」，**没有任何确认弹窗**（dialog 事件为空）；
  点「复习」回来是队列页 + 「开始复习（20）」，没有"上次没做完"的痕迹。
  已答的两题既没交卷也没落库（`quiz_attempt` 只在交卷时写），所以**连记录都找不回**。
  同一现象在练习页（同一个 `QuizRunner`）：回来是「还没开始」。
- **位置**：`frontend/src/components/QuizRunner.vue:37-46`（进度全在组件内 ref）、`views/Review.vue:152-156`、`views/Practice.vue:414-422`
  对照：`components/NoteEditor.vue:95-124` 已有 `sessionStorage` 草稿 + `beforeunload` 守卫，全站唯一一处
- **最小改动**：照 NoteEditor：`{idx, answers, picked, typed}` 按 runId 落 `sessionStorage`（`cairn.quiz.draft`），
  `startPractice` 时若有草稿就直接进作答并提示「接着上次第 3 题」；`dirty` 时补 `beforeunload`。
  两句文案即可，别做后端暂存。

### 断点 4-4 · 错题本的「去练习」去的是另一个任务，出的是另一批题

- **断点**：第 7 步（旁路）——错题本里点「去练习」，以为要重做这些错题。
- **症状**：落到练习页，选中的是列表第一条内容、题型单选、5 题，点「出题」由模型**新出一组**；
  那 6 道错题一道也不会出现。用户做完以为"错题练过了"，下次它们照样错。
- **位置**：`frontend/src/views/Review.vue:127-130,263-266`（`goPractice` 无参数）；`views/Practice.vue:128 generate()`；
  后端 `/api/quiz/wrong` 的题没有任何"拿来作答"的入口
- **最小改动**：错题本里把「去练习」换成/补上「练这些错题」——把 `wrongItems`
  （字段已含 `id/type/question/options/answer`）直接喂给现有 `QuizRunner`，不调 `generate`。
  纯前端，约 15 行；`generate` 那条保持不动（它解决的是"给材料出题"）。

### 断点 4-5 · 同一个数在复习页有三个名字

- **断点**：第 5 步之后看头部与列表。
- **症状【实测】**：同一屏上「**今日到期** 25」/ 页签「**今日待复习**」/ 列表条「**到期的 25 题**」；
  交卷后更明显：「**0 今日到期** · **25 队列中** · 今天没有到期的题」——三句话并存，用户会以为"队列中 25"还没做。
  待判有四种说法：「待判 / 待人工判断 / 没判出来 / 待人工判断 N 题」。
- **位置**：`frontend/src/views/Review.vue:181-206,224`；`QuizRunner.vue:304-306,320`；`TodayBar.vue`、`Dashboard.vue`
- **最小改动**：按 `docs/dev/文案规范.md` §2（同一个东西只有一个名字）统一成三个词：
  「今日待复习 N」「还没到期的 N」「待人工判断 N」，把「到期」「待判」「队列中」从可见文案里去掉。

## 任务流 5 · 试卷导入

- **路径**：内容详情（PDF/图片）→「导入试卷」→ `/exam/:fileId` 复核（左页图 / 右题卡）→ 改题 →「确认导入」→ 回知识库看这条

### 断点 5-1 · 复核页退出即全丢，一句提示都没有（已知取舍，报损失条件）

- **断点**：第 3 步——改过任意一题之后，误点顶栏导航 / F5 / 崩溃 / 切到别的内容。
- **症状**：草稿只在前端内存里，路由一离开就没了；**没有 confirm，也没有 beforeunload**。
  重进要重跑 `/api/exams/parse`（模型）+ 初审（模型），几十秒；期间用户只能盯着"正在读这份试卷的题目…"。
  **实际损失条件**：改了 20 题、花 20 分钟，一次误触 = 全白做，且界面不会告诉他"刚才改的都没了"。
  本条属于仓库自己认定过的取舍（`交互断裂清单-v0.4.md` §6），不是新缺陷 —— 但按口径"造成实际损失的条件"必须报。
- **位置**：`frontend/src/views/ExamReview.vue:54-75`（草稿仅 `ref`）、无 `onBeforeRouteLeave` / `beforeunload`
- **最小改动**：加一个 `dirty`（任一 draft 字段改过即真）+ `onBeforeRouteLeave` / `beforeunload` 各弹一次确认
  （「这页改了 N 题还没导入，离开就没了」）。不引入存储，取舍不变。

### 断点 5-2 · 「重新导入」不是接着改，而是让模型从零再猜一遍

- **断点**：第 3 步重进——上次导入后想补改一条答案，点「重新导入」。
- **症状**：进来看到的是**模型这一轮的新猜测**，不是库里那份改好的；上次手改对的第 7、12 题回到错答案。
  若此时直接点「确认导入」，错答案被写回去（commit 会替换 `origin='imported'` 的题），而用户以为"我只是补了一条"。
- **位置**：`frontend/src/views/ExamReview.vue:54-73 load()` 只调 `api.examParse`，从不读已导入的题；
  现成可用的读取出口是 `api.quizPaper(item_id)`（`backend/app/routers/quiz.py:335`，题号/题干/选项/答案/讲解/分值都在 `payload` 里）
- **最小改动**：`load()` 里先判 `item.kind === 'exam'`（详情已经带 `kind`）→ 走 `quizPaper(item.id)` 回填 drafts，不调 parse；
  顶部只说一句「这份试卷在库里已经有 24 题，下面是库里那版，改完点确认导入」。

### 断点 5-3 · 「导入试卷」按钮不出现时，没有任何解释

- **断点**：第 1 步——用户拿着扫描件 PDF 想导入。
- **症状**：`canImportExam` 要求 `pdf/图片 + ocr_status==='done' + page_count>0`；不满足时按钮**整个不渲染**，
  页面没有任何替代文案。用户不知道"读完才能导"，也不知道差在哪，只会认为这个版本不支持试卷。
- **位置**：`frontend/src/components/ItemDetail.vue:80-91,235-237`
- **最小改动**：`ext` 是 pdf/图片但条件不满足时，渲染一个**禁用**的「导入试卷」+ 旁注
  「这份文件还没读完，读完才能导入」（与 6-3 同一处原件状态，可以一起做）。

## 任务流 6 · 可选组件

- **路径**：功能提示缺组件 → 设置 → 下载 → 安装中 / 失败 / 取消 → 回到原功能确认可用

### 断点 6-1 · 装完回来，原功能还在劝你再装一次

- **断点**：第 5 步——装好组件、关掉设置窗口，回到刚才那个页面（设置是模态，页面没卸载）。
- **症状**：检索页仍然挂「现在只能按关键词搜。装上「向量检索」就能按意思搜」+「去安装」；
  采集面板顶部仍然挂「读 PDF 与图片要先装「本地识别」」；引导页的组件清单也不变。
  用户据此判断**安装失败**，再点一次「安装」拿到 `COMPONENT_BUSY`，于是更确信坏了。
- **位置**：`frontend/src/views/Ask.vue:249-258 probeEmbed()`（仅 onMounted）、`components/ingest/FileForm.vue:33-43 loadOcr()`（仅 onMounted）、
  `views/Setup.vue:87-97 loadComponents()`（仅 onMounted）；`components/settings/DownloadsTab.vue` 是唯一知道装完的人
- **最小改动**：`useUi` 加 `componentsTick`，DownloadsTab 在安装完成/取消/卸载后 +1；上面三处 `watch(componentsTick, 重新探测)`。
  更好的是收成 `useComponents()` 单例（现在三处各写一套 `api.components()` + `usable()` 判据，容易再漂）。

### 断点 6-2 · 卡片上写着「点重读」，卡片上没有「重读」

- **断点**：第 5 步——装完 OCR 回到采集面板，这张卡还在 `needComponent`。
- **症状**：卡片正文说「装完回来点「重读」就行，原件已经存好了」，可动作区只有「去设置」一个按钮，
  没有「重读」。用户点「去设置」发现组件已经装好了 —— 界面自相矛盾，这一屏没有出路。
- **位置**：`frontend/src/components/ingest/FileIngestCard.vue:98`（那句话）对比 `:296-312`（`needComponent` 只渲染「去设置」，`failed/cancelled` 才渲染「重读」）

### 断点 6-3 · 关掉采集面板后，这份 PDF 在界面上「失踪」了

- **断点**：第 5 步的另一条路——用户当时点「关闭」走了，之后从知识库打开这条内容。

### 断点 6-4 · 「装完会通知」这句承诺没有兑现

- **位置**：`frontend/src/components/settings/DownloadsTab.vue:75`（承诺）、`views/Tasks.vue:30-35`（类型名没映射）
- **最小改动**：二选一——① 把这句改成「关掉窗口也会继续下载，回「设置 → 下载」看进度」（一行）；

  顺带给 `TYPE_TEXT` 补 `component_install: '安装组件'`。
