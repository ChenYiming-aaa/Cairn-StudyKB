# 代码签名

> **作用域**：Windows 安装包的 Authenticode 签名（证书选型、接入方式、验证方法）。只影响发布流程，不约束代码与接口。
> **不要读**：不参与发布的话不用看；想用 Cairn 请看根目录 [README](../../README.md)。

## 现状（2026-11-08）

| 项 | 状态 |
|---|---|
| 签名工具 | ✅ `C:\Program Files (x86)\Windows Kits\10\bin\10.0.22000.0\x64\signtool.exe` |
| CA 签发的证书 | ❌ **没有**。个人证书库里 8 张证书，无一为代码签名类型 |
| 已发布安装包 | ❌ 未签名（`signtool verify` 报 `No signature found`） |
| 本地签名链路 | ✅ 已用自签名证书实测跑通，见下 |

自签名实测（2026-11-08，证书已删除，未留在库里）：

```
signtool sign /sha1 <指纹> /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 test.exe
→ 退出码 0，Successfully signed

signtool verify /pa /v test.exe
→ 签名存在；时间戳由 DigiCert RFC3161 验证通过
→ 唯一错误：A certificate chain processed, but terminated in a root certificate
   which is not trusted（自签名必然如此）
```

结论：**工具链没问题，卡在证书**。自签名不能对外发布——它会让 SmartScreen 更坚决地拦截，
而且用户装不了根证书。

## 四条路线（2026-11 查证，含地域限制）

| 路线 | 价格 | 地域 | 用户看到的发布者 | 门槛 |
|---|---|---|---|---|
| **Azure Artifact Signing**（原 Trusted Signing） | $9.99/月（5000 次签名） | 组织：美/加/欧/英；**个人：仅美/加 → 中国大陆不可用** | 你的名字 | 需要 Azure 付费订阅，身份验证 1–40 个工作日 |

| **SignPath Foundation** | 免费 | 无地域限制 | **SignPath Foundation**（不是你的名字） | OSI 许可（MIT ✅）、已发布 ✅、MFA、作者/审查/批准三角色、**每次发布人工审批** |
| **商业 OV**（DigiCert/Sectigo/SSL.com） | $150–300/年 | 全球 | 你的名字 | 身份审核 1–5 天，硬件令牌或云 HSM |
| EV | $400+/年 | 全球 | 你的名字 | **2024 起不再即时免 SmartScreen**，不值得为此多花钱 |
| 自签名 | 免费 | — | 未知/不受信任 | 对公众等于装不上，只能企业内部或本地验证 |

**所有路线都买不到的一件事**：首次下载当天就消失的 SmartScreen 警告。签名解决的是
「UAC 里的未知发布者」和「文件未被篡改」，SmartScreen 信誉仍要靠下载量累积（OV 几周到几个月，
EV 稍快但不再豁免）。

## 接入方式（证书到手后按对应一条做）

### A. pfx 或可导出的证书（商业 OV 常见）

electron-builder 自动识别，**不用改任何配置**：

```bash
export WIN_CSC_LINK=/path/to/cert.pfx      # 也支持 base64 或 https 链接
export CSC_KEY_PASSWORD='...'
cd desktop && npm run dist
```

它会先签 `Cairn.exe`，再签 NSIS 安装包，两处都签才完整。

### B. 云签名（Certum SimplySign）

证书装在「个人」证书库，没有 pfx 可指，**必须**在 `desktop/package.json` 的
`build.win` 里加（electron-builder 26 不支持用环境变量指定主题名）：

```json
"signtoolOptions": {
  "certificateSubjectName": "<证书 Subject，SimplySign 里能看到>",
  "signingHashAlgorithms": ["sha256"],
  "rfc3161TimeStampServer": "http://time.certum.pl"
}
```

没有证书时**不能**留着这段——会报
`No code signing certificate configured. Provide certificateFile, certificateSha1, or certificateSubjectName.`
所以它应该只加在发布分支或发布机本地，不要提交到 main。

### C. SignPath Foundation（免费，但在 CI 里签）

签名不在本机做，走 `signpath/github-action`：构建产物上传给 SignPath，人工批准后回传已签名的包。
需要仓库根目录写一份 code signing policy，并在 SignPath 里配置 GitHub 集成。

## 验证

PowerShell 里跑（**Git Bash 会把 `/pa` 当成路径**，实测报 `File not found: .../pa`）：

```powershell
& "C:\Program Files (x86)\Windows Kits\10\bin\10.0.22000.0\x64\signtool.exe" verify /pa /v .\Cairn-0.1.0-setup.exe
```

期望看到 `Successfully verified` 和 `The signature is timestamped`。
发布后还可以：右键安装包 → 属性 → 数字签名 → 双击看签名者与时间戳。

## 两个必须记住的坑

1. **必须带时间戳**（`/tr` + `/td`）。不盖时间戳的话，证书一过期，已经发出去的安装包就会变成
   「签名无效」，用户装不了。
2. **签名必须发生在打包之前或打包之中**。只签最外层 NSIS 安装包是不够的——解包后安装到
   `%LOCALAPPDATA%` 里的 `Cairn.exe` 仍是未签名，用户每次启动都还会看到未知发布者。
   electron-builder 的 `npm run dist` 会两处都签，别手工只签外层。
