## 0. 一页结论

你提的四件事（常见文件采集 + 本地 OCR、自建课程工作区、试卷导入识别、原文按原件显示）**彼此不是同一层的东西**：前两件是"数据怎么进来、怎么组织"，后两件是"进来之后怎么看、怎么用"。混在一起做会同时改采集、存储、渲染、题库四块，一次交付不出去。

所以拆成四层，**每层都能单独上线、单独回滚**：

| 层 | 做什么 | 新增依赖 | 主包/组件体积 | 工期 | 没有它会怎样 |
|---|---|---|---|---|---|
| **L1 本地文件与工作区** | docx / pdf / pptx / xlsx / txt 直接进库 + 用户自建**工作区** + 原文按类型呈现（文本级） | 纯 Python，5 个小库 | 主包 **+16 MB**（估） | 5–7 天 | 只能粘文本，课程资料进不来 |
| **L2 试卷导入与本地识别** | 扫描件/图片走**本地 OCR**（组件化）+ 试卷结构化 + 人工复核 + AI 校对 | 一个 `cairn-ocr` 组件 | 组件 **≈150 MB 下载** | 6–8 天 | 电子版试卷能导，扫描件不行 |
| **L3 原件级呈现** | PDF 逐页原样渲染、点引用跳到第 N 页高亮、docx 图片与表格 | 前端 `pdfjs-dist` | 前端 **+1.5 MB** | 3–4 天 | 原文只是"文本"，不是"原件" |
| **L4 明确不做** | 手写体、公式、LibreOffice 级 Office 渲染、云 OCR、旧版 `.doc` | — | — | — | 做了也做不好，不如说清 |

**一句话**：L1 解决 80% 的课程资料（电子讲义、电子试卷），L2 补上剩下 20%（拍照/扫描），L3 才是"像在看原件"。**建议 L1 立刻做，L2 视你有没有扫描件样本再定，L3 可等 L1 用一周后再判。**

## 3. 分层方案

每层写四件事：**做什么 / 为什么放这层 / 刻意不做什么 / 完成信号**。

### L1 · 本地文件与工作区（P0，先做）

**做什么**

1. **文件上传落盘**：文件存到 `<数据目录>/files/<item_id>/<sha256 前 8 位>.<ext>`，原件永久保留；库里只登记元数据（原文件名、大小、页数、有无文本层）。同一份文件重复上传按 sha256 命中，不重复占盘。
2. **文本抽取**（按格式分派，见 §4 表）：docx 取段落+表格+标题层级；pdf 逐页取文本层；pptx 取每页形状文本与备注；xlsx 取单元格转 Markdown 表；txt/md 直读。
3. **工作区**：用户手动建的一维文件夹（`workspace` 表），可改名、换色、排序、删除（删除时内容回到「未归类」，不删内容）。一条内容只属一个工作区。
4. **原文呈现（文本级）**：docx → 转 HTML（保留标题/列表/表格/粗斜体，走 `bleach` 白名单）；pptx → 按页大纲；pdf → 按页分节的文本视图，每节标「第 N 页」；图片 → 原图+文字左右对照（L2 才有字）。
5. **采集面板合并**：三个 tab 收成两个（「粘贴文本」「文件与链接」），删掉只认 txt 的重复入口。

**为什么放这层**：全部是纯 Python 小库，**零组件下载**，装完就能用。这一步就能覆盖电子讲义、电子试卷、课程 PPT——也就是"某个课程的相关知识库文件"的绝大多数。

**刻意不做**：不做 OCR（扫描件在 L1 里明确提示「这份是扫描件，装上识别组件才能读」）；不做 PDF 原样渲染；不做 `.doc`（97-2003 旧格式）；不做 Excel 图表。

**完成信号**：不装任何组件的前提下，一份课程 docx 进库 → 原文页看到排版 → 建一个工作区把它放进去 → 左栏能按工作区筛出来。

### L2 · 试卷导入与本地识别（P1）

**做什么**

1. **`cairn-ocr` 组件**：复用现有组件协议（`components/_protocol.py` 那套一行一个 JSON），`op: "ocr"` 收图片字节、回 `[{page, lines:[{text, box, conf}]}]`。引擎 RapidOCR（PP-OCRv4 的 ONNX 版），中文印刷体够用。
2. **扫描 PDF 处理链**：逐页渲染成图（pypdfium2）→ OCR → 合并成带页码的文本；页图缓存到文件目录，供原文页显示。
3. **试卷结构化**：抽取/识别出来的文本 → 规则清洗（题号规范化、选项对齐）→ 模型结构化（题干、选项、答案、解析、分值、大题）→ **前端持有草稿** → 复核 → 一次提交进题库。
4. **AI 校对**：分三层——规则层（去页眉页脚、合并断行、全半角、`1.` `（1）` `一、` 归一）→ 模型层（只改错字与断行，**不许改写内容**，输出逐条 diff）→ 人工层（复核界面显示"改了 K 处"，可逐条接受/拒绝，原 OCR 文本永远保留）。
5. **整套练习**：导入的试卷在练习页能"按卷刷"，不必一题一题挑。

**为什么放这层**：OCR 引擎哪怕用最省的组合也要 150 MB 上下，塞主包会把 L1 的体积收益全吃掉；而它只服务"扫描件"这一种场景。做成组件既符合已有架构，也让不想装的人不受影响。

**刻意不做**：不做手写体、不做公式转 LaTeX（会坏，而且坏得看不出来）、不做自动判分（答案缺失时无从判）、不接任何云 OCR。

**完成信号**：拍一张试卷照片 → 10–20 秒出文字 → 复核界面出 20 题、能改题干和答案 → 确认导入 → 练习页能答、能判分、错题进复习。

### L3 · 原件级呈现（P2）

**做什么**

1. **PDF 原样渲染**：前端 `pdfjs-dist` 逐页 canvas，可选文本层，支持页内搜索；问答引用点进去直接定位到第 N 页并高亮那一段（靠 L2 落的逐页文本做 page 映射）。
2. **docx 图片与嵌套表格**：L1 只出文字骨架，这层补内嵌图片（文件流，不塞 base64 到数据库）。
3. **原件与文字对照**：左边原件、右边抽取文本，能互相跳（点段落定位到页/行）。

**为什么放这层**：这是"体验升级"不是"能用"，而且它依赖 L2 的逐页文本才有意义（没有页映射，跳过去也只能到第一页）。单独一层，做完 L1 用一周再判值不值。

**刻意不做**：**不引 LibreOffice**（多 300 MB，只为一件事）；pptx 不做像素级还原；不做"编辑原件"。

**完成信号**：PDF 里点引用 → 打开第 7 页、高亮命中段；30 页 PDF 首屏 1 秒内出第一页。

### L4 · 明确不做（写下来是为了不再讨论）

| 不做 | 理由 |
|---|---|
| 手写体识别 | 中文手写准确率撑不住"能用"，做出来是"看起来能识别" |
| 公式 → LaTeX | 上下标/分式必碎，且错得静默；定量结论不能靠它 |
| LibreOffice 转换 | +300 MB 换一个"能看到 PPT 缩略图"，性价比不成立 |
| 云 OCR（百度/腾讯） | 与"数据在你硬盘上"的定位冲突，且要配第二套 Key |
| 旧版 `.doc` / `.wps` | 格式私有且旧；提示另存为 `.docx`，一句话解决 |
| 工作区多人共享 | 红线 1：不做多用户 |

## 4. 技术选型（含许可与体积，这是能不能做的前提）

**许可必须先看**：项目是 MIT，引入 AGPL 会传染。PDF 这一块最容易踩——

| 用途 | 选型 | 许可 | 体积（估） | 放哪 |
|---|---|---|---|---|
| docx 读 | `python-docx` | MIT | 0.4 MB | 主包 |
| docx → HTML | `mammoth`（Python 版） | BSD-2 | 0.3 MB | 主包 |
| pptx 读 | `python-pptx` | MIT | 1.2 MB | 主包 |
| xlsx 读 | `openpyxl` | MIT | 2.5 MB | 主包 |
| PDF 取文本 + 页图渲染 | `pypdfium2`（PDFium） | BSD-3 / Apache-2.0 | 12 MB | 主包 |
| **PDF 库备选** | ~~PyMuPDF~~ | **AGPL-3.0** | 60 MB | **不用**：传染性许可，与 MIT 冲突 |
| OCR 引擎 | `rapidocr-onnxruntime` + PP-OCRv4 模型 | Apache-2.0 | 33 MB（含模型 15 MB） | 组件 |
| OCR 推理 | `onnxruntime` | MIT | 68 MB | 组件 |
| 图像预处理 | `opencv-python-headless` | Apache-2.0 | 40 MB | 组件 |
| PDF 前端渲染 | `pdfjs-dist` | Apache-2.0 | 1.5 MB（gzip 后约 0.5） | 前端 |

**结论**：主包 **+16 MB**（172 → 约 188 MB）；OCR 组件下载 **≈150 MB**、装后约 230 MB。两个数字都要在动手前实测一次（现有 `tools/build_components.py` 加一个 `ocr` 条目即可，协议不用改）。

**格式支持矩阵**（这张表就是 L1/L2 的边界，别在实现时悄悄扩大）

| 格式 | L1 文本抽取 | L1 原文呈现 | L2 补充 | 说明 |
|---|---|---|---|---|
| `.docx` | ✅ python-docx | ✅ 转 HTML | 内嵌图片放 L3 | 图里的字读不到 |
| `.pdf` 有文本层 | ✅ 逐页取文本 | ✅ 按页分节 | L3 上 pdfjs | 双栏可能串行 |
| `.pdf` 扫描件 | ❌ | ✅ 页图（无字） | ✅ OCR | 不装组件时明确提示 |
| `.pptx` | ✅ 形状文本+备注 | ✅ 按页大纲 | — | 不做版式还原 |
| `.xlsx` | ✅ 首个工作表 → 表格 | ✅ 表格 | — | 多表只取第一张并提示 |
| `.png .jpg .jpeg .webp` | ❌ | ✅ 原图 | ✅ OCR | — |
| `.txt .md` | ✅ | ✅ 现有纯文本 | — | 已有能力 |
| `.doc` `.wps` | ❌ | ❌ | ❌ | 提示另存为 docx |

## 5. 数据模型变更（字段意图，不是 DDL）

> **本节故意不写 `CREATE TABLE`**：按数据契约 §1「表结构变更先登记、再迁移」，
> 落地那一轮才动 `backend/app/db/schema.sql` + 数据契约（`user_version` 3 → 4）+ ADR。
> 这里只把**字段意图**定死，避免实现时各写一套。

### 5.1 新表 `workspace`（用户自建文件夹）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `name` | TEXT NOT NULL | 展示名，≤20 字（与标题同口径）；**同名允许，不做唯一约束** |
| `color` | TEXT | 可选，取主题色 id；空 = 默认色 |
| `sort_order` | INTEGER DEFAULT 0 | 手动排序；只影响左栏显示 |
| `created_at` / `updated_at` | TEXT | ISO 带时区 |

**不做嵌套**：一条内容属于一个工作区，工作区之间平级。课程维度一层就够，嵌套树 + 拖拽排序是另一周的 UI 成本（§14 D1 可推翻，但要有理由）。

### 5.2 `knowledge_item` 增列

| 列 | 类型 | 说明 |
|---|---|---|
| `workspace_id` | INTEGER NULL → `workspace(id)` ON DELETE SET NULL | 删工作区不删内容，内容回落到「未归类」 |
| `kind` | TEXT NOT NULL DEFAULT `'material'` | `material` 资料 / `exam` 试卷 / `image` 图片 / `note` 手记。**决定「整理」怎么跑**（见 §5.5） |
| `file_id` | INTEGER NULL → `item_file(id)` | 一条内容的主文件；无文件（粘贴文本）时为 NULL |

### 5.3 新表 `item_file`（原件元数据）

之所以独立成表、不塞进 `knowledge_item`：一份试卷可能挂「卷面 + 答案」两个文件；文件元数据（页数、识别状态）变化频繁，和内容字段的读写节奏不同。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `item_id` | INTEGER NOT NULL → CASCADE | 删内容连带删记录 |
| `role` | TEXT DEFAULT `'main'` | `main` 卷面 / `answer` 答案 / `attachment` 附件 |
| `original_name` | TEXT | 原文件名，仅展示与导出用 |
| `ext` / `mime` | TEXT | 分派渲染器用 |
| `size` | INTEGER | 字节 |
| `sha256` | TEXT | 去重（同文件不重复占盘） |
| `stored_path` | TEXT | **相对数据目录**，不存绝对路径（换机器还能用） |
| `page_count` | INTEGER | PDF/PPT 页数；其他为 0 |
| `has_text_layer` | INTEGER | 1 = 能直接抽文本；0 = 需要 OCR |
| `ocr_status` | TEXT | `none` / `pending` / `running` / `done` / `failed` |

### 5.4 新表 `item_page`（逐页文本，L2 起用）

一次 OCR 很贵（一张 A4 数秒），**必须缓存**，否则每次打开原文都重跑。同时它是 L3「跳转到第 N 页」的唯一依据。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `item_id` / `file_id` | INTEGER → CASCADE | |
| `page_no` | INTEGER | 从 1 开始 |
| `text` | TEXT | 该页文本（抽取或 OCR 结果） |
| `source` | TEXT | `text_layer` / `ocr` |
| `avg_conf` | REAL | OCR 平均置信度；低于阈值前端标黄 |
| `image_path` | TEXT | 页图相对路径（扫描件才有） |

### 5.5 `question` 增列

| 列 | 类型 | 说明 |
|---|---|---|
| `origin` | TEXT DEFAULT `'ai'` | `ai` 模型生成 / `imported` 试卷导入 / `manual` 手录 |
| `number` | TEXT | 原卷题号（`"12"`、`"二.3"`）；AI 生成时为 NULL |

**复用现有 `question` 表，不新建题库**。理由：`quiz_attempt` / `review_item` 都挂在 `question.id` 上；新建一套等于把作答、复习、错题本全部复制一遍。试卷 = 一条 `kind='exam'` 的内容，题目通过 `item_id` 关联，天然成"一套"。

分值、材料、题组放 `payload` JSON 里（`score` / `material` / `group`），**不改表**——`payload` 本来就是自由对象。

### 5.6 「整理」按 `kind` 分派（重要的取舍）

| kind | 整理做什么 | 为什么 |
|---|---|---|
| `material` | 现状不变：标题/摘要/要点/笔记/分类 | — |
| `exam` | **不写笔记**，只出「卷面概览」：科目、题型分布、题数、可见知识点 | 对试卷写"要点 + 笔记"是纯浪费 token，且会污染学习页 |
| `image` | 只出文字 + 一句话说明 | 图没有"笔记"可言 |

不这么做的话，用户采一张图点「整理」，会得到一份看起来像样、实际全是废话的笔记——这是当前架构下最容易踩的坑。

## 6. 端点变更

> 下表**省略统一的 `/api` 前缀**（契约登记时补全）。新增端点落地前必须先登记进 `contracts/接口契约.md`。

| 方法 | 路径 | 作用 | 层 |
|---|---|---|---|
| POST | `files` | 上传一个文件（multipart）→ 落盘 + 抽取 → 返回 `file_id`、页数、有无文本层、前 500 字预览 | L1 |

## 8. OCR 与 AI 校对的设计（R2 + R5）

这是最容易做成"看起来能用、实际不能用"的一块，所以把约束先写死。

### 8.1 识别链路

```
文件 → (有文本层? 直接抽 : 渲染成图) → OCR 组件 → 逐页文本 + 行框 + 置信度
      → 规则清洗 → 模型校对 → 人工复核 → 落 item_page
```

### 8.2 规则层（不花 token，先做掉一半问题）

| 规则 | 做法 |
|---|---|
| 页眉页脚 | 全文出现率 ≥20% 的短行 + 页面上下 12%/15% 区域内的行，删 |
| 断行合并 | 行尾无标点且下一行不以题号/项目符号开头 → 合并；中文不加空格 |
| 全半角 | 中文语境下把 `，。？：；（）` 的 ASCII 版本归一（英文段落不动） |
| 题号 | `1、` `1.` `(1)` `一、` `第1题` 统一成可解析记号；保留原始写法到 `number` |
| 选项对齐 | 行首 `A` `A.` `A、` `Ａ` 归一为 `A`，同一题的选项必须齐 4 个或明确标注"选项不全" |

### 8.3 模型层（只改错，不改写）

- **输入**：分块后的文本（每块 ≤2000 字），带行号。
- **输出**：`[{line: 12, before: "...", after: "...", why: "错字"}]`，**不许返回整篇重写**。
- **硬约束**（写进 prompt 并用断言检查）：`after` 与 `before` 的编辑距离不得超过该行长度的 30%；超了就整条丢弃，记 `dropped`。
- 拦的是最坏情况：模型"顺手润色"把一份试卷改成了另一篇文章，而用户看不出来。

### 8.4 人工层

- 复核界面显示「识别 118 行，模型改了 7 处」，逐条可接受/拒绝，默认全部接受但**每一条都能点开看前后对照**。
- 置信度 < 0.85 的行标黄；标黄行在复核时默认展开。
- **原始 OCR 文本永久保留**（`item_page.text` 不被覆盖，校对结果单独存一份 `text_reviewed`），任何时候能回退。

## 9. 试卷导入的状态机

```
① 上传        文件进 files/，建草稿（不建内容）
② 抽取/识别   有文本层直接抽；扫描件走 OCR（进度条 10/40/70/90）
③ 规则清洗    题号、选项、页眉页脚
④ 结构化      模型出 [{number, type, question, options, answer, explanation, score}]
⑤ 复核        ★ 人来改。这一步不能省，也不该"默认全对直接入库"
⑥ 提交        exams/commit 一次写入：1 条内容(kind=exam) + N 条题目(origin=imported)
```

**判断标准**：第 ⑤ 步允许"整体跳过"（一键确认），但**首屏必须是复核界面**，不是进度条直接跳到"导入成功"。试卷识别错一道题（尤其答案），比识别不出来的伤害大得多。

**题型映射**（必须落全，否则导进来的卷子答不了）

| 原卷题型 | 落到的 `type` | 备注 |
|---|---|---|
| 单选 | `single` | 答案 `"A"` |
| 多选 | `multiple` | 答案 `["A","C"]`，比较时转集合（现有逻辑） |
| 判断 | `boolean` | `true` / `false` |
| 填空 | `short` | 答案存文本；**不做多空分栏**，多空写成 `①…②…` |
| 简答/论述 | `short` | 走现有模型批改 |
| 材料题/大题 | `short` + `payload.material` | 材料放 `material`，小题各成一条，`payload.group` 相同 |

分值一律进 `payload.score`，不参与判分（现有判分不看分值）。

## 10. 现有冗余功能的处置（R7，逐条待你拍板）

**判断标准**：维护成本（代码 + 组件体积 + 每次改接口要同步的地方）减去真实使用价值。已经付掉的成本不算理由——沉没成本不该绑架后续。

| # | 功能 | 现状成本 | 我的建议 | 理由 |
|---|---|---|---|---|
| 1 | 采集面板「拖入文件」tab | 只认 txt/md，读进来切到粘贴页 | **删**，并入新的「文件」入口 | 与「粘贴文本」90% 重叠，且不能留原件 |
| 2 | 「网页渲染」组件（playwright 49 MB）+ 站点登录 | 一个组件 + 一个 router + 面板里一整块 UI | **降级**：能力保留，从首启引导移除，采集面板里收进「高级」折叠区 | 只为知乎/CSDN 这类站点服务；它和 OCR 抢体积时优先 OCR |
| 3 | 「视频转录」组件（100 MB + 539 MB 模型） | 现行组件最多的一个，模型最大 | **保留不动**，但文案不再推荐 | 已经做完，删了要让老用户重装；只是别在引导页推它 |

| 5 | 番茄钟 / 学习记录 / 仪表盘 | 三张表 + 一个页面 | **保留不动** | 删了仪表盘要重做，收益为零 |

**一句话**：真正该删的只有 #1（功能重叠）和 #2 的显性入口（成本收益不成立）。其余是"保持原样"，别在加新功能的时候顺手改老功能——那是最容易引入回归的方式。
