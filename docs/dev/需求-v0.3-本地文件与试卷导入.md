## 0. 一页结论

你提的四件事（常见文件采集 + 本地 OCR、自建课程工作区、试卷导入识别、原文按原件显示）**彼此不是同一层的东西**：前两件是"数据怎么进来、怎么组织"，后两件是"进来之后怎么看、怎么用"。混在一起做会同时改采集、存储、渲染、题库四块，一次交付不出去。

所以拆成四层，**每层都能单独上线、单独回滚**：

| 层 | 做什么 | 新增依赖 | 主包/组件体积 | 工期 | 没有它会怎样 |
|---|---|---|---|---|---|
| **L1 本地文件与本地识别** | docx / pdf / pptx / xlsx / txt 进库 + **PDF 与图片一律本地识别** + 用户自建**工作区** + 原文按类型呈现 | 4 个 Python 小库 + 一个 `cairn-ocr` 组件 | 主包 **+10 MB**；识别组件 **109.5 MB 下载**（实测） | 7–9 天 | 只能粘文本，课程资料进不来；PDF 进来读不出字 |
| **L2 试卷导入与校对** | 试卷结构化 + 人工复核 + AI 校对 + 目录批量导入 + 按卷练习 | 无新依赖（复用 L1 的识别结果） | — | 5–6 天 | 文字进得来，但拆不成能做的题 |
| **L3 原件级呈现** | PDF 逐页原样渲染、点引用跳到第 N 页高亮、docx 图片与表格 | 前端 `pdfjs-dist` | 前端 **+1.5 MB** | 3–4 天 | 原文只是"文本"，不是"原件" |
| **L4 明确不做** | 手写体、公式、LibreOffice 级 Office 渲染、云 OCR、旧版 `.doc` | — | — | — | 做了也做不好，不如说清 |

**一句话**：L1 让课程资料"进得来、读得出"（PDF 与图片靠本地识别，不靠 PDF 文本层）；L2 让试卷"拆得成题"；L3 才是"像在看原件"。**建议 L1 立刻做，L2 紧随其后，L3 可等 L1 用一周后再判。**

## 3. 分层方案

每层写四件事：**做什么 / 为什么放这层 / 刻意不做什么 / 完成信号**。

### L1 · 本地文件与本地识别（P0，先做）

**做什么**

1. **文件上传落盘**：文件存到 `<数据目录>/files/<item_id>/<sha256 前 8 位>.<ext>`，原件永久保留；库里只登记元数据（原文件名、大小、页数、识别状态）。同一份文件重复上传按 sha256 命中，不重复占盘。
2. **PDF 逐页本地识别（核心）**：`pypdfium2` 把每页渲染成图（长边 1600 px，约 150 dpi）→ `cairn-ocr` 组件 → 每页文本 + 行框 + 置信度 → 写 `item_page` 并**缓存**。同一份 PDF 第二次打开不重跑。**电子版与扫描件走同一条链路，不区分**；文本层只在"整页一个字都没认出来"时兜底，另用于页数与 L3 的坐标定位。模型默认 **PP-OCRv6 small**（自带、离线），设置里可切 medium 质量档。**行框给的是坐标不是阅读顺序**，双栏必须自己判列（实测必现交错，见 §4.1）。
3. **图片识别**：`.png .jpg .jpeg .webp` 直接送同一个组件，结果按"第 1 页"存。
4. **非 PDF 的文本抽取**：docx 取段落+表格+标题层级；pptx 取每页形状文本与备注；xlsx 取首个工作表转 Markdown 表；txt/md 直读。这四类有可靠的结构化读取，不需要识别。
5. **工作区**：用户手动建的一维文件夹（`workspace` 表），可改名、换色、排序、删除（删除时内容回到「未归类」，不删内容）。一条内容只属一个工作区。
6. **原文呈现（文本级）**：pdf → 按页分节，每节标「第 N 页」，并把已渲染的页图放在文字上方（所见即识别依据）；docx → 转 HTML（保留标题/列表/表格/粗斜体，走 `bleach` 白名单）；pptx → 按页大纲；图片 → 原图 + 文字左右对照。
7. **采集面板合并**：三个 tab 收成两个（「粘贴文本」「文件与链接」），删掉只认 txt 的重复入口。

**为什么 PDF 必须走本地识别**（这条决定 L1 的范围，不能回退）

- **中文 PDF 的文本层经常是坏的**：字体子集缺 `ToUnicode` 映射，抽出来是方块、乱码，或"每个字都对但顺序全乱"。`has_text_layer=1` 只说明有字，不说明能读。
- **双栏与表格会串行**：文本层按绘制顺序吐字，双栏讲义抽出来是左右交错，模型拿到的句子本身就是错的。
- **"电子版"不等于"有真文本层"**：不少课件是把扫描图贴进 PDF 再加一行页脚文字，看标记有文本层，正文一个字抽不到。
- 文本层仍留着三个用处：页数、L3 页内坐标定位、与识别结果交叉校验（同页字数差 >40% 就提示复核）。**它是校验依据，不是读取路径。**

**为什么识别组件放在 L1 而不是 L2**：它不是"扫描件专用补丁"，而是 PDF 的读法。放 L2 会出现一个说不清的中间态——PDF 是 L1 支持的格式，但读不出字。组件化本身保留：主包不涨，首次处理 PDF/图片时引导装一次，装完永久可用。

**刻意不做**：不做云 OCR；不做手写体；不做公式转 LaTeX；不做 PDF 原样渲染（L3）；不做 `.doc`（97-2003 旧格式）；不做 Excel 图表。

**完成信号**：装好识别组件后，一份电子版 PDF 与一份扫描 PDF 各进一次 → 都出逐页文字、页码连续、双栏基本可读 → 原文页能按页翻并看到页图 → 建一个工作区把它放进去，左栏能筛出来。未装组件时 docx/pptx/xlsx/txt 照常可用，PDF/图片给出"去设置装识别组件"的明确引导。

### L2 · 试卷导入与 AI 校对（P1）

**做什么**

1. **试卷结构化**：L1 已给出的逐页文本 → 规则清洗（题号规范化、选项对齐）→ 模型结构化（题干、选项、答案、解析、分值、大题）→ **前端持有草稿** → 复核 → 一次提交进题库。
2. **AI 校对**：分三层——规则层（去页眉页脚、合并断行、全半角、`1.` `（1）` `一、` 归一）→ 模型层（只改错字与断行，**不许改写内容**，输出逐条 diff）→ 人工层（复核界面显示"改了 K 处"，可逐条接受/拒绝，原识别文本永远保留）。
3. **整套练习**：导入的试卷在练习页能"按卷刷"，不必一题一题挑。
4. **目录批量导入**：选一个课程文件夹，按清单批量进库（识别在 L1，这里只管排队与失败重试）。

**为什么放这层**：结构化的前提是"文字已经准了"。识别在 L1 收口，一旦题目对不上，就只会是拆题的问题，不会是"到底是认错了字还是拆错了题"。两件事混在一起做，这种归因做不出来。

**刻意不做**：不做自动判分（答案缺失时无从判）；不做"识别不出的题自动编一个"；不做第三方题库模板导入（Anki/Excel），先把 PDF/图片这条路走通。

**完成信号**：一份 20 题的扫描试卷 → 出逐页文字 → 复核界面出 20 题、能改题干和答案 → 确认导入 → 练习页能答、能判分、错题进复习。

### L3 · 原件级呈现（P2）

**做什么**

1. **PDF 原样渲染**：前端 `pdfjs-dist` 逐页 canvas，可选文本层，支持页内搜索；问答引用点进去直接定位到第 N 页并高亮那一段（靠 L1 落的逐页文本与页图做 page 映射）。
2. **docx 图片与嵌套表格**：L1 只出文字骨架，这层补内嵌图片（文件流，不塞 base64 到数据库）。
3. **原件与文字对照**：左边原件、右边识别文本，能互相跳（点段落定位到页/行）。

**为什么放这层**：这是"体验升级"不是"能用"，而且它依赖 L1 的逐页文本与页图才有意义（没有页映射，跳过去也只能到第一页）。单独一层，做完 L1 用一周再判值不值。

**刻意不做**：**不引 LibreOffice**（多 300 MB，只为一件事）；pptx 不做像素级还原；不做"编辑原件"。

**完成信号**：PDF 里点引用 → 打开第 7 页、高亮命中段；30 页 PDF 首屏 1 秒内出第一页。

### L4 · 明确不做（写下来是为了不再讨论）

| 不做 | 理由 |
|---|---|
| 手写体识别 | 中文手写准确率撑不住"能用"，做出来是"看起来能识别" |
| 公式 → LaTeX | 上下标/分式必碎，且错得静默；定量结论不能靠它 |
| LibreOffice 转换 | +300 MB 换一个"能看到 PPT 缩略图"，性价比不成立 |
| 云 OCR（百度/腾讯） | 与"数据在你硬盘上"的定位冲突，且要配第二套 Key |
| 旧版 `.doc` / `.wps` | 格式私有且旧；提示另存为 `.docx`，一句话解决 |
| 工作区多人共享 | 红线 1：不做多用户 |

## 4. 技术选型（含许可与体积，这是能不能做的前提）

**许可必须先看**：项目是 MIT，引入 AGPL 会传染。PDF 这一块最容易踩——

| 用途 | 选型 | 许可 | 体积 | 放哪 |
|---|---|---|---|---|
| docx 读 | `python-docx` | MIT | 0.4 MB | 主包 |
| docx → HTML | `mammoth`（Python 版） | BSD-2 | 0.3 MB | 主包 |
| pptx 读 | `python-pptx` | MIT | 1.2 MB | 主包 |
| xlsx 读 | `openpyxl` | MIT | 2.5 MB | 主包 |
| PDF 页图渲染（识别前置） | `pypdfium2`（PDFium） | BSD-3 / Apache-2.0 | 4.2 MB（win 轮子） | 主包 |
| **PDF 库备选** | ~~PyMuPDF~~ | **AGPL-3.0** | 60 MB | **不用**：传染性许可，与 MIT 冲突 |
| 识别引擎 | `rapidocr` 3.10（**内置 PP-OCRv6 det/rec small**） | Apache-2.0（模型来自 PaddleOCR，同为 Apache-2.0） | 27.3 MB（含模型） | 组件 |
| 识别推理 | `onnxruntime` | MIT | 14.9 MB | 组件 |
| 图像预处理 | `opencv-python-headless` | Apache-2.0 | 43.8 MB | 组件 |
| PDF 前端渲染 | `pdfjs-dist` | Apache-2.0 | 1.5 MB（gzip 后约 0.5） | 前端 |

**为什么用 RapidOCR 而不是直接 `pip install paddleocr`**：RapidOCR 就是"PaddleOCR 的模型 + ONNX Runtime"，同一个 PP-OCRv6，不装 PaddlePaddle。实测两条路的依赖树（Windows / Python 3.13 / 2026-11-12）：

| | RapidOCR + onnxruntime | 官方 paddleocr 3.7 + onnxruntime |
|---|---|---|
| 依赖包数 | **21** | 68（连带 pandas、modelscope、huggingface-hub、cryptography…） |
| 下载体积 | **109.5 MB** | 127.8 MB |
| 是否要 PaddlePaddle | 否 | 否（3.7 已把 paddle 从硬依赖里拿掉），但默认仍走 Paddle Inference |
| 模型来源 | **随包自带**，首次不用联网 | 首次运行从 ModelScope / HF 下载 |
| 许可证 | Apache-2.0（含模型） | Apache-2.0 |

我们这个项目是离线优先 + 组件化，**自带模型、21 个包**这一条就够定案了。

### 4.1 识别引擎实测（本机，2026-11-12）

环境：Python 3.13 · `rapidocr` 3.10.0 · `onnxruntime` 1.31.1 · Windows · CPU 单线程默认。样本 1240×1754（A4 @150dpi）、微软雅黑 30px、12 行中文讲义段落。

| 项 | 实测 |
|---|---|
| 下载 / 装后 | 109.5 MB / 21 个包；`site-packages` **293 MB** |
| 自带模型 | `PP-OCRv6_det_small` + `PP-OCRv6_rec_small` + `ch_ppocr_mobile_v2.0_cls`，**全部在包里，离线可用** |
| 单页耗时 | 冷启动 3.0 s（含 import 2.3 s），热 2.8 s |
| 干净印刷体 | 12/12 行全部命中，置信度 0.94–1.00，字符准确率 **100%** |
| 模拟拍照件（+高斯噪声 / 1.5° 旋转 / JPEG q55） | 字符准确率 **99.3%**，切出 13 行 |
| **双栏排版** | **输出顺序是左右交错的**（左1 → 右1 → 左2 → 右2…） |
| 可切换档位 | tiny 1.5M 参数（≈6 MB）/ small 7.7M（默认，≈18 MB）/ medium 34.5M（≈80 MB，需另下） |

**这两条要写进实现约束**：

1. **双栏判列必须自己做**——引擎只给行框，不给阅读顺序；按 y 排序就是交错。这不是"可能有问题"，是实测必现（T9.6 的验收项因此不能删）。
2. **默认 small 档就够**：干净件 100%、模拟拍照件 99.3%。medium 留成"质量档"开关（讲义扫描得糊、或模板题号认不准时换），不默认开——它要多下 60 MB、耗时翻倍。

**结论**：主包 **+~10 MB**（4.2 + 0.4 + 0.3 + 1.2 + 2.5，172 → 约 182 MB）；识别组件下载 **109.5 MB**、装后约 290 MB。**PDF 与图片必须装组件才能读字**，这是本方案明确的取舍：宁可多一次下载，不要一个"PDF 支持了但读不出字"的中间态。

**格式支持矩阵**（这张表是 L1/L2 的边界，别在实现时悄悄扩大）

| 格式 | 文本从哪来 | 原文呈现 | 组件未装时 | 说明 |
|---|---|---|---|---|
| `.docx` | ✅ python-docx 结构化读取 | ✅ 转 HTML | 可用 | 图里的字读不到（L3 补图） |
| `.pdf`（电子版，有文本层） | ✅ **本地识别**（文本层仅校验） | ✅ 页图 + 按页文本 | ❌ 提示装组件 | 文本层可能乱码/串行，不作读取路径 |
| `.pdf`（扫描件） | ✅ **本地识别** | ✅ 页图 + 按页文本 | ❌ 提示装组件 | 与电子版同一条链路，不区分 |
| `.pptx` | ✅ 形状文本 + 备注 | ✅ 按页大纲 | 可用 | 不做版式还原 |

之所以独立成表、不塞进 `knowledge_item`：一份试卷可能挂「卷面 + 答案」两个文件；文件元数据（页数、识别状态）变化频繁，和内容字段的读写节奏不同。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `item_id` | INTEGER NOT NULL → CASCADE | 删内容连带删记录 |
| `role` | TEXT DEFAULT `'main'` | `main` 卷面 / `answer` 答案 / `attachment` 附件 |

一次识别很贵（一张 A4 实测约 2.8 秒），**必须缓存**，否则每次打开原文都重跑。它同时是 L3「跳转到第 N 页」的唯一依据。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `item_id` / `file_id` | INTEGER → CASCADE | |
| `page_no` | INTEGER | 从 1 开始 |
| `text` | TEXT | 该页文本，**主来源是本地识别** |
| `source` | TEXT | `ocr`（默认）/ `text_layer`（仅当整页识别为空时的兜底，前端要标出来）/ `extract`（docx/pptx/xlsx 结构化抽取） |
| `avg_conf` | REAL | 识别平均置信度；< 0.85 前端标黄 |
| `image_path` | TEXT | 页图相对路径（PDF 与图片都有，供原文页显示与人工比对） |

### 5.5 `question` 增列

| 列 | 类型 | 说明 |
|---|---|---|
| `origin` | TEXT DEFAULT `'ai'` | `ai` 模型生成 / `imported` 试卷导入 / `manual` 手录 |
| `number` | TEXT | 原卷题号（`"12"`、`"二.3"`）；AI 生成时为 NULL |

**复用现有 `question` 表，不新建题库**。理由：`quiz_attempt` / `review_item` 都挂在 `question.id` 上；新建一套等于把作答、复习、错题本全部复制一遍。试卷 = 一条 `kind='exam'` 的内容，题目通过 `item_id` 关联，天然成"一套"。

分值、材料、题组放 `payload` JSON 里（`score` / `material` / `group`），**不改表**——`payload` 本来就是自由对象。

### 5.6 「整理」按 `kind` 分派（重要的取舍）

| kind | 整理做什么 | 为什么 |
|---|---|---|
| `material` | 现状不变：标题/摘要/要点/笔记/分类 | — |
| `exam` | **不写笔记**，只出「卷面概览」：科目、题型分布、题数、可见知识点 | 对试卷写"要点 + 笔记"是纯浪费 token，且会污染学习页 |
| `image` | 只出文字 + 一句话说明 | 图没有"笔记"可言 |

不这么做的话，用户采一张图点「整理」，会得到一份看起来像样、实际全是废话的笔记——这是当前架构下最容易踩的坑。

## 8. 本地识别与 AI 校对的设计（R2 + R5）

这是最容易做成"看起来能用、实际不能用"的一块，所以把约束先写死。

### 8.1 识别链路（PDF 与图片只有这一条）

```
PDF → pypdfium2 逐页渲染（150 dpi，长边 1600 px）→ PNG
图片 → 原图（超长边缩到 1600 px）
      ↓
cairn-ocr 组件（本地，RapidOCR / PP-OCRv6 small）→ 每页 [{text, box, conf}]
      ↓
按行框重排（y 聚类成行，行内按 x 排序；页高 12%/15% 之外的行记作页眉页脚候选）
      ↓
存 item_page（source='ocr', avg_conf, image_path）→ 页面级缓存
      ↓
[试卷] 规则清洗 → 模型校对 → 人工复核 → 结构化
```

**三件必须一开始就做对的事**

1. **页图就是"原文"**：识别结果永远和当页页图配对存。用户看到文字的同时能看到它是从哪张图来的——错了一眼就能看出来，这比任何置信度显示都有效。
2. **逐页落库 + 断点续跑**：进程关掉、机器重启、组件被卸载，已识别的页不重跑。重识别只针对失败页或用户点名的页。
3. **先渲染后识别、单页即释放**：不要一次把 300 页都转成图放内存。单页"渲染 → 识别 → 落库 → 释放"，常驻内存只有一页。

### 8.2 识别质量与速度（PDF 场景的真实约束）

| 项 | 取值 | 理由 |
|---|---|---|
| 渲染 DPI | 150（长边 1600 px） | 再高识别准确率提升有限，耗时线性上涨；再低小字号开始糊 |
| 单页耗时 | 实测 2.8 秒（单线程，A4@150dpi） | 30 页串行约 84 秒；2–4 页并发后约 30–50 秒，属于"喝口水"的量级 |
| 并发 | 2–4 页并行（按 CPU 核数） | 再多会互相抢核，总时长反而变长 |
| 文本层校验 | 同页字数差 > 40% 或识别置信度 < 0.6 → 该页标"需复核" | 文本层不可读也要能发现"这页可能有问题" |
| 双栏 | 行框聚类后按列切分再排序 | 引擎只给行框、不给阅读顺序；实测输出是左1→右1→左2→右2，按 y 排序必然交错。这是识别链路里最容易错得看不出来的一步 |

### 8.3 规则层（不花 token，先做掉一半问题）

| 规则 | 做法 |
|---|---|
| 页眉页脚 | 全文出现率 ≥20% 的短行 + 页面上下 12%/15% 区域内的行，删 |
| 断行合并 | 行尾无标点且下一行不以题号/项目符号开头 → 合并；中文不加空格 |
| 全半角 | 中文语境下把 `，。？：；（）` 的 ASCII 版本归一（英文段落不动） |
| 题号 | `1、` `1.` `(1)` `一、` `第1题` 统一成可解析记号；保留原始写法到 `number` |
| 选项对齐 | 行首 `A` `A.` `A、` `Ａ` 归一为 `A`，同一题的选项必须齐 4 个或明确标注"选项不全" |

### 8.4 模型层（只改错，不改写）

- **输入**：分块后的文本（每块 ≤2000 字），带行号。
- **输出**：`[{line: 12, before: "...", after: "...", why: "错字"}]`，**不许返回整篇重写**。
- **硬约束**（写进 prompt 并用断言检查）：`after` 与 `before` 的编辑距离不得超过该行长度的 30%；超了就整条丢弃，记 `dropped`。
- 拦的是最坏情况：模型"顺手润色"把一份试卷改成了另一篇文章，而用户看不出来。
- **识别是主，校对是辅**：校对只处理"形近字、断行、全半角、题号错位"，不负责"把读错的一整句补回来"——那种情况交给人看页图。

### 8.5 人工层

- 复核界面显示「识别 118 行，模型改了 7 处」，逐条可接受/拒绝，默认全部接受但**每一条都能点开看前后对照**。
- 置信度 < 0.85 的行标黄；标黄行在复核时默认展开，旁边就是当页页图。
- **原始识别文本永久保留**（`item_page.text` 不被覆盖，校对结果单独存一份 `text_reviewed`），任何时候能回退。

## 9. 试卷导入的状态机

```
① 上传        文件进 files/，建草稿（不建内容）
② 本地识别    逐页渲染 → 识别 → item_page（进度 12/30 页；失败页可单独重试）
③ 规则清洗    题号、选项、页眉页脚
④ 结构化      模型出 [{number, type, question, options, answer, explanation, score}]
⑤ 复核        ★ 人来改。这一步不能省，也不该"默认全对直接入库"
⑥ 提交        exams/commit 一次写入：1 条内容(kind=exam) + N 条题目(origin=imported)
```

**判断标准**：第 ⑤ 步允许"整体跳过"（一键确认），但**首屏必须是复核界面**，不是进度条直接跳到"导入成功"。试卷识别错一道题（尤其答案），比识别不出来的伤害大得多。

**题型映射**（必须落全，否则导进来的卷子答不了）

| 原卷题型 | 落到的 `type` | 备注 |
|---|---|---|
| 单选 | `single` | 答案 `"A"` |
| 多选 | `multiple` | 答案 `["A","C"]`，比较时转集合（现有逻辑） |
| 判断 | `boolean` | `true` / `false` |
| 填空 | `short` | 答案存文本；**不做多空分栏**，多空写成 `①…②…` |
| 简答/论述 | `short` | 走现有模型批改 |
| 材料题/大题 | `short` + `payload.material` | 材料放 `material`，小题各成一条，`payload.group` 相同 |

分值一律进 `payload.score`，不参与判分（现有判分不看分值）。

| 4 | 在线演示站（`dist-demo` + `src/demo/`） | 第二份数据源，改接口要同步 fixture | **保留，但不随每次改动更新**，只在发版前重建 | 它是仓库的门面，成本已沉没；变成本在于"每次都同步"，改成"发版前同步"即可 |
| 5 | 番茄钟 / 学习记录 / 仪表盘 | 三张表 + 一个页面 | **保留不动** | 删了仪表盘要重做，收益为零 |

## 12. 验收标准

除了每层自己的 `verify_mN.py`，整体还要满足：

1. **识别必须离线**：断网状态下完成一份 PDF 的识别，抓包确认无任何外发请求。
2. **组件缺失时边界清楚**：docx/pptx/xlsx/txt 照常可用；PDF/图片给"去设置装识别组件"的明确指引（不报错、不假装成功、不留半份乱码内容）。
3. **识别质量基线**：一份 20 页电子版 PDF + 一份 20 页扫描 PDF，各抽 5 页人工比对。**目标值**：电子版 ≥99%，扫描件 ≥95%（字符准确率，按行计）。这两个数是验收前实测后写死的，不靠估。
4. **性能**：30 页 PDF 首次识别 ≤60 秒（2–4 页并发；单线程实测 2.8 秒/页）；已有缓存时打开原文 ≤1 秒出首屏；单页失败可单独重试。
5. **数据可迁移**：把整个数据目录复制到另一台机器，文件、工作区、试卷、题目全部可用（`stored_path` 必须是相对路径）。
6. **体积**：主包 ≤195 MB（预计 182 MB，若坚持 175 MB见 §14 D3）；识别组件 **≤130 MB 下载**（实测 109.5 MB）。
7. **回归**：`tools/regress.py` 一条命令跑完 m1–m11，全绿。
8. **文案**：新界面所有可见文案过 `verify_m7.py` 的禁止词扫描（术语用「内容」「已整理」「存进知识库」，不出现「条目」「入库」「后端」）。

## 13. 风险与前置条件

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **没有真实样本** | 抽取与识别全部无法验收（"看起来对"和"真的对"差很远） | **动手前请给 4 份**：课程 docx（带图带表）、**双栏讲义 PDF**、电子版试卷、扫描/拍照试卷 |
| 2 | 主包 +10 MB 破 175 MB 目标 | 与 M8 的体积承诺冲突 | 见 §14 D3：要么放宽到 195，要么把 xlsx 挪到 L3 |
| 3 | 识别组件打包 | 现有 `build_components.py` 未含 opencv/onnxruntime，首次打包大概率踩 DLL 缺失 | 先打一个只做 hello + 单图识别的最小包验证，再补功能 |
| 4 | 大文件 | 300 页 PDF 渲染 + 识别可能吃掉几百 MB 内存 | 强制单页流式（渲染→识别→落库→释放）；>200 MB 直接拒收并说明 |
| 5 | 中文路径 | Windows 中文文件名在某些库上乱码 | 存储一律用 id 命名，原名只进数据库；读写走 `Path` 不拼字符串 |
| 6 | 磁盘增长 | 原件永久保留，课程资料动辄几个 G；页图另占一份 | 页图统一 JPEG q85 存；设置页显示"原件 + 页图占用 X GB"；提供"只留文字、删原件与页图"的单条开关 |
| 7 | 试卷答案识别错 | 用户按错的答案复习，伤害大于"导不进来" | 复核页**答案字段高亮为必检项**；答案缺失时明确标"未识别到答案"而不是猜 |
| 8 | 识别慢，被当成卡住 | 30 页首次约 40–85 秒，用户不知道在干什么 | 按页上报进度（12/30）；可关页面、后台继续；完成发一条站内提示 |
| 9 | **认错但读起来通顺** | 比"认不出"更危险——用户不会去核对 | 文字与页图永远并排；置信度 <0.85 标黄；试卷答案人工确认；不做"自动纠错后隐藏原文" |
| 10 | 双栏/表格串行 | 讲义类 PDF 常见，行序错会把整段理解带偏 | 行框聚类判列写进 T9.6 验收；抽 5 页人工比对，不接受"看起来对齐" |
