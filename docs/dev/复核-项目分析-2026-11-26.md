## 2. 五处修正的细节

### 2.1 提示词不是「没有集中存放」，而是「集中了，但缺 schema 与回归」

`backend/app/prompts/` 下有 9 份模板（ask / organize / organize_exam / organize_image / quiz / grader / exam_parse / exam_audit / exam_proof），共 305 行；`services/prompts.py`（1.2 KB）只负责单趟 `{{占位符}}` 替换。`agents/organizer.py` 里剩下的是 `KINDS` 路由表、重试提示语与容错归一化——这些**本来就该在代码里**，不是「散落的提示词」。

所以 P1-6 的前半句（建目录）已经完成，后半句（每份提示词配输入/输出契约、成功与失败样例、organizer 的 JSON schema 校验）仍然成立。这条建议应当改写成：**`app/prompts/` 已集中，缺的是 schema 校验与离线样例**。原文把它写成「没有集中存放」，会让人去做一件已经做完的事。

### 2.2 红线只有 4 条带解除条件

§2.1 的表格只列了第 3（多 Agent 框架）、4（ORM）、5（UI 库）、6（向量库）四条，标题也写着「第 3–6 条的真实理由与解除条件」。第 1、2、7、8、9 条没有代价说明。这仍然是同类项目里很少见的做法，但「每条都写了」是把它夸到了不成立。

### 2.3 两处行数没有可复现口径

后端：原文 12,619，实测 15,357（含空行）/ 12,049（非空非注释）。前端：原文 18,877，恰好等于「`.vue`+`.js` 非空非注释」。同一份文档里两个数字用了不同口径，且都没写出来——这本身就是它批评的「同一事实多个值」的同类问题。

### 2.4 目录地图那三个数字里错了一个

`app/routers` 18 ✓、`app/services` 30+ ✓、`components/` 4 ✗（16 个 `.vue` + `filters/ingest/list/raw/settings` 五个子目录）。未来的 `AGENTS.md` 写目录地图时，这个数字得重数。

### 2.5 ruff 只是「跑过一次」

`backend/.ruff_cache` 存在说明有人跑过，但 ruff 不在 `pyproject.toml` 的依赖里、不在 venv 里、也没有任何配置段。它现在**不能作为闸门**，只能算历史痕迹。原文把它列进「做对的部分」，实际上它和 `doc_check.py` 不是一个级别。

## 4. 「试卷无法重做」的实测与根因

### 4.1 先说结论

**这不是数据丢失，是两条不同的路径各有问题：**

1. **导入的试卷（`kind='exam'`）没丢，入口也还在**；坏的是结果页那颗「再做一遍」按钮——它把你扔回空舞台，而不是重新开卷。这一步看起来就像「卷子没了」。
2. **由材料生成的题组（`origin='ai'`）确实没有任何重做入口**。它们只以散题形式存在库里，界面上只剩错题本（只含答错的）和复习队列（只含到期/待复习的）。这就是「只保留了错题」的直接原因。

### 4.2 证据

真实库 `%APPDATA%/Cairn/data.db`（只读打开，后复制成副本用于实测）：

```
item id=8  title=二级Java模拟试卷考点梳理  kind=exam  status=ready
question   item_id=8  origin=imported  25 条，number 1–25 齐全
quiz_attempt 该卷 0 条 → 用户从未在库里留下这卷的作答
其他为 origin='ai' 的生成题：item 14 有 10 题、item 1/2 各 5 题，均无列表入口
```

在副本上起后端（`--data-dir` 指副本，原库不动）后：

| 步骤 | 结果 |
|---|---|
| `GET /api/quiz/paper/{item_id}` → 8 | 返回 25 题，`number` 1–25 |
| 练习页选中「二级Java…」，左侧按钮 | 「按卷练：二级Java模拟试卷考点梳理」，可点 |
| 点击后 | 「第 1 / 25 题」，正常作答 |
| 完整答完 25 题交卷 | 结果页 5/25、错 20 题，正常 |
| 点结果页 **「再做一遍」** | **舞台退回空态：「还没开始 / 左侧已选好试卷，点『按卷练』开始」** |
| 再回练习页点「按卷练」 | 仍然 25 题、从第 1 题开始（数据无损） |

### 4.3 根因

`frontend/src/views/Practice.vue`：

```js
function onRestart() {
  backToIdle()          // 清空题组、phase 回 idle → 舞台变空态
}
```

而 `QuizRunner` 在按卷练时把按钮文案设成「再做一遍」（`:restart-label="paperRun ? '再做一遍' : '回配置再出一组'"`），点下去只是 `emit('restart')`，父组件并没有重新取题。**按钮承诺「再做一遍」，实际执行的是「回到配置」。**

生成题组那条更彻底：`quiz/generate` 把题写进 `question` 表就结束了，没有「题组」这个实体，也没有列「某条内容下所有题」的接口。所以交卷那一刻，这一组的入口就消失了，只有答错的题会留在错题本里。

### 4.4 改法

**A（推荐，3 行，只动前端）**——让「再做一遍」真的重开：

```js
async function onRestart() {
  backToIdle()
  // 试卷的「再做一遍」要真的重新开卷：题在库里，不必让用户回左侧再点一次。
  // 生成的题组仍然回配置（题是现出的，得重选题型/难度）。
  if (paperRun.value) await startPaper()
}
```

`startPaper()` 自己会判断 `phase === 'idle'`（`backToIdle` 刚给）、重新取题并 `runKey++` 重挂作答器；`paperRun` 不会被 `backToIdle` 清掉，所以分支可靠。改完跑 `verify_m10`（按卷练）与 `verify_m11`，再用 `tmp/exam-check/walk_redo.py` 复走一遍。

**B（诚实但不解决）**——把试卷的按钮文案改成「回配置」。只消除误导，用户还得自己再点一次。不推荐单做。

**C（真需求，先记 backlog）**——让生成题组可重做：需要「题组」概念（一张记录表 + 一个列表接口 + 一个入口），属于新功能。按红线 9「新需求先记入 backlog，不进当前里程碑」，现在不该顺手做。
