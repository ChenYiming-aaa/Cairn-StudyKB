## 一、真实缺陷（已修）

### S-1 `theme-boot.js` 在打包版里 404，首屏防白闪形同虚设（**M6 回归，本轮已修**）

**现象**：浏览器实测时 console 每次都刷
`GET /theme-boot.js 404`。控制台错误计数不为 0，一开始被当成「本轮改动引入」。

**根因**：T6.7 新增了 `frontend/public/theme-boot.js`，`index.html` 在挂载前同步引用它；
但 `backend/app/main.py` 的静态根文件白名单是 M5 时代写的四个名字
（`favicon.ico` / `logo.svg` / `apple-touch-icon.png` / `robots.txt`），**没有 `theme-boot.js`**。
dev 下由 Vite 直接吐 `public/`，所以看不出来；只有「后端吐 dist」这条路径（桌面版、安装包）才暴露。

**影响**：打包版首屏防白闪脚本根本没生效（深色用户会先看到一眼白底），并非只是多一条 404。

**处理**：白名单加一项（`backend/app/main.py`，`for _name in (...)` 那行）。
实测 `GET /theme-boot.js` → **200**，本轮浏览器检查从 19/20 变 24/24、console 零错误。

> 这条也说明 `verify_m6` 漏了一个方向：它断言了 `index.html` 引了脚本、断言了脚本内容，
> 但**没断言这个 URL 真能取到**。以后新增根目录静态文件，记得同时看一眼白名单。

## 二、容易误判的环境行为（不是 bug，但值得写进文档）

### S-2 相对 `--data-dir` 是按**项目根**解析的，不是按当前目录

`config.py:183-186`：相对路径以 `DATA_ROOT.parent` 为基准（源码下 = 项目根）。所以

```bash
cd backend && uv run python -m app --data-dir ../data/tmp/m7ui
```

实际落在 **`<项目根>/../data/tmp/m7ui`**（即 `C:\Users\<你>\Desktop\data\tmp\m7ui`），
而不是 `<项目根>/data/tmp/m7ui`。本轮就踩了一次：后端在一个**空库**上启动，
`/api/knowledge/categories` 返回 0 条，差点被误判成「接口坏了」。

**建议**：验收脚本与临时实例一律传**绝对路径**；`docs/dev/运行与打包.md` 补一句
「相对 `--data-dir` 相对的是项目根，不是 cwd」。

**副作用**：本轮在 `C:\Users\<你>\Desktop\data\tmp\m7ui`（项目根之外）留下一个空库与 `logs/`，
可手工删。

## 四、可优化但本轮不做（建议排进 T7.2–T7.7 或之后）

### S-8 `Ctrl+Shift+B` 能收列表，但**没有可见的恢复入口**（**已在 T7.2 修掉**）

`useLayout` 已经能收/展 `list`，`App.vue` 也绑了快捷键。问题是条目列表栏**还没接 `SidePanel`**（T7.2），
所以列宽变 0 时原本会留 1px 边框 + 一个被压扁的搜索框（实测 `scrollWidth 113`，很难看）。

本轮加了一条**过渡规则**（`styles/app.css`）：

```css
html[data-list="off"] .workspace > .list-panel { display: none; }
```

现在按键能干净地收起（`232px 0px 1208px`）与恢复，但：
- 顶栏还没有「列表」按钮（`RailToggle target="list"` 已就绪，T7.2 放到顶栏）
- 那条 CSS 是临时桥，T7.2 把 `ItemList` 包进 `SidePanel` 后**应当删掉**

**T7.2 已处理**：`ItemList` 换成 `SidePanel target="list"`，顶栏加了 `RailToggle target="list"`
（只在知识库页出现），那条过渡样式已删除。收起后 `.side-panel.is-collapsed` 自己 `overflow:hidden`
+ 去掉右边框，搜索框不再被压扁（实测宽 38，是 0 宽容器里被裁掉后的残留 padding）。

### S-9 `< 1000px` 的「列表浮层化」没做（**已在 T7.2 做掉**）

M7 §3.3 第三档要求「左栏收 rail + 条目列表浮层化（点条目后覆盖详情）」。
本轮只做了前两档（`≥1200` 三栏、`1000–1200` 自动收 rail，实测 1100 宽生效）。
浮层化要改 `ItemList` 的定位与选中交互，属于 T7.2。

**T7.2 已处理**：`@media (max-width: 999px)` 里 `.workspace` 变两列 + `.list-panel` 绝对定位
（`left: var(--w-sidebar)`，宽度仍读 `--w-list`，所以拖拽与记忆照旧）；`Knowledge.vue` 在
`window.innerWidth < 1000` 时选中条目后自动 `collapse('list')`。

### S-10 状态计数是全库口径，叠加分类后数字不变

左栏「待整理 9」永远是全库 9，即使当前选了「学习方法」。
**好处**：数字稳定、不会随筛选跳动；**代价**：容易被读成「该分类下还有 9 条」。
要变成分类口径，得让 `GET /api/knowledge/categories` 额外返回每个分类的分状态计数（契约变更）。
本轮保持全库口径，先记录。

### S-11 分类全展开会把「常用标签」挤出首屏

实测 13 个分类、展开一个分类的 6 个标签后，标签云已经在首屏之外（要滚动）。
可选做法：① 分类区限高 + 内部滚动；② 标签区挪到分类上面（与 M7 §2 的 ASCII 稿相反）；
③ 维持现状（用户主动展开才发生）。本轮选 ③，等你看过实际界面再定。

### S-12 两个搜索框语义不同，容易混

左栏是「筛选分类或标签」（只过滤树），列表顶部是「搜索标题」（真检索）。
两个输入框长得一样。建议 T7.5 写文案规范时把 placeholder 与 aria-label 明确区分
（左栏「筛选分类或标签」/ 列表「搜索条目标题」），必要时给左栏加个小图标。

### S-13 拖拽手柄命中区 8px，触屏与高分屏偏窄

`SplitHandle` 宽 8px（视觉只有 2px 的抓握线）。鼠标没问题，触屏与 4K 缩放下会难点。
可选：命中区加到 12px（视觉不变），或加 `@media (pointer: coarse)` 单独放宽。

### S-14 `tokens.css` 是生成物，但布局变量也住在里面

本轮新增 `--w-rail: 44px` 时，必须改 `tools/check_contrast.py` 的 `ROOT_BLOCK` 再 `--write`；
**直接改 `tokens.css` 会在下一次生成时被覆盖**。文件头只写了「配色是生成物」，
没说版面尺寸也是。建议文件头补一句，或把布局变量拆到 `layout.css`。

### S-15 徽标 / 计数小字的对比度问题仍在（承接 M6 S-20 第 2 条）

左栏的计数（`--c-text-3`，12px）与浅色主题的 success/warning 徽标仍低于 AA 小字 4.5:1。
本轮没动配色（不在 T7.0/T7.1 范围），等 M7 视觉统一那一轮一起处理。

## 六、第二部分（T7.2–T7.4）发现的问题

### S-16 展开态的 `SidePanel` **没有收起按钮**（设计缺口，已补）

`SidePanel` 的 `RailToggle` 放在 `#rail` 插槽里，而 `#rail` 只在**收起后**才 `v-show`。
左栏与列表栏靠顶栏按钮躲过这个问题，但学习页选择器、练习配置栏不在顶栏，
展开状态下就只剩「记得按 Ctrl+B」这条路（而且 Ctrl+B 也不管它们）。

**处理**：两个面板的正文顶部各加一条 `.panel-bar`（名字 + `RailToggle`），
样式放 `app.css`（`.panel-bar` / `.panel-name`）而不是各写一份。
以后再有 `SidePanel` 挂在页面内部，记得同样给一个展开态的收起入口。

### S-17 `rail` 属性漏写不会报错，只会让正文在 44px 里挤成竖排字（已修）

`SidePanel` 的 `rail` 默认 `false`；漏写时宽度照样变成 44px，但**显示的是正文**而不是窄条，
中文会一个词一行地竖着排（实测截图里「条目选择」「已选 0 篇」全竖起来了），而自动化脚本
（`locator.count()`）照样能数到 `#rail` 里的元素，看起来像「通过」。

**处理**：两个页面补上 `rail`；测试改成断言 `.picker-body` / `.config-body` **不可见**
和 `.rail-label` **可见**，而不是数个数。

### S-18 「一大坨文字 + 可点」的容器会污染可访问名（已修）

`TodayBar` 是一个 `<button>`，内容拼起来是「今日 待整理 9 待复习 0 连续 1 天 专注 0 秒 详情 →」。
没有任何 `aria-label` 时这就是它的可访问名，于是：

- 读屏用户听到一长串数字，分不清这是导航还是状态
- 按名字找按钮的脚本 `get_by_role("button", name="待整理")` **先匹配到它**，
  一点就把页面带去 `/dashboard`；本轮 `check.py` 就是这样挂掉的（`.list-meta` 30 秒找不到）

**处理**：`aria-label="今日概览，打开完整仪表盘"`（短名，不含状态词）。
T7.5 改文案时，凡是「整块可点 + 里面有很多词」的容器都要显式给短 `aria-label`。

### S-19 `panels` 的语义是「折叠」，默认值写反过一次（已修）

`state.panels` 存的是「是否折叠」，但初值写成了 `{ chat: false }` —— 等于默认展开。
问答历史抽屉因此**每次进检索页都自动弹开**，还会盖住「历史」按钮自己。
`localStorage` 里没存过的用户全中招。

**处理**：改成 `{ chat: true }`，并在常量旁注明「浮层默认是关的」。

### S-20 `--space-5` 这个令牌**不存在**（遗留，未动）

`tokens.css` 只有 `--space-1/2/3/4/6/8`。`Ask.vue` 里两处 `var(--space-5)`
（`.stats` 的 `margin`、`.skeletons` 的 `margin-top`）全部**静默失效**成 0 ——
CSS 变量没定义时整条声明被丢弃，不报错、不警告。

本轮新写的 `TodayBar` 一开始也用了它，表现是「今日条所有格子挤在一起、左内边距为 0」，
靠量 `gap` 的计算值（返回 `normal` 而不是 `24px`）才定位到。

**建议**：① 这两处改成 `--space-4` 或 `--space-6`（会动到检索页的间距，没在本轮改）；
② 长期看应该在 `check_contrast.py` 里加一条「`var(--x)` 必须已定义」的静态检查——
`npm run lint` 不查 CSS，这类错只有肉眼或量计算值才能发现。
