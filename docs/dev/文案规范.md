> **作用域**：全站**可见文案**（按钮、标题、空态、提示、错误、Toast、aria-label、placeholder）。
> 不覆盖：代码注释、日志、API 错误码、数据库字段名、开发文档。
> **冲突时**：与 `00-总纲.md` §2 红线冲突以红线为准；与 `milestones/M7-布局与文案.md` 冲突以本文为准

> 建立于 2026-11-09（M7 第三部分）。改文案前读一遍，改完按 §9 自查。
>
> **2026-11-11 修订**：术语「条目」→「内容」（§2）、状态词「就绪」→「已整理」（§2.2）、
> 两个搜索框的 placeholder 同步收短（§2.1）。`verify_m7.py` 的定位与禁止词已同步，
> 全站界面文案里不再有「条目」（代码注释不受限）。

## 1. 语气四条

| # | 规则 | 落地写法 |
|---|---|---|
| 1 | **第二人称，说人话** | 「你还没采集任何内容」而不是「暂无数据」；「这条已经在库里了」而不是「内容已存在」 |
| 2 | **动词开头，句子短** | 按钮用「采集内容 / 开始整理 / 重新生成 / 开始复习」；不用「确定 / 提交 / 执行 / 应用」 |
| 3 | **不卖萌、不夸张、不用感叹号、不用「哦」「啦」「呢」** | 不用「～」「!!」「太棒了」「一键搞定」 |
| 4 | **出错先说影响，再说怎么办** | 「这条没能整理：模型额度用完了。充值后再点一次整理。」 |

补充三条（实操最容易违反的）：

- **数字后面给出处**：「全库还有 9 条待整理」比光写「9」有用；拿不到数字就留 `—`，不要写 0 充数
- **不承诺做不到的事**：「随时可以回到这里」要确认入口真的在那里（旧文案指过并不存在的「环境」按钮）
- **一句话只做一件事**：提示里同时说「已保存」「已生效」「下一步」时，拆成一句主句 + 一句补充

## 2. 术语表（同一个东西只有一个名字）

| 用 | 不用 | 备注 |
|---|---|---|
| 内容 | 条目、资料、内容项、卡片、记录 | 一条入库的东西 = 一条内容；计数说「N 条内容」 |
| 整理 | 结构化、解析、处理、生成摘要 | 「整理」含分类/摘要/要点/笔记四件事 |
| 学习页 | 页面、文档、笔记页、HTML | 「学习」是导航项，「学习页」是产物 |
| 练习 / 复习 | 测试、刷题、背题、做题 | 「作答」指具体答一道题 |
| 待整理 / 整理中 / 就绪 / 失败 | pending、ready、处理中、failed | 条目状态，四选一 |
| 模型 | AI、大模型、LLM | 「模型 Key」「模型服务」 |
| 思考强度 | 推理强度、reasoning、effort | 设置里的四档：关 / 低 / 中 / 高 |
| 采集 | 抓取、导入、添加 | 「采集内容」是入口动词；「抓取正文」是阶段名 |
| 存进知识库 | 入库、落库、写库 | 采集完成的确认语；「已存进知识库」 |
| 工作区 | 文件夹、目录、空间 | 用户自建的一层归类；**不嵌套**（ADR-032） |
| 原件 | 附件、源文件 | 落盘的原始文件；「原文」仍指排好版的文字，两者不混用 |
| 识别 / 已识别 12/30 页 | OCR、文字提取 | 界面**不写「OCR」**；进度写「正在识别 12/30 页」 |
| 读取 / 已读取 3 页 | 抽取、解析、文字提取 | Word / PPT / Excel / 文本的读法，与「识别」分开：PDF 与图片一律叫识别（要在图上认字），office 与文本叫读取（直接读结构）。混用会让用户以为 Word 也要装组件 |
| 整理成题目 | 结构化、解析 | 「结构化」是 §6 禁止词，界面一律写「整理成题目」 |
| 按卷练习 | 刷题、背题 | 一次做完整套试卷；「刷题」是 §6 禁止词 |

**术语表管的是「同一个东西别叫两个名」，不是全站禁用这些字**。例如「文档」在
「Markdown 文档」这类确有所指的地方仍可用；但**不能用来指代学习页**。

**v0.3 新增术语（T9.1）**：工作区 / 原件 / 识别 / 整理成题目 / 按卷练习，
同义词黑名单就是上表「不用」列。补三条口径：

1. 「原文」**保留**，指抽取或识别后呈现的文字；不要因为有了「原件」就把「原文页」改名。
2. 界面不出现 `OCR` 字样（写「识别」），也不用「文字提取」「附件」「源文件」
   「文件夹」「目录」「空间」「结构化」「解析」。
3. 上面是**术语约定**，不是 §6 的 `FORBIDDEN` 清单；`verify_m7.py` 按 §6 逐页扫，
   改 §6 必须同步改脚本里的 `FORBIDDEN` 与按文案定位的断言，否则会互相打架。
4. **两个例外（2026-11-13，T10.6 文件夹批量导入）**：
   - **「文件夹」只许指磁盘上真实的那一层**（批量导入时选的那个，按钮「选文件夹」、
     提示「只扫这一层，子文件夹不跟进来」）；**应用里自己那层归类仍然只叫「工作区」**。
     换句话说禁的是拿「文件夹/目录」指代工作区，不是禁用这个物理概念。
   - **「导入」只用于把本地文件整份放进知识库**（试卷导入、文件夹导入）；从网址取正文
     仍然叫「采集」。`verify_m7` 按 `FORBIDDEN` 扫，词表里两个词都没进，改词表时要连这条一起看。
5. **答案的「解析」写「讲解」**（2026-11-13，T10.3 复核页）：题目讲解那一栏是「讲解与分值」，
   `<summary>` 与 placeholder 都不写「解析」—— 它与「整理」的同义词撞车，让人以为要再跑一次整理。
6. 界面不留「正在解析…」这类**过程词**：试卷导入的首屏就是复核界面（需求 §9），
   处理中的按钮写「正在导入…」。
7. **题目初审的词**（2026-11-13，T10.9）：按钮写「**检查题目**」、进行中写「正在检查…」，
   汇总句写「看了 25 题，3 题有疑问」；模型给的题干建议叫「**改法**」，采纳是「**用这条**」，
   退回去是「**撤回**」。不写「审核」「校验」「AI 审查」—— 前两个不在用户词表里，
   第三个是系统视角。「题干 / 选项 / 答案」是这行的通用词，不受限。
8. **PDF 原样呈现的词**（2026-11-13，T11.1）：说「**画出来 / 还在画 / 画不出来**」，
   不说「渲染」「加载 PDF 引擎」「canvas」；「**页图**」指那一页的图像（识别时就落盘的那张），
   与「原文」（文字）分开。取不到原件时的提示要给出路：「这份 PDF 没能按原样画出来，
   页图和文字照样能看」—— 只说失败不说还能用什么，等于让人以为坏了。

### 2.1 两个搜索框必须能区分（M7 补充记录 S-12）

| 位置 | placeholder | aria-label | 语义 |
|---|---|---|---|
| 知识库左栏顶部 | `筛选分类或标签` | `筛选分类或标签` | 只过滤树，不发检索请求 |
| 内容列表顶部 | `搜索标题` | `搜索标题` | 真检索（标题/摘要） |
| 练习配置栏 | `搜标题…` | `搜索标题` | 同内容列表 |
| 学习页选择器 | `搜标题…` | `搜索标题` | 同上 |

placeholder 允许带省略号，aria-label **不省略**、不带标点。

### 2.2 状态词对齐（后端枚举 → 界面）

| 后端 | 界面 | 用在哪 |
|---|---|---|
| `pending` | 待整理 | 状态徽标、左栏快筛、今日条 |
| `organizing` | 整理中 | 同上 |
| `ready` | 已整理 | 徽标、练习页「需要先整理成 ready」改为「需要先整理」 |
| `failed` | 失败 | 徽标 |

「待整理 / 整理中 / 已整理 / 失败」是同一条时间轴上的四个位置，读出来就知道前后关系；
「就绪」自解释性差，2026-11-11 弃用。

任务状态（`agent_task`）是另一套，别和内容状态混用：
`queued` 排队中 / `running` 进行中 / `done` 完成 / `failed` 失败。

## 3. 空状态三段式

`是什么（一句）` + `为什么空（一句）` + `一个动作（按钮）`。

```
这里放你的学习页。还没有生成过。 [选几条内容开始生成]
```

细则：

1. 第一句说**这里是什么**（不是「暂无数据」）
2. 第二句说**为什么空**；分不清是「真没有」还是「筛没了」时要分开写：
   - 真没有：「还没有采集过内容。」
   - 筛没了：「换个关键词，或点左栏「全部内容」。」
3. 第三句是**一个**动作，动词开头。没有可执行动作时宁可不给按钮，也不给假按钮
4. 空态里可以给「回头路」（如最近 3 条），但那是补充，不是第三段

## 4. 错误两层

| 层 | 内容 | 位置 |
|---|---|---|
| 一层（给人） | 一句人话：先说影响，再说怎么办 | 卡片正文、Toast |
| 二层（给报障） | 错误码 + 后端 `detail` 原文 | 折叠区、「任务」页、控制台 |

- 一层文案由 `api/client.js` 的 `FRIENDLY` 表统一给（按错误码前缀匹配），**组件不要自己编**
- 错误码本身不动（前端分支依赖它），只改映射出来的人话
- 批量操作失败时，一层文案要带**数量**：「3 条没能整理」比「整理失败」有用
- 不许出现「未知错误」这种把人挡在门外的句子；实在没有信息就写「这次没成功，再试一次；还不行去任务中心看详情」

## 6. 禁止词清单（`verify_m7.py` 逐页扫描，命中即 FAIL）

按 `innerText` 逐页扫，以下**字符串**不许出现：

```
暂无数据   内容项   资料库   刷题     背题
结构化     处理中   AI 生成  大模型   LLM
pending    ready    推理强度  reasoning
条目       就绪
入库       后端
```

说明：

- `条目` / `就绪` 2026-11-11 起禁用：前者统一叫「内容」，后者统一叫「已整理」。
  注释、日志、API 字段名不受限，扫描只看界面 `innerText`。
- `AI` 只禁「AI 生成 / AI 整理」这类指代模型的写法；「AI 测试」这类**分类名**是用户内容，不在扫描范围
  （扫描只看界面固定文案，不扫左侧分类树里的用户数据）
- `处理中` 禁的是把后端枚举直接露出来；「正在处理」也不建议，统一用「整理中 / 进行中」
- `页面` / `文档` **不在**禁用清单（正常中文要用），只是不能拿来当学习页的名字

## 7. 标点与数字

| 项 | 规则 | 例 |
|---|---|---|
| 句末 | 提示、空态、按钮不加句号；成段说明加句号 | `开始整理` / `还没有采集过内容。` |
| 括号 | 中文文案用全角括号；技术值（端口、路径、命令）用半角 | `（可留空）` / `(8756 端口)` |
| 顿号 | 并列三项以上用「、」，最后一项不加「和」 | `分类、摘要、要点、笔记` |
| 数字 | 数量用阿拉伯数字；「一」只在固定词里 | `12 条排队中` / `一句话` |
| 时间 | 用 `humanDuration` / `shortTime`，不在模板里手拼 | `1 小时 25 分` |
| 省略号 | 进行中用 `…`（一个字符），不用 `...` | `整理中…` |
| 乘号/箭头 | 比数用 `→`，范围用 `–`（en dash） | `888 → 1208` / `30–60 秒` |

## 8. 可访问名（aria-label）

**整块可点、内部又有很多词的容器，必须显式给短 `aria-label`**（M7 补充记录 S-18）。

- 好：`aria-label="今日概览，打开完整仪表盘"`、`aria-label="收起列表"`
- 坏：把「今日 待整理 9 待复习 0 连续 1 天」拼成可访问名 —— 读屏用户听到一串数字，
  按名字找按钮的脚本也会先撞上它
- aria-label 里**不要**带状态数字；数字放在可见文本里
- 按钮的 aria-label 与可见文字尽量一致；不一致时以「动作 + 对象」为准（`收起出题配置`）

## 9. 改完怎么自查

```bash
cd frontend
npm run lint           # 不查文案，但能挡住语法错误
grep -rn "暂无数据\|结构化\|已派发\|内容已存在\|AI 生成\|大模型\|推理强度\|就绪" src/
# 「条目」只应出现在注释里，出现在模板/字符串里就是漏改
grep -rn "条目" src/ --include=*.vue --include=*.js | grep -v "^\S*: *[/*]"
grep -rn "pending\|ready\|processing" src/ --include=*.vue   # 只应出现在枚举判断里
```

最后跑 `backend/scripts/verify_m7.py`，它会把六条验收连同逐页禁止词一起过一遍。
