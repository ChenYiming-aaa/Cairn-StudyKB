# Cairn 文案规范

> **作用域**：全站**可见文案**（按钮、标题、空态、提示、错误、Toast、aria-label、placeholder）。
> 不覆盖：代码注释、日志、API 错误码、数据库字段名、开发文档。
> **冲突时**：与 `00-总纲.md` §2 红线冲突以红线为准；与 `milestones/M7-布局与文案.md` 冲突以本文为准

## 1. 语气四条

| # | 规则 | 落地写法 |
|---|---|---|
| 1 | **第二人称，说人话** | 「你还没采集任何内容」而不是「暂无数据」；「这条已经在库里了」而不是「内容已存在」 |
| 2 | **动词开头，句子短** | 按钮用「采集内容 / 开始整理 / 重新生成 / 开始复习」；不用「确定 / 提交 / 执行 / 应用」 |
| 3 | **不卖萌、不夸张、不用感叹号、不用「哦」「啦」「呢」** | 不用「～」「!!」「太棒了」「一键搞定」 |
| 4 | **出错先说影响，再说怎么办** | 「这条没能整理：模型额度用完了。充值后再点一次整理。」 |

补充三条（实操最容易违反的）：

- **数字后面给出处**：「全库还有 9 条待整理」比光写「9」有用；拿不到数字就留 `—`，不要写 0 充数
- **不承诺做不到的事**：「随时可以回到这里」要确认入口真的在那里（旧文案指过并不存在的「环境」按钮）
- **一句话只做一件事**：提示里同时说「已保存」「已生效」「下一步」时，拆成一句主句 + 一句补充

## 2. 术语表（同一个东西只有一个名字）

| 用 | 不用 | 备注 |
|---|---|---|
| 条目 | 资料、内容项、卡片、记录 | 一条入库内容 = 一个条目 |
| 整理 | 结构化、解析、处理、生成摘要 | 「整理」含分类/摘要/要点/笔记四件事 |
| 学习页 | 页面、文档、笔记页、HTML | 「学习」是导航项，「学习页」是产物 |
| 练习 / 复习 | 测试、刷题、背题、做题 | 「作答」指具体答一道题 |
| 待整理 / 整理中 / 就绪 / 失败 | pending、ready、处理中、failed | 条目状态，四选一 |
| 模型 | AI、大模型、LLM | 「模型 Key」「模型服务」 |
| 思考强度 | 推理强度、reasoning、effort | 设置里的四档：关 / 低 / 中 / 高 |
| 采集 | 抓取、导入、添加 | 「采集内容」是入口动词；「抓取正文」是阶段名 |

**术语表管的是「同一个东西别叫两个名」，不是全站禁用这些字**。例如「文档」在
「Markdown 文档」这类确有所指的地方仍可用；但**不能用来指代学习页**。

### 2.1 两个搜索框必须能区分（M7 补充记录 S-12）

| 位置 | placeholder | aria-label | 语义 |
|---|---|---|---|
| 知识库左栏顶部 | `筛选分类或标签` | `筛选分类或标签` | 只过滤树，不发检索请求 |
| 条目列表顶部 | `搜索条目标题` | `搜索条目标题` | 真检索（标题/摘要） |
| 练习配置栏 | `搜条目标题…` | `搜索条目标题` | 同条目列表 |
| 学习页选择器 | `搜条目标题…` | `搜索条目标题` | 同上 |

placeholder 允许带省略号，aria-label **不省略**、不带标点。

### 2.2 状态词对齐（后端枚举 → 界面）

| 后端 | 界面 | 用在哪 |
|---|---|---|
| `pending` | 待整理 | 状态徽标、左栏快筛、今日条 |
| `organizing` | 整理中 | 同上 |
| `ready` | 就绪 | 徽标、练习页「需要先整理成 ready」改为「需要先整理」 |
| `failed` | 失败 | 徽标 |

任务状态（`agent_task`）是另一套，别和条目状态混用：
`queued` 排队中 / `running` 进行中 / `done` 完成 / `failed` 失败。

## 3. 空状态三段式

`是什么（一句）` + `为什么空（一句）` + `一个动作（按钮）`。

```
这里放你的学习页。还没有生成过。 [选几条内容开始生成]
```

细则：

1. 第一句说**这里是什么**（不是「暂无数据」）
2. 第二句说**为什么空**；分不清是「真没有」还是「筛没了」时要分开写：
   - 真没有：「还没有采集过内容。」
   - 筛没了：「换个关键词，或点左栏「全部条目」。」
3. 第三句是**一个**动作，动词开头。没有可执行动作时宁可不给按钮，也不给假按钮
4. 空态里可以给「回头路」（如最近 3 条），但那是补充，不是第三段

## 4. 错误两层

| 层 | 内容 | 位置 |
|---|---|---|
| 一层（给人） | 一句人话：先说影响，再说怎么办 | 卡片正文、Toast |
| 二层（给报障） | 错误码 + 后端 `detail` 原文 | 折叠区、「任务」页、控制台 |

- 一层文案由 `api/client.js` 的 `FRIENDLY` 表统一给（按错误码前缀匹配），**组件不要自己编**
- 错误码本身不动（前端分支依赖它），只改映射出来的人话
- 批量操作失败时，一层文案要带**数量**：「3 条没能整理」比「整理失败」有用
- 不许出现「未知错误」这种把人挡在门外的句子；实在没有信息就写「这次没成功，再试一次；还不行去任务中心看详情」

## 5. 反例 → 改法（都真实存在过）

| 原文案 | 问题 | 改成 |
|---|---|---|
| 可以随时从顶栏的「环境」回到这里 | 顶栏没有叫「环境」的按钮（M6 后是齿轮） | 随时点顶栏的齿轮回到这里 |
| 内容已存在，已定位到「xxx」 | 「内容已存在」像报错；没说是谁帮你定位 | 这条已经在库里了，已帮你定位到「xxx」 |
| 已派发 12 个整理任务 | 「派发」是系统视角，用户看不到谁在派 | 开始整理了，12 条排队中 |
| 暂无数据 | 说了等于没说 | 这里放你的条目。还没有采集过内容。 |
| 标题（可留空，整理后由 AI 生成） | 「AI」不是本项目的术语 | 标题（可留空，整理后由模型生成） |
| 还没有可出题的条目（需要先整理成 ready） | 把枚举值露给用户 | 还没有能出题的条目，先把它们整理完 |
| 这条被站点拦下了，多半要登录 | 只说现象，没说怎么办 | 这条被站点拦下了，多半要登录。登录后再点一次采集。 |
| 结构化笔记有未保存的修改，切换条目会丢失，继续？ | 「结构化」不是术语 | 笔记有没保存的修改，切换会丢失。继续？ |

## 6. 禁止词清单（`verify_m7.py` 逐页扫描，命中即 FAIL）

按 `innerText` 逐页扫，以下**字符串**不许出现：

```
暂无数据   内容项   资料库   刷题     背题
结构化     处理中   AI 生成  大模型   LLM
pending    ready    推理强度  reasoning
```

说明：

- `AI` 只禁「AI 生成 / AI 整理」这类指代模型的写法；「AI 测试」这类**分类名**是用户内容，不在扫描范围
  （扫描只看界面固定文案，不扫左侧分类树里的用户数据）
- `处理中` 禁的是把后端枚举直接露出来；「正在处理」也不建议，统一用「整理中 / 进行中」
- `页面` / `文档` **不在**禁用清单（正常中文要用），只是不能拿来当学习页的名字

## 7. 标点与数字

| 项 | 规则 | 例 |
|---|---|---|
| 句末 | 提示、空态、按钮不加句号；成段说明加句号 | `开始整理` / `还没有采集过内容。` |
| 括号 | 中文文案用全角括号；技术值（端口、路径、命令）用半角 | `（可留空）` / `(8756 端口)` |
| 顿号 | 并列三项以上用「、」，最后一项不加「和」 | `分类、摘要、要点、笔记` |
| 数字 | 数量用阿拉伯数字；「一」只在固定词里 | `12 条排队中` / `一句话` |
| 时间 | 用 `humanDuration` / `shortTime`，不在模板里手拼 | `1 小时 25 分` |
| 省略号 | 进行中用 `…`（一个字符），不用 `...` | `整理中…` |
| 乘号/箭头 | 比数用 `→`，范围用 `–`（en dash） | `888 → 1208` / `30–60 秒` |

## 8. 可访问名（aria-label）

**整块可点、内部又有很多词的容器，必须显式给短 `aria-label`**（M7 补充记录 S-18）。

- 好：`aria-label="今日概览，打开完整仪表盘"`、`aria-label="收起列表"`
- 坏：把「今日 待整理 9 待复习 0 连续 1 天」拼成可访问名 —— 读屏用户听到一串数字，
  按名字找按钮的脚本也会先撞上它
- aria-label 里**不要**带状态数字；数字放在可见文本里
- 按钮的 aria-label 与可见文字尽量一致；不一致时以「动作 + 对象」为准（`收起出题配置`）

cd frontend
