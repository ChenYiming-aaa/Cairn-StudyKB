# v0.3.1 · 修补丁：体积数字终于对得上了

> **作用域**：v0.3.1 的 GitHub Release 正文。
> **读者**：所有用户（补丁版，会推给已装 v0.3.0 的人）。
> **发布时**：把这段「作用域 / 读者」删掉再贴 —— 它是写给维护者看的。

v0.3.0 里同一个安装包会显示两个大小：「检查更新」说 **174 MB**，Release 页和 README 说 **182 MB**。
这不是笔误 —— 程序里前后有五处各算了一遍体积，两处按 1024 进位、三处按 1000 进位。
本版把这些收成一处，统一按 **1 MB = 1000 × 1000 字节**（「MB」的定义，也是文档一直用的口径）。

升级方式：设置 → 关于 → 检查更新，或者手动下 `Cairn-0.3.1-setup.exe`。
**数据目录不动**，随时可以装回 v0.3.0。

## 你会看到的变化

- **「检查更新」里的大小变成 182 MB**，与 Release 页、README 写的数字一致了
- **文件列表里的体积略有变化**（普遍大 5% 左右）：同一个 12.3 MB 的文件，现在写 12.9 MB。
  因为以前那两处按 1024 进位，与文档不是一套算法
- 不到 1 KB 的文件现在写「812 B」，不再一律进成「1 KB」

## 只对维护者有意义的部分

- 五处实现（`utils/format.fileSize`、`useUpdater`、`Setup.vue`、`DownloadsTab.vue`、`HtmlPages.vue`）
  收成一个 `fileSize(bytes, digits)`；`digits=0` 给下载与组件体积（`182 MB`），默认 1 位给文件列表（`12.9 MB`）
- 验收加了两条断言钉住：下载页的数字必须等于「后端给的字节数 ÷ 10⁶」，
  前端源码里不许再出现 `1048576` / `1024 * 1024` 这类第二套算法
- 顺手改正三处过时的验收条数（`运行与打包.md` 里 `verify_m8` 105 → 106、`verify_m7` → 93，补上 m10 / m11 两行）

**没有功能变化**：本地识别、试卷导入、PDF 原样呈现、引用跳转与 v0.3.0 完全一样。
