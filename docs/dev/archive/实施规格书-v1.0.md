# 个人学习知识库 Agent · 实施规格书 v1.0

> 本文档是**执行规格**，不是构想。每一条都应当可直接落地、可被验收。
> 代码由 AI 编写，用户负责试用与验收。因此本文档的写法是"给实现者看的"，不写"给领导看的"。

## 0. 文档定位

| 项 | 说明 |
|---|---|
| 目的 | 把"多源采集 → 整理 → 阅读 → 检索 → 生成 → 练习 → 计时"这条闭环拆成 5 个可独立验收的里程碑 |

## 1. 产品定义

### 1.1 一句话

把文章、网页、视频等多源内容采集进本地知识库，由 LLM 自动分类、摘要、结构化，形成可阅读、可检索、可生成学习页、可出题练习的知识资产，并用番茄钟记录学习时间，最终构成一个能督促自己学完的闭环。

### 1.2 核心闭环

```
采集 → 整理 → 阅读 → 检索/问答 → 生成学习页 → 出题练习 → 错题与复习 → 计时复盘
 ↑                                                                        │
 └────────────────────────── 复盘结果驱动下一轮采集 ←──────────────────────┘
```

### 1.3 目标与非目标

**目标（本期必做）**

1. 三种采集入口：粘贴文本、网页链接、视频链接（自动转录）
2. LLM 自动整理：分类、标签、摘要、关键点、结构化笔记
3. 左侧分类树 + 右侧阅读器，可直接查看全文与整理结果
4. 本地全文检索 + 语义检索，问答必须带来源引用
5. 知识条目 → 单文件 HTML 学习页，可在应用内预览、可下载分享
6. 指定题型/难度/数量实时出题，作答后自动判分
7. 错题本 + 简单间隔复习队列
8. 番茄钟绑定学习对象，记录专注时长
9. 仪表盘汇总学习数据
10. 打包为 Windows 可安装桌面程序 + 可用浏览器访问的本地 Web 版

**非目标（本期明确不做）**

- 多用户、账号、权限、云端同步
- 移动端适配
- 番茄钟的应用锁定 / 网站拦截 / 白名单（桌面端专属能力，后置到 v2）
- 复杂间隔重复算法（SM-2 / FSRS）
- 社交、分享社区、公开站点托管
- 富文本编辑器、图片上传与 OCR
- 全自动 Agent 自主决策（本期是"固定管线的多步调用"，不是自主 Agent）

> **术语校准**：本项目的"子 Agent"是**按内容类型/任务类型路由的固定 LLM 调用管线**（整理 Agent、出题 Agent、批改 Agent、问答 Agent），由后端一个调度器串起来。不引入 LangGraph / CrewAI 这类多 Agent 框架。这点要提前对齐，避免后期预期落差。

## 2. 技术决策

### 2.1 最终选型

| 层 | 选型 | 版本约束 | 理由 |
|---|---|---|---|
| 运行时 | Python | **3.12**（不用 3.13） | 3.13 上 ctranslate2 / sentence-transformers 等二进制依赖的 wheel 覆盖仍不完整，踩坑不值得 |
| 环境管理 | uv | 最新 | 一条命令装 Python 3.12 + 建 venv + 锁依赖，比 pip+venv 干净 |
| 后端 | FastAPI + uvicorn | fastapi>=0.115 | 异步原生，SSE 流式出题必需；类型校验省掉大量手写校验 |
| 数据校验 | Pydantic v2 | 随 FastAPI | 请求/响应模型 + LLM 输出结构校验共用一套 |
| 数据库 | SQLite（标准库 `sqlite3`） | SQLite >= 3.34 | 单文件零运维；**不引 ORM**，手写 SQL + 薄 repository 层，代码透明可读 |
| 全文检索 | SQLite FTS5，`tokenize='trigram'` | — | 内置，中文可搜；短查询走 LIKE 兜底（见 §4.4） |
| 向量检索 | sqlite-vec | 可选 | 与主库同一个 `.db`；不可用时可降级为 numpy 暴力检索 |
| Embedding | `sentence-transformers` + `BAAI/bge-small-zh-v1.5` | — | 512 维，约 100MB，本地离线，3060 上毫秒级 |
| LLM | OpenAI 兼容 HTTP 接口 | — | DeepSeek / 硅基流动 / Ollama 通用；不做厂商 SDK 绑定 |
| 网页抓取 | `trafilatura` + `httpx` | — | 成熟、纯 Python、中文正文效果好；保留 adapter 接口 |
| 视频 | `yt-dlp` + `ffmpeg` + `faster-whisper` | — | 全部 pip/winget 可装，可用 GPU 加速 |
| HTML 生成 | `markdown` + `Jinja2` + `Pygments` | — | 三者都是十年级别的稳定库，输出全内联 CSS，离线可开 |
| 前端 | Vue 3 + Vite + vue-router | — | 模板语法贴近 HTML，学习曲线平缓；不引 UI 组件库、不引 Pinia |
| 桌面壳 | Electron | — | 生态最成熟，打包踩坑资料最多 |

### 2.2 被否决的方案及原因

| 被否决 | 原因 |
|---|---|
| `webclaw`（Rust MCP） | 官方仅提供 macOS/Linux 预编译二进制，Windows 需自建 Rust 工具链（MSVC+cmake+clang）；主协议 AGPL-3.0，将来分享受约束 |
| `video-transcriber-mcp`（Rust） | 3K 行新项目，Windows 需手动下载 zip 并配 yt-dlp/ffmpeg 进 PATH；多一个进程即多一处故障面 |
| `softrag` | 21 star，API 仍在 breaking change，不适合作为核心依赖 |
| CortexDB | Go 编写，难以在 Python 进程内嵌；RAG 评测表现并不突出 |
| LangGraph / CrewAI / DeerFlow | 团队级、多状态、生产编排框架。本项目管线固定、节点少，框架带来的复杂度远大于收益 |
| ChromaDB / Qdrant | 独立向量服务，违背"一个文件搞定"的目标 |
| SQLAlchemy ORM | 学习成本与调试不透明性高于收益；裸 SQL 更适合作为学习型项目 |
| Tauri | 需 Rust 工具链，与"简单易学"冲突 |
| React | 概念体系持续膨胀，中文入门材料质量参差 |

### 2.3 关键原则

1. **一切外部能力都走 adapter 接口**：`fetcher`、`transcriber`、`embedder`、`llm`、`renderer` 各一个抽象基类 + 一个实现。将来想换 webclaw 只改一个类，上层零改动。
2. **实现优先选"十年老库"**，不用 trend 库。
3. **单文件数据**：所有业务数据在 `data.db`，备份 = 复制一个文件。
4. **失败必须可见**：任何异步任务都必须落到 `agent_task` 表，前端能看到失败原因，而不是静默挂掉。
5. **不阻塞事件循环**：DB 与模型推理都是同步阻塞操作，端点用 `def`（FastAPI 自动丢线程池），不要用 `async def` 里直接调同步 IO。

## 4. 架构

### 4.1 进程与端口模型

```
[开发模式]
  浏览器 → Vite Dev Server :5173 → 代理 → FastAPI :8756

[生产模式]
  Electron 主进程
    ├─ 随机空闲端口 P（net.createServer().listen(0) 探测）
    ├─ spawn Python 子进程，--port P，--data-dir %APPDATA%/StudyKB
    └─ BrowserWindow 加载 index.html，preload 注入 window.api.baseUrl
```

**硬性规定（第一天就定，不等到最后）**

- 端口**绝不硬编码**在渲染进程里，必须由主进程传入。
- 后端启动后先写一个 `ready` 标记（stdout 打印 `READY <port>`），Electron 捕获后再创建窗口，避免白屏。
- 窗口关闭时 `child.kill()`，并在 Python 侧注册 `atexit` 清理，防止僵尸进程。
- 数据目录由 `--data-dir` 传入，默认 `%APPDATA%/StudyKB`，开发模式默认 `./data`。

### 4.3 统一约定

**错误响应格式**

```json
{ "error": { "code": "FETCH_BLOCKED", "message": "目标站点返回 403", "detail": "https://..." } }
```

错误码分域：`FETCH_*` / `TRANSCRIBE_*` / `LLM_*` / `DB_*` / `RAG_*` / `QUIZ_*`。前端按 code 前缀决定提示文案。

**接口返回约定**

- 所有列表接口返回 `{ "items": [...], "total": n }`
- 所有耗时操作先返回 `{ "task_id": "..." }`，前端轮询 `GET /api/tasks/{id}`
- 所有时间戳为 ISO 8601 本地时区字符串

**日志**

- `logging` + 按天滚动到 `data/logs/app.log`
- 每次 LLM 调用记录：`agent`、`model`、`prompt_tokens`、`completion_tokens`、`duration_ms`、`ok/err`，落到 `llm_call_log` 表（便于算成本、定位慢调用）
- API Key 只出现在配置对象里，**任何日志与异常栈都不许打印**

### 4.4 检索实现要点（易踩坑，提前定死）

| 坑 | 对策 |
|---|---|
| FTS5 默认 `unicode61` 对中文按标点切，整句成一个 token，搜不到 | 建表即写 `tokenize='trigram'` |
| trigram 对**少于 3 个字符**的查询词无效（如"AI"、"错题"两字） | 查询词长度 < 3 时改走 `LIKE '%kw%'` 兜底，并在结果里标注 `match_type: like` |
| FTS5 是外部内容表，删改需手动同步 | 用触发器 `AFTER INSERT/UPDATE/DELETE ON chunk` 同步 `chunk_fts`，不要靠代码维护 |
| 向量检索与全文检索分数量纲不可比 | 用 RRF 融合：`score = Σ 1/(60 + rank_i)`，不直接加权求和 |
| bge 模型对短查询需要指令前缀 | 检索时 query 前加 `为这个句子生成表示以用于检索相关文章：`；入库的文档向量**不加** |
| sqlite-vec 加载失败（扩展/平台问题） | 启动时自检；失败则 `embedder` 降级为 numpy 暴力余弦相似（<10 万 chunk 完全够），功能不中断，只在设置页提示"向量加速不可用" |

### 4.5 切块策略

- 输入：`raw_content`（纯文本）
- 先按空行分段，再按句末标点（`。！？；\n`）细切
- 聚合到目标长度 600 字，最大 900 字，相邻块重叠 80 字
- 块内容写入 `chunk.content`，`position` 从 0 递增
- 送 LLM 做整理时，用**全文前 8000 字 + 首尾各 500 字**的采样策略；触发截断时在 `knowledge_item` 上写 `truncated=1`，前端详情页显示"内容过长，已按摘要处理"

## 5. 数据模型

> 全部写在 `db/schema.sql`，用 `PRAGMA user_version` 做版本迁移。

```sql
-- 知识条目
CREATE TABLE knowledge_item (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  title         TEXT    NOT NULL,
  source_type   TEXT    NOT NULL,          -- text | web | video | file
  source_url    TEXT,
  raw_content   TEXT    NOT NULL,
  content_hash  TEXT    NOT NULL,          -- sha256(raw_content)
  summary       TEXT,
  key_points    TEXT,                      -- JSON 数组
  structured_note TEXT,                    -- Markdown
  category      TEXT,
  tags          TEXT,                      -- JSON 数组
  status        TEXT    NOT NULL DEFAULT 'pending',  -- pending | organizing | ready | failed
  truncated     INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT    NOT NULL,
  updated_at    TEXT    NOT NULL
);
CREATE UNIQUE INDEX idx_item_url  ON knowledge_item(source_url) WHERE source_url IS NOT NULL;
CREATE INDEX        idx_item_hash ON knowledge_item(content_hash);
CREATE INDEX        idx_item_cat  ON knowledge_item(category, status);

-- 分块
CREATE TABLE chunk (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id  INTEGER NOT NULL REFERENCES knowledge_item(id) ON DELETE CASCADE,
  position INTEGER NOT NULL,
  content  TEXT    NOT NULL
);
CREATE INDEX idx_chunk_item ON chunk(item_id);

-- 全文索引（trigram 必须）
CREATE VIRTUAL TABLE chunk_fts USING fts5(
  content, content='chunk', content_rowid='id', tokenize='trigram'
);
CREATE TRIGGER chunk_ai AFTER INSERT ON chunk BEGIN
  INSERT INTO chunk_fts(rowid, content) VALUES (new.id, new.content);
END;
CREATE TRIGGER chunk_ad AFTER DELETE ON chunk BEGIN
  INSERT INTO chunk_fts(chunk_fts, rowid, content) VALUES('delete', old.id, old.content);
END;
CREATE TRIGGER chunk_au AFTER UPDATE ON chunk BEGIN
  INSERT INTO chunk_fts(chunk_fts, rowid, content) VALUES('delete', old.id, old.content);
  INSERT INTO chunk_fts(rowid, content) VALUES (new.id, new.content);
END;

-- 异步任务
CREATE TABLE agent_task (
  id          TEXT PRIMARY KEY,            -- uuid4
  type        TEXT NOT NULL,               -- fetch_url | transcribe_video | organize | ...
  status      TEXT NOT NULL,               -- queued | running | done | failed
  progress    INTEGER NOT NULL DEFAULT 0,  -- 0-100
  stage       TEXT,                        -- downloading | transcribing | indexing ...
  input_json  TEXT,
  output_json TEXT,
  error_code  TEXT,
  error_msg   TEXT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_task_status ON agent_task(status, created_at);

-- HTML 学习页
CREATE TABLE html_artifact (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,
  item_ids    TEXT NOT NULL,               -- JSON 数组
  html_content TEXT NOT NULL,
  created_at  TEXT NOT NULL
);

-- 题目
CREATE TABLE question (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id     INTEGER REFERENCES knowledge_item(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,               -- single | multiple | boolean | short
  difficulty  TEXT NOT NULL,               -- basic | understand | apply
  payload     TEXT NOT NULL,               -- JSON: {question, options[], answer, explanation}
  fingerprint TEXT NOT NULL,               -- sha256(item_id + type + question)
  created_at  TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_q_fp ON question(fingerprint);

-- 作答记录
CREATE TABLE quiz_attempt (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  user_answer TEXT NOT NULL,
  is_correct  INTEGER,                     -- NULL = 待人工判断
  feedback    TEXT,
  duration_ms INTEGER,
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_attempt_q ON quiz_attempt(question_id, created_at);

-- 复习队列（简单间隔，非 SM-2）
CREATE TABLE review_item (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id   INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  due_at        TEXT NOT NULL,
  interval_days INTEGER NOT NULL DEFAULT 1,
  lapses        INTEGER NOT NULL DEFAULT 0,
  last_result   INTEGER,
  updated_at    TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_review_q ON review_item(question_id);
CREATE INDEX idx_review_due ON review_item(due_at);

-- 番茄钟
CREATE TABLE study_session (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  target_type     TEXT,                    -- item | quiz | html | free
  target_id       INTEGER,
  start_time      TEXT NOT NULL,
  end_time        TEXT,
  duration_seconds INTEGER NOT NULL DEFAULT 0,
  planned_seconds  INTEGER NOT NULL DEFAULT 1500,
  status          TEXT NOT NULL DEFAULT 'running',  -- running | paused | done | abandoned
  note            TEXT,
  created_at      TEXT NOT NULL
);
CREATE INDEX idx_session_time ON study_session(start_time);

-- LLM 调用日志（成本与排障）
CREATE TABLE llm_call_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  agent       TEXT NOT NULL,
  model       TEXT NOT NULL,
  prompt_tokens     INTEGER,
  completion_tokens INTEGER,
  duration_ms INTEGER,
  ok          INTEGER NOT NULL,
  error_msg   TEXT,
  created_at  TEXT NOT NULL
);
```

**复习间隔规则（M4 实现，刻意保持简单）**

- 答错 → `interval=1`，`lapses+1`，`due_at = now + 1 天`
- 答对且 `interval < 7` → `interval *= 2`（1→2→4→7）
- 答对且 `interval >= 7` → `interval = 15`
- 待复习列表 = `WHERE due_at <= now ORDER BY due_at LIMIT 20`

## 6. 里程碑

> 每个里程碑结束都必须是"当天就能真用起来"的状态。
> 估算前提：每天有效投入 3–4 小时。总工期约 **16–18 个工作日**。

### M1 · 骨架与最小闭环（约 4 天）

**目标**：粘贴一段文字进去 → 点整理 → 左侧看到分类、右侧看到摘要和关键点。这一条链路跑通，项目就算立住了。

**任务**

### M3 · 检索与学习页（约 4 天）

**目标**：能搜到、能问、能生成一份好看的单文件 HTML 拿出去。

**任务**

| 编号 | 任务 | 关键要求 |
|---|---|---|
| T3.1 | 全文检索 | `GET /api/search?q=&limit=`：词长 ≥3 走 FTS5 trigram，<3 走 LIKE 兜底；返回 chunk 摘要 + 命中词高亮位置 + 所属条目 |
| T3.2 | Embedding 服务 | `sentence-transformers` 懒加载（首次调用约 3s，之后常驻）；批量编码（batch=32）；入库后异步补向量；文档不加指令前缀、查询加 `为这个句子生成表示以用于检索相关文章：` |
| T3.3 | 向量索引 | `sqlite-vec` 建 `vec0` 表（float[512]）；启动自检，不可用则降级 numpy 余弦相似（读全表也算，10 万条以内没问题） |
| T3.4 | 混合检索 | RRF 融合 top-20 + top-20 → 取前 8；返回 `match_type` 便于调试 |
| T3.5 | 问答接口 | `POST /api/ask`：检索 → 拼上下文（每块标注 `[1] 标题`）→ 要求模型**只依据给定材料回答并标注引用编号** → 返回 `{answer, sources[]}`；检索为空时直接返回固定话术，**不调用模型**（防止编造） |
| T3.6 | 问答前端 | 输入框 + 流式答案 + 来源卡片（点击跳转到条目详情并滚动到对应段落）；显示"本次检索命中 N 段，其中向量 M 段" |
| T3.7 | HTML 渲染 | `services/renderer.py`：条目 → Markdown（标题/摘要/关键点/结构化笔记/来源信息）→ `markdown` 转 HTML → Jinja2 套模板 → Pygments 代码高亮样式**内联**到 `<style>` → 输出自包含单文件 |
| T3.8 | 学习页接口 | `POST /api/html/generate`（1..n 个 item_id，可选标题）；`GET /api/html/{id}` 返回内容；`/download` 以附件下载；`html_artifact` 落库 |
| T3.9 | 学习页前端 | 知识库支持多选 → "生成学习页" → 抽屉内 iframe 预览（`sandbox="allow-same-origin"`）→ 下载按钮；历史产物列表可再下载 |

## 7. 横切规范

### 7.1 密钥与配置

- `.env` 只存在于本地，`.gitignore` 排除；仓库里只放 `.env.example`
- 配置优先级：命令行参数 > `.env` > 代码默认值
- 前端**永远不接触** API Key

### 7.2 代码规范

- 一个文件不超过 300 行，超了就拆
- 所有 prompt 放 `prompts/*.md`，代码里只引用文件名
- 所有外部能力走 adapter，方便替换与 mock
- 每个 service 至少有一个可直接运行的 `if __name__ == "__main__"` 自测入口

### 7.3 Git 节奏

- 每个 T 编号一次 commit，message 用 `feat(M1): T1.4 LLM 客户端`
- 里程碑完成打 tag：`m1-done`
- 里程碑验收通过前不开始下一个，避免返工叠加

### 7.4 验收脚本

每个里程碑配 `scripts/verify_mN.py`，用手写断言覆盖该里程碑的核心接口。要求：

- 不依赖前端，直接打 HTTP
- 用独立的临时数据库，跑完清理
- 输出 `PASS/FAIL` 清单，任一 FAIL 退出码非 0

### 7.5 前端样式基线（第一天定死，后面只增不改）

```
间距：4 / 8 / 12 / 16 / 24 / 32
字号：12（辅助） 13（正文） 14（小标题） 16（标题） 20（页面标题）
色板：主色 1（品牌）+ 成功 / 警告 / 危险 / 中性灰 4 档
圆角：8（控件） 12（卡片）
行高：1.6（正文） 1.4（标题）
```
