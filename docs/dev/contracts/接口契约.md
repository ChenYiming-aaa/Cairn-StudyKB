# 接口契约 v1.0

> **作用域**：只读本文件 + `00-总纲.md` + `决策记录.md`。**不要读** `milestones/*`（那是各阶段的任务说明，不是接口真相）。
> **冲突时**：本文件与任何里程碑文档冲突，**以本文件为准**。发现冲突不改代码，先在 `HANDOFF.md` 记一条待裁决。
> **唯一真相**：代码落地后本文件的权威性移交至 FastAPI 自动生成的 `/docs`（OpenAPI）。
> 迁移完成当天在此写明："⚠️ 唯一真相已迁移至 `http://127.0.0.1:8756/docs`，本文件仅做变更登记"。

## 1. 通用约定

- 前缀统一 `/api`
- 所有请求/响应 `Content-Type: application/json`，SSE 端点除外
- 错误统一：`{"error": {"code": "FETCH_BLOCKED", "message": "目标站点拒绝访问", "detail": "..."}}`
- 列表统一：`{"items": [...], "total": 123}`
- 耗时操作统一：先返回 `{"task_id": "uuid"}`，前端轮询 `GET /api/tasks/{id}`

## 3. 关键端点详细形状

### POST /api/knowledge

```json
// 请求
{ "title": "可选，缺省取正文首行前 40 字作占位标题", "raw_content": "必填", "source_type": "text" }
// 响应 201
{ "id": 12, "title": "...", "status": "pending", "chunk_count": 7, "duplicated": false }
// duplicated=true 时说明内容哈希撞上已有条目，此时 id 指向已有条目，不新建
```

### GET /api/knowledge

查询参数：`source_type` `category` `status` `q`（标题模糊） `tag`（标签精确匹配，走 `json_each`） `page`（默认1） `page_size`（默认20，上限100）

```json
{ "items": [{ "id": 12, "title": "...", "source_type": "web", "category": "学习方法",
              "tags": ["专注"], "status": "ready", "created_at": "..." }],
  "total": 37 }
```

### GET /api/knowledge/categories

左侧分类树专用：全库聚合，**不设条数上限**（此前前端取前 100 条自行聚合，破百后计数偏低）。

```
?category=学习方法&tag=间隔重复   （都可选；只影响 counts，不影响分类树本身）
```

```json
{ "categories": [{ "name": "学习方法", "count": 12,
                   "tags": [{ "name": "间隔重复", "count": 5 }] }],
  "counts": { "total": 37, "pending": 4, "organizing": 1 } }
```

- `category` 为空或 NULL 的条目归入 `未分类`，`tags` 为空数组
- 排序：分类按 `count` 降序后按名称；标签同理
- 标签来自 `json_each(tags)`，非法 JSON 视为空数组
- `counts.organizing > 0` 是前端决定「是否继续轮询刷新」的依据
- **`category` / `tag` 只收窄 `counts`**（左栏状态行与「开始整理 N 条」跟着筛选走）；`categories` 始终是全库的
- 分类名按展示名比对（`COALESCE(NULLIF(category,''),'未分类')`），和树里的数字逐条对得上

### GET /api/knowledge/{id}

```json
{ "id": 12, "title": "...", "source_type": "web", "source_url": "https://...",
  "raw_content": "...", "summary": "...", "key_points": ["..."],
  "structured_note": "# ...", "note_edited": 0,
  "category": "学习方法", "tags": ["专注"], "status": "ready",
  "truncated": 0, "created_at": "...", "updated_at": "..." }
```

`note_edited=1` 时，前端在"重新整理"按钮旁提示"将覆盖你手动编辑的内容"。

> 创建时的 `title` 只是占位（正文首行前 40 字），整理成功后会被 Agent 生成的 ≤20 字标题重写。

### PATCH /api/knowledge/{id}

```json
// 请求（字段全部可选，只传要改的）
{ "title": "新标题（≤20 字，超长 422）", "category": "学习方法", "tags": ["专注"],
  "structured_note": "# 一级标题\n\n## 二级标题\n- 要点" }
// 响应 200
{ "id": 12, "updated_at": "...", "note_edited": 1, "note_chunk_count": 3 }
```

**副作用（必须实现）**：请求里带了 `structured_note` 时，后端要

1. 把 `note_edited` 置 1
2. 删除该条目 `source='note'` 的 chunk，用同一个 chunker 重新切块写入
3. 不触发重新整理，不覆盖其他字段

> 用户手写的内容必须能被检索到，所以 note 也要进 chunk。这是刻意的设计，见数据契约 §6。

### POST /api/knowledge/{id}/organize

```
→ 202 { "task_id": "uuid" }
```

- 未配置 Key → 400 `LLM_NO_KEY`（**不派发注定失败的任务**）
- 条目已在整理中 → 409 `ITEM_BUSY`，不重复派发
- 条目不存在 → 404 `ITEM_NOT_FOUND`
- 条目 `status` 先置 `organizing`，任务结束后由 Agent 置 `ready` 或 `failed`
- 成功时同时**重写 `title`**（Agent 生成，≤20 字）；手填标题也会被覆盖
- `note_edited=1` 时前端必须先确认「将覆盖手改内容与标题」，再发请求（数据契约 §3）

### POST /api/knowledge/organize-pending

```
?limit=20（默认 20，上限 100）&category=学习方法&tag=间隔重复
→ 200 { "items": [{ "item_id": 12, "task_id": "uuid" }], "total": 1 }
```

只挑 `status='pending'` 的条目，逐条派发独立任务。返回的 `items` 为空表示没有待处理条目。
`category` / `tag` 与列表筛选同一口径：左栏筛着某分类时，整理的就是这批（按钮上的 N 与动作一致）。

### GET /api/knowledge/{id}/mindmap

```
?theme=paper|notes|chestnut|docs|study|teal&mode=light|dark
  （theme 默认 paper，mode 默认 light；兼容老写法 ?theme=light|dark，此时当成明暗）
Content-Type: image/svg+xml
```

返回纯 SVG 片段，**不含 `<script>`、不含任何外链**，可直接 `<img src>` / 内联嵌入。

- 数据来源：`structured_note` 的 Markdown 标题层级，**不经 LLM**
- 每次现场生成，不缓存（笔记一改就得跟着变）
- 配色按**主题派生**（`mindmap.palette(theme, mode)`）：根节点用主题主色，1–3 级做 ±42° 邻近色，第 4 级中性灰；
  SVG 不能读 CSS 变量（要能离线单独打开），所以 `_THEME_ACCENT` 里保留一份与 `tokens.css` 对齐的主色
- 无标题时退化：以条目 `title` 为根、`key_points` 为一级子节点
- 条目不存在 → 404 `ITEM_NOT_FOUND`；`structured_note` 为空 → 返回单节点 SVG，不报错

### GET /api/settings

前端唯一的配置数据源。**只读**，不含任何密钥。

```json
{ "llm": {
    "active": "deepseek",
    "providers": {
      "deepseek": {"label": "DeepSeek", "base_url": "https://api.deepseek.com",
                   "has_key": true, "supports_effort": true,
                   "models": ["deepseek-flash", "deepseek-reasoner"]},
      "custom":   {"label": "OpenAI 兼容", "base_url": "", "has_key": false,
                   "supports_effort": false, "models": []}
    },
    "tasks": {
      "organizer": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "asker": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "quizzer": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "grader": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"}
    }
  },
  "appearance": {"theme": "paper", "mode": "system", "font_size": "md"},
  "env_file": "C:\\Users\\<你>\\AppData\\Roaming\\Cairn\\.env",
  "config": {
    "ok": true,                       // false = 配置被两处拼起来了（见下）
    "strict": false,                  // CAIRN_ENV_STRICT=1 时为 true
    "env_file": "C:\\Users\\<你>\\AppData\\Roaming\\Cairn\\.env",
    "legacy_file": null,              // 非空 = 从这个"老地方"补过值
    "legacy_keys": [],                // 补进来的变量名（只有名字，没有值）
    "hint": "配置只来自上面这一个文件"
  } }
```

- **绝不出现** `api_key` / `*_key` 字段，只有 `has_key: true|false`（红线 7）
- `config` 是配置来源审计（ADR-028）：`ok=false` 表示除 `env_file` 外还从布局默认 `.env`
  补过值。这个块存在的意义是**让它看得见**——只有看得见的东西才会被检查/断言
- `models` 是"上次探测到的候选列表"，可能为空；为空时前端允许手输模型名
- `tasks[*].model` 为空串 = 用该 provider 的默认（`models[0]`）
- `effort ∈ none|low|medium|high`，仅当 `supports_effort=true` 时有效
- 读取用「默认值 ← `settings.json`」深合并：文件缺键就补默认值，不因手改坏一个键而整份作废

### PATCH /api/settings

```json
// 请求：只带要改的部分，形状与 GET 的对应子树一致
{ "appearance": {"theme": "study", "mode": "dark"} }
// 响应 200：更新后的全量（形状同 GET /api/settings）
```

- 允许改的子树：`appearance` / `llm.tasks` / `llm.active` / `llm.providers.<id>.base_url|label|models|supports_effort`
- **Key 不走这里**（走 `POST /api/settings/llm`）
- 非法枚举值（theme / mode / effort / provider 不存在）→ 400 `SETTINGS_INVALID`，`detail` 指明哪个键
- 写入是原子的（`settings.json.tmp` → `os.replace`），并立即对下一次 LLM 调用生效，不需要重启

### POST /api/settings/probe

```json
// 请求（base_url / api_key 可省略：省略则用已保存的 provider 配置；api_key 只用于本次探测，不落盘）
{ "provider": "deepseek", "base_url": "https://api.deepseek.com", "api_key": "" }

// 响应 200
{ "ok": true, "models": ["deepseek-flash", "deepseek-reasoner"],
  "latency_ms": 412, "error_code": null, "hint": null }
```

- 先 `GET {base_url}/models`；失败退化 `POST {base_url}/chat/completions`（`max_tokens=1`，一条 `ping`）
- **只探测，不写任何文件**（ADR-028）：不改 `base_url`、不改 `models`、不碰 `settings.json`。
  模型列表由前端在用户点「保存 / 记住」时随 `PATCH /api/settings` 提交
  （"试穿一下就被扣款"是不允许的；关窗口没保存就当作还没确定）
- 退化成功时 `ok=true`、`models=[]`、`error_code="LLM_MODELS_UNSUPPORTED"`（服务不提供列表但对话可用）
- 超时 15 秒、**不重试**；错误码复用 `LLM_*` 家族（`LLM_NO_KEY` / `LLM_QUOTA` / `LLM_TIMEOUT` / `LLM_HTTP_ERROR` / `LLM_MODELS_UNSUPPORTED`）
- **绝不回显 Key**：`detail` / `hint` / 日志里都不出现（红线 7）
- 缺 `base_url`（请求里没给、已存配置里也没有）→ 400 `SETTINGS_INVALID`

### POST /api/settings/llm

```json
// 请求（任一项为空 = 不改这一项）
{ "provider": "custom", "api_key": "sk-...", "base_url": "https://api.siliconflow.cn/v1" }
// 响应 200
{ "saved": true, "env_file": "C:\\Users\\<你>\\AppData\\Roaming\\Cairn\\.env",
  "settings": { /* 同 GET /api/settings */ } }
```

- 写到该 provider 的 `key_env`（默认 provider = `LLM_API_KEY`，第二个 = `ALT_API_KEY`），走 `python-dotenv` 的 `set_key`，不动别人的行
- 写后热加载，`has_key` 立刻变 `true`；响应里直接带新全量配置，前端不必二次请求
- 值含换行或引号 → 400 `ENV_INVALID_VALUE`；`base_url` 不以 `http(s)://` 开头 → 400 `ENV_INVALID_VALUE`
- 与 `POST /api/env/key` 的分工：`env/key` 是首次引导的**单 provider 快捷入口**（写死的三个键），
  `settings/llm` 是设置窗口的**双 provider 入口**，两者共用 `env_store` 的落盘逻辑，行为必须一致

### GET /api/version

```json
{ "version": "0.2.0", "commit": "485bf6b", "built_at": "2026-11-10T14:40:12+08:00" }
```

### POST /api/env/key

```json
// 请求（三项都可选；空串 = 不改这一项，不是"清空"）

// 响应 200
```

- 落到 `Settings.env_file`：显式指定数据目录（`--data-dir` / `DATA_DIR`）时是 `<数据目录>/.env`，

### POST /api/ingest/url

```json
// 请求
{ "url": "https://...", "force": false }
// 响应 202
{ "task_id": "uuid", "existing_item_id": null }
// 若该 URL 已存在且 force=false，直接返回 { "task_id": null, "existing_item_id": 12 }
```

- `force=true`：派任务重新抓取，**只覆盖正文** `raw_content` 并重建 `source='raw'` 的 chunk、状态回 `pending`；
  标题、分类、标签、摘要、`structured_note`、`note_edited` 一律不动（2026-11-06 裁决）。
- 任务 `type` 为 `fetch_url`，`stage` 依次 `fetching` → `saving`，`progress` 取固定值 10 / 50 / 90。
- `output_json`：`{"item_id": 12, "duplicated": false, "existing_item_id": null, "chunk_count": 3}`；
  同内容不同 URL 时 `duplicated=true` 且 `existing_item_id` 指向已有条目，**不新建**。
- **成功与否看正文，不看状态码**：知乎专栏页返回 403 却带完整正文，正文够 200 字就入库；
  只有 `404/410` 无条件判 `FETCH_NOT_FOUND`（那才是真没有页面）。
- **浏览器降级**：httpx 抓取报 `FETCH_BLOCKED` / `FETCH_EMPTY` 时，自动改用真实浏览器渲染
  再抓一次（知乎这类拦 TLS 指纹、或纯 JS 渲染的站点靠这条）。其余错误（超时 / DNS /
  404 / 非网页）不降级 —— 换浏览器也一样，只是把 30 秒拖成 60 秒。
  浏览器用本机的 Edge/Chrome（`BROWSER_CHANNEL`，默认 `msedge`），不额外下载 Chromium。
  降级成功时多花 3–5 秒；降级也失败时，取信息量大的那个错误上报。

错误码：`FETCH_TIMEOUT` `FETCH_BLOCKED` `FETCH_EMPTY` `FETCH_INVALID` `FETCH_DNS` `FETCH_NOT_FOUND`
`FETCH_LOGIN_REQUIRED` `FETCH_BROWSER_UNAVAILABLE` `URL_INVALID`

### POST /api/ingest/video

```json
// 请求（model / language 可省，默认 small / zh）
{ "url": "https://...", "model": "small", "language": "zh", "force": false }
// 响应 202
{ "task_id": "uuid", "existing_item_id": null }
// 若该 URL 已存在且 force=false，直接返回 { "task_id": null, "existing_item_id": 12 }
```

- 任务 `type` 为 `transcribe_video`，`stage` 依次为 `metadata`(0–5) → `downloading`(5–30)
  → `transcribing`(30–95) → `saving`(95–100)；`progress` 单调不减。
- **字幕优先**：`metadata` 阶段若该视频有中/英字幕（`subtitles` 优先于 `automatic_captions`，
  简体优先于繁体），直接取字幕入库，跳过 `downloading` 与 `transcribing`——
  `stage` 会是 `metadata` → `saving`。字幕链任何一步失败（无字幕 / 需登录 / 格式不认 /
  下载失败 / 解析为空）都静默退回语音识别，**不会让任务失败**。
  B 站字幕必须登录：在采集面板点「站点登录 → B 站」即可。登录助手把 cookie 导出成
  `cookies.txt`，路径规则与 `YTDLP_COOKIES` 一致（配了就用配置的路径，否则 `data/cookies.txt`），
  导出后立即生效，不需要重启。
- `output_json`：`{"item_id": 12, "duplicated": false, "existing_item_id": null,
  "chunk_count": 4, "duration": 312, "segment_count": 87, "language": "zh",
  "source": "asr"}`；`source` 为 `asr`（语音识别）或 `subtitle`（现成字幕）。
  `raw_content` 每行形如 `[mm:ss] 文本`，超过 1 小时用 `[h:mm:ss]`。
- **繁简归一（仅 `source=asr`）**：识别结果在拼行前按汉字段做一次繁→简转换，
  标点、英文、数字、时间戳不动（ADR-025）。`source=subtitle` 保留字幕原文，不做转换。
- 无音轨但有字幕的视频可以入库；既无音轨也无字幕才报 `TRANSCRIBE_NO_AUDIO`。
- **链接归一化**：入库前先收敛成「单条视频」的规范地址，同一视频的不同分享形式不会重复入库。
  - 抖音聚合页 `douyin.com/jingxuan?modal_id=<id>` → `douyin.com/video/<id>`
  - 抖音图文笔记 `douyin.com/note/<id>` → 保留原样，直接报 `TRANSCRIBE_UNSUPPORTED`
  - B 站去掉 `t` / `spm_id_from` / `vd_source` 等追踪参数，**保留分 P 的 `p`**
  - `youtu.be/<id>` → `youtube.com/watch?v=<id>`；`v.douyin.com`、`b23.tv` 短链先跟随跳转
  - 入库后 `source_url` 是归一化后的地址
- **抖音单独一条通道**：详情接口要 `a_bogus` 签名（签名在页面自己的 JS 里），
  yt-dlp 因此报 `Fresh cookies (not necessarily logged in) are needed`。
  实现改为用浏览器打开视频页、截获页面自己发出的 `aweme/detail` 响应拿媒体直链，
  再下 mp4 → ffmpeg 抽音轨 → 识别，`stage` 仍是标准的四阶段。
  这条通道需要 playwright 与可用浏览器，缺失时报 `TRANSCRIBE_BROWSER_UNAVAILABLE`。
- `source_type="video"`，标题取视频标题（截断 100 字）；抖音取文案第一段（`#` 之前），
  避免标题被一串话题标签占满。
- `force=true` 语义同 `/api/ingest/url`：**只覆盖正文**，标题/分类/标签/笔记不动。
- 去重规则与网页一致：同 URL 直接回 `existing_item_id`；同内容不同 URL 撞 `content_hash`
  时 `duplicated=true` 且不新建。

错误码：`TRANSCRIBE_NO_FFMPEG` `TRANSCRIBE_YTDLP_FAIL` `TRANSCRIBE_NO_AUDIO`
`TRANSCRIBE_MODEL_FAIL` `TRANSCRIBE_UNSUPPORTED` `TRANSCRIBE_BLOCKED`
`TRANSCRIBE_NOT_FOUND` `TRANSCRIBE_EMPTY` `TRANSCRIBE_BROWSER_UNAVAILABLE` `URL_INVALID`
`COMPONENT_MISSING`（M8：语音 / 浏览器组件没装，`detail` 写组件 id，文案统一指「设置 → 下载」）

```json
→ { "id": 3, "deleted": true }      // 不存在 → 404 HTML_NOT_FOUND
```

只删产物，不动条目与 chunk。

### POST /api/quiz/generate（SSE）

```json
{ "item_id": 12, "types": ["single","boolean"], "difficulty": "understand", "count": 5 }
// count 上限 20；types 只能取 single/multiple/boolean/short；difficulty 只能取 basic/understand/apply
data: {"type":"question","index":0,"question":{"id":31,"type":"single","question":"...",
        "options":["裸文本一","裸文本二"],"answer":"B","explanation":"...","difficulty":"understand",
        "source_item_id":12,"source_title":"条目标题","duplicate":false}}
data: {"type":"question","index":1,"question":{...}}
data: {"type":"skip","index":2,"reason":"json_parse_failed"}
data: {"type":"error","code":"LLM_HTTP_ERROR","message":"...","detail":"..."}
data: {"type":"done","count":4,"skipped":1,"requested":5}
```

- `skip.reason` 取值：`json_parse_failed` / `not_object` / `bad_type` / `empty_question` /
  `missing_explanation` / `bad_options` / `bad_answer` / `duplicate` / `store_failed`。
  **单题失败只跳这一题**，流不中断。
- `duplicate: true` 表示撞了已有 fingerprint、复用了旧题（不重复入库）。
- **`options` 只放选项内容本身**，不带 `"A. "` / `"B、"` / `"(C)"` 这类字母或序号前缀 ——
  序号由界面按数组下标生成（`A` 起）。模型偶尔带前缀时后端会剥掉
  （`repo/questions.strip_option_prefix`，生成侧与读取侧都过），所以前端拿到的一律是裸文本。
  历史脏数据（缺陷期入库的）也在读取时剥，界面不会出现「A. A. …」。
- 首轮题数不足时**逐题补生成**（再调一次，prompt 只要 1 题并带上已出题干）；
  `done.count` 是最终入库题数，可能小于 `requested`。
- 材料取条目正文的 chunk **等距抽样**（≤6000 字，覆盖全文首尾），不是截前 6000 字。
- 模型侧失败：`type=error` 的 `code` 取 `LLM_TIMEOUT` / `LLM_QUOTA`（HTTP 402、429）/ `LLM_HTTP_ERROR`，
  与 `/api/ask` 同一套分类；发完 error 仍会补一个 `done`，前端不用猜流是否结束。
- 错误：条目不存在 → 404 `ITEM_NOT_FOUND`；材料过短 → 400 `QUIZ_MATERIAL_TOO_SHORT`；
  `types` / `difficulty` 非法 → 422。

### POST /api/quiz/submit

```json
{ "answers": [{ "question_id": 31, "user_answer": "B", "duration_ms": 8200 }] }
→ { "items": [{ "question_id": 31, "is_correct": true, "correct_answer": "B",
                "explanation": "...", "feedback": null }],
    "correct_count": 3, "total": 5, "accuracy": 0.6 }
// 简答批改失败时 is_correct = null，feedback = "批改服务不可用，已标记待人工判断"
```

- `user_answer` 形状随题型：单选 `"B"`、多选 `["A","C"]`（**后端按集合比较，顺序无关**）、
  判断 `true/false`、简答文本。未作答（空串 / 空数组 / null）一律判错并给出参考答案。
- `accuracy = correct_count / total`，四舍五入两位；`is_correct = null` 的题**算进 total 但不进
  correct_count**（前端要单独显示「待人工判断」，不许当成答错）。
- 任一 `question_id` 不存在 → 404 `QUESTION_NOT_FOUND`（整批不落库）。
- **判完分顺带写复习队列**（T4.6）：答错 → `interval_days=1`、due 明天；答对且该题在队列里 → 间隔推进；
  `is_correct IS NULL`（待人工判断）→ **不排期**。同一次提交里同一题只推一次，避免交卷把间隔推两格。
  前端**不要**再调 `/api/review/{id}/result` 重复上报。

### GET /api/quiz/wrong

```json
{ "items": [{ "question_id": 31, "type": "single", "question": "...", "options": ["裸文本一","裸文本二"],
              "answer": "B", "explanation": "...", "difficulty": "understand",
              "source_item_id": 12, "source_title": "条目标题",
              "wrong_count": 2, "last_wrong_at": "2026-11-07T16:08:34+08:00",
              "due_at": "2026-11-08T08:08:34+00:00", "interval_days": 1, "lapses": 1 }],
  "total": 3 }
// ?limit=20&offset=0
```

- 错题本 = **最近一次作答明确答错**的题；复习答对后自动移出。
- 待人工判断（`is_correct IS NULL`）既不算错也不算对，**不进错题本**。
- 从未排期（比如答题后还没触发过复习）时 `due_at` 为 `null`。
- 历史上错过但已答对的题不在列表里，历史仍可在 `quiz_attempt` 查。

### GET /api/review/due

```json
{ "items": [{ "question_id": 31, "type": "single", "question": "...", "options": ["裸文本一","裸文本二"],
              "answer": "B", "explanation": "...", "difficulty": "understand",
              "source_item_id": 12, "source_title": "条目标题",
              "review_id": 7, "due_at": "2026-11-08T08:08:34+00:00",
              "due_local": "2026-11-08T16:08:34+08:00",
              "interval_days": 1, "lapses": 1, "last_result": 0, "overdue_days": 0 }],
  "total": 2, "tracked": 5, "wrong": 3, "now": "2026-11-07T08:08:34+00:00" }
// ?limit=20（1–100）
```

- `items` 是**完整题目**（带 options/answer/explanation），复习模式可以直接作答，不必再调 generate。
- `due_at` 是 UTC 存储值；`due_local` 是同一时刻的本地表示，只用于显示。
- `total` = 到期总数（可能大于 `items.length`，因为 `limit`）；`tracked` = 队列总量；
  `wrong` = 错题本数量。三个角标一次请求拿全。
- 到期判断在 **Python 侧**做（`datetime.fromisoformat` → aware → 比较），不在 SQL 里比字符串
  （数据契约 §3）。

### POST /api/review/{question_id}/result

```json
{ "correct": true }
→ { "scheduled": true, "question_id": 31, "due_at": "2026-11-10T08:08:34+00:00",
    "interval_days": 2, "lapses": 1, "last_result": 1 }
// 答对但该题从没答错过（不在队列里）→ 200 { "scheduled": false, "due_at": null, "reason": "not_tracked" }

```

- 用途：**人工裁定**「待人工判断」的简答题（批改失败时后端刻意不排期，不猜对错）。

- `correct=true` 且不在队列里 → `scheduled=false`，不算错误（没答错过的题本来就不需要复习）。

### POST /api/session/{id}/{action}　action ∈ pause | resume | finish | abandon

```json
// finish 可选带笔记（T5.1「结束写笔记」）；其余 action 忽略请求体
{ "note": "铃响就停，不是凑满 25 分钟" }
→ 200 { "id": 7, "status": "done", "end_time": "...", "duration_seconds": 320, "note": "...", ... }
```

- **状态机**：`running ⇄ paused`，两者都能 `finish`/`abandon` 进终态；终态不可回到 active。
- **幂等**：对**同一个终态**重复调用（连点两下 finish）返回现状，不重算时长、不覆盖 `end_time`/`note`；
  跨终态（`done` 再 `finish` 之外的组合）→ 409 `SESSION_STATE`。id 不存在 → 404 `SESSION_NOT_FOUND`。
- **时长口径**：`duration_seconds` 是**已结算**时长，`elapsed_seconds` 是含当前段的实时值。
  前端只需要 `elapsed_seconds`，用它当锚点在本机继续走（见 §3 计时口径）。

### POST /api/session/{id}/heartbeat

```json
→ 200 { "id": 7, "status": "running", "duration_seconds": 320, "start_time": "...", ... }
```

- 15 秒一次（`useTimer`），把已过时间卷进 `duration_seconds` 并把锚点挪到当下，**不改 status**。
- 非 running（paused / 终态）直接返回现状、**不报错**：闭窗时 `sendBeacon` 与 pause 几乎同时到达，
  迟到的心跳不该弹 409。用 POST 而不是 PATCH 就是因为 `sendBeacon` 只能发 POST。
- 作用：进程被强杀时最多丢一个心跳间隔的时长。

### 计时与统计口径（与 M5 §6.6 同源，实现见 `db/repo/sessions.py`、`db/repo/stats.py`）

| 项 | 口径 |
|---|---|
| 有效时长 | `duration_seconds + (now - start_time)` 仅在 `running`；暂停期间不计 |
| 锚点 | `start_time` = **当前段起点**；`paused` 时它等于暂停时刻（表结构没改，用这两列表达 `pausedAccum`） |
| 今日待整理 | `status='pending'` 且 `date(created_at,'localtime')` = 今天 |
| 今日待复习 | `due_at <= now` 的条数（不限今天新增） |
| 本周专注 | 本周一 00:00 起 `status='done'` 的 `duration_seconds` 之和；`abandoned` 不计 |
| 连续学习天数 | 今天有记录就从今天起算；**今天还没学不算断**，从昨天起算 |
| 正确率 | `is_correct=1` / `is_correct IS NOT NULL`（NULL 不进分母） |
| 分类分布 | `GROUP BY category` 取前 8，空分类并入「未分类」 |

> 路径一律带 `/api` 前缀（本文件是 `doc_check.py` 的登记事实源）。
> 错误码与界面文案见 `执行计划-v0.3-M9-M11.md` §6.2；前端按 `code` 走 `client.js` 的 `friendlyMessage` 映射，

### L1 · 文件、识别、工作区（M9）

## 4. 前端调用约定

- `client.js` 暴露 `get/post/patch/del`，自动拼接 baseUrl（优先级：`window.api?.baseUrl` > `import.meta.env.VITE_API_BASE` > 空串）
  - **两种运行形态都用「空串 = 相对路径」**，都不注入 baseUrl：
    - 开发期：Vite `server.proxy['/api'] → 127.0.0.1:8756`，页面在 5173，相对路径被反代
    - 生产：Electron 加载 `http://127.0.0.1:<port>/`，后端吐出 `frontend/dist`，页面与 `/api` **同源**，相对路径直接命中
  - **不要往 preload 注入 baseUrl**（`file://` 时代的旧方案，已废弃，见 §5 末尾理由）。
    `window.api.baseUrl` 仅保留为调试逃生口：需要临时把前端指向另一个后端时才用
  - **preload 只为一个特权能力存在：更新器**（T8.5，ADR-030）。暴露面固定为
    `window.cairn = { update: { check, download, cancel, install, onProgress }, app: { version, isPackaged, platform } }`，
    四个方法全部走 `ipcRenderer.invoke`，**不把 `ipcRenderer` 本身递出去**；
    主进程侧校验调用来源（只接受本窗口 `http://127.0.0.1:<port>`）且**不接受渲染进程传 URL**
- 统一处理 `error.code`，按前缀映射提示：`FETCH_*` → 采集失败类文案，`LLM_*` → 模型调用失败类文案
- SSE 用 `fetch` + `ReadableStream` 解析（**不用 EventSource**，因为需要 POST 与自定义头），封装成 `streamSSE(path, body, onEvent)`
- 轮询任务用 1.5s 间隔、指数退避到 5s，最多 20 分钟；组件卸载必须清定时器

## 5. 静态资源路由（非 API）

> 这两条**不是 API**：没有错误码、不属于 `/api` 命名空间，`tools/doc_check.py` 不校验。
> 写在这里只为一件事——固定约束，防止后续会话把 catch-all 加回来。

| 路由 | 返回 | 注册条件 |
|---|---|---|
| `GET /` | `frontend/dist/index.html` | `dist/index.html` 存在 |
| `GET /assets/*` | Vite 静态产物 | `dist/assets/` 是目录 |

**四条硬约束**

1. **禁止** `app.mount("/", StaticFiles(html=True))`。未匹配的 `/api/*` 会返回 HTML 而不是 404，
   接口调试从此变成"永远 200 但内容是 HTML"——最难查的那类故障。
2. **必须条件注册**：`dist/index.html` 不存在（dev 没 build / 没装前端）就整段跳过，
   否则后端启动即抛错。这也顺便让 dev 与 prod 自动区分开，不需要额外的环境开关。
3. 只注册 `GET /`，**不做 SPA catch-all**。前端是 hash 路由（`createWebHashHistory`），
   深链接带 `#`，不会打到后端。
4. 路径优先级：`CAIRN_WEB_DIR` 环境变量 > `Path(__file__).resolve().parents[2] / "frontend" / "dist"`。
   PyInstaller 打包后 `__file__` 指向 `_internal/` 内部，相对路径会算错，
   **届时必须由 Electron 传入 `CAIRN_WEB_DIR`**（与 `FFMPEG_DIR` 同一套做法）。

**为什么不用 `file://`**

`file://` 页面的 origin 是 `null`，页面里对 `/api` 的请求会被 CORS 白名单拦掉；
而放行 `null` 又与 `allow_credentials=True` 构成已知的危险组合。
改为让后端吐出前端产物、Electron 加载 `http://127.0.0.1:<port>/` 之后，
页面与接口同源，**CORS 这个问题整体消失**，不需要反代、不需要 preload 暴露端口、不需要放行 `null`。
