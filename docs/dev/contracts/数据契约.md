# 数据契约 v1.0

> **作用域**：只读本文件 + `00-总纲.md` + `决策记录.md`。**不要读** `milestones/*`（那是各阶段的任务说明，不是表结构真相）。
> **冲突时**：本文件与任何里程碑文档冲突，**以本文件为准**。发现冲突不改代码，先在 `HANDOFF.md` 记一条待裁决。
> **唯一真相**：代码落地后本文件的权威性移交至 `backend/app/db/schema.sql`。
> 迁移完成当天必须在此行下方写明："⚠️ 唯一真相已迁移至 xxx，本文件仅做变更登记"。
> 改动任何字段前，先在 `决策记录.md` 加一条 ADR。

---

## 1. 变更规则

- **只增不改**：新增字段/表可以，改字段名与类型不行（改就要写迁移脚本 + ADR）
- 表结构变更通过 `PRAGMA user_version` 递增，`db/migrate.py` 按版本号顺序执行
- 当前 `user_version = 4`（2026-11-12 起，M9 登记）。迁移脚本：`v2_ask_log.sql`（1→2，问答历史）、
  `v3_llm_effort.sql`（2→3，`llm_call_log` 补 `effort` / `effort_dropped` 两列，只加列不重写数据）、
  **`v4_files_workspace.sql`**（3→4：`workspace` / `item_file` / `item_page` 三张新表 + `knowledge_item` 三列 + `question` 两列）
- **v4 老数据回填值**：`knowledge_item.kind` 一律 `'material'`、`workspace_id` 为 NULL（未归类）、`file_id` 为 NULL；
  `question.origin` 一律 `'ai'`、`number` 为 NULL。`kind` 必须是 `NOT NULL DEFAULT 'material'`
  —— SQLite 的 `ALTER TABLE` 只允许添加带默认值的 NOT NULL 列。
- **v4 迁移只做追加**：建表一律 `IF NOT EXISTS`，改表一律 `ADD COLUMN`，**不重写任何已有行**；
  `schema.sql` 新建库必须与「v3 升级到 v4」的字段集合、默认值、索引完全一致（T9.2 验收项）
- 任何新表都必须同时在 `schema.sql`、本文件、`docs/dev/milestones/` 对应里程碑里出现
- **例外（2026-11-05 裁决）**：依赖可选扩展的 `chunk_vec` 不写进 `backend/app/db/schema.sql`，单独放 `backend/app/db/schema_vec.sql`，由 `migrate.py` 仅在检测到 sqlite-vec 扩展时执行；`schema.sql` 保持全量业务表且可在无扩展环境直接建库（见 ADR-010）

## 2. 全量 DDL

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- ── 知识条目 ────────────────────────────────────────────
CREATE TABLE knowledge_item (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  title           TEXT    NOT NULL,
  source_type     TEXT    NOT NULL,   -- text | web | video | file
  source_url      TEXT,
  raw_content     TEXT    NOT NULL,
  content_hash    TEXT    NOT NULL,   -- sha256(raw_content)，用于去重
  summary         TEXT,
  key_points      TEXT,               -- JSON 数组字符串
  structured_note TEXT,               -- Markdown，用户可编辑
  note_edited     INTEGER NOT NULL DEFAULT 0,  -- 1 = 用户手改过，重新整理前需确认
  category        TEXT,
  tags            TEXT,               -- JSON 数组字符串
  status          TEXT    NOT NULL DEFAULT 'pending',
                  -- pending | organizing | ready | failed
  truncated       INTEGER NOT NULL DEFAULT 0,  -- 送模型时是否被截断
  created_at      TEXT    NOT NULL,
  updated_at      TEXT    NOT NULL,
  -- v4（M9）新增：老数据 kind='material'、workspace_id/file_id 为 NULL
  workspace_id    INTEGER REFERENCES workspace(id) ON DELETE SET NULL,
  kind            TEXT NOT NULL DEFAULT 'material',  -- material | exam | image | note
  file_id         INTEGER REFERENCES item_file(id)
);
CREATE UNIQUE INDEX idx_item_url  ON knowledge_item(source_url) WHERE source_url IS NOT NULL;
CREATE INDEX        idx_item_hash ON knowledge_item(content_hash);
CREATE INDEX        idx_item_cat  ON knowledge_item(category, status);

-- ── 分块 ────────────────────────────────────────────────
CREATE TABLE chunk (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id  INTEGER NOT NULL REFERENCES knowledge_item(id) ON DELETE CASCADE,
  position INTEGER NOT NULL,
  content  TEXT    NOT NULL,
  source   TEXT    NOT NULL DEFAULT 'raw'   -- raw = 原文切块 | note = 用户笔记切块
);
CREATE INDEX idx_chunk_item ON chunk(item_id, source);

-- ── 全文索引（trigram 是中文可搜的唯一前提）───────────────
CREATE VIRTUAL TABLE chunk_fts USING fts5(
  content, content='chunk', content_rowid='id', tokenize='trigram'
);
CREATE TRIGGER chunk_ai AFTER INSERT ON chunk BEGIN
  INSERT INTO chunk_fts(rowid, content) VALUES (new.id, new.content);
END;
CREATE TRIGGER chunk_ad AFTER DELETE ON chunk BEGIN
  INSERT INTO chunk_fts(chunk_fts, rowid, content) VALUES('delete', old.id, old.content);
END;
CREATE TRIGGER chunk_au AFTER UPDATE ON chunk BEGIN
  INSERT INTO chunk_fts(chunk_fts, rowid, content) VALUES('delete', old.id, old.content);
  INSERT INTO chunk_fts(rowid, content) VALUES (new.id, new.content);
END;

-- ── 向量索引（M3 启用）────────────────────────────────────
-- 依赖 sqlite-vec 扩展。启动时先查 sqlite_master，不存在才创建。
-- 扩展加载失败时不建此表，检索降级为 numpy 暴力余弦，功能不中断。
-- 本段 DDL 不进 schema.sql，单独存放于 backend/app/db/schema_vec.sql（见 §1 例外）。
CREATE VIRTUAL TABLE chunk_vec USING vec0(
  chunk_id  INTEGER PRIMARY KEY,   -- 对应 chunk.id
  embedding float[512]             -- bge-small-zh-v1.5 输出维度，不可随意改
);

-- ── 异步任务 ────────────────────────────────────────────
CREATE TABLE agent_task (
  id          TEXT PRIMARY KEY,        -- uuid4
  type        TEXT NOT NULL,           -- fetch_url | transcribe_video | organize | index_embed
  status      TEXT NOT NULL,           -- queued | running | done | failed
  progress    INTEGER NOT NULL DEFAULT 0,  -- 0-100
  stage       TEXT,                    -- metadata | downloading | transcribing | saving
  input_json  TEXT,
  output_json TEXT,
  error_code  TEXT,
  error_msg   TEXT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_task_status ON agent_task(status, created_at);

-- ── HTML 学习页 ─────────────────────────────────────────
CREATE TABLE html_artifact (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  title        TEXT NOT NULL,
  item_ids     TEXT NOT NULL,     -- JSON 数组
  html_content TEXT NOT NULL,
  created_at   TEXT NOT NULL
);

-- ── 题目 ────────────────────────────────────────────────
CREATE TABLE question (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id     INTEGER REFERENCES knowledge_item(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,         -- single | multiple | boolean | short
  difficulty  TEXT NOT NULL,         -- basic | understand | apply
  payload     TEXT NOT NULL,         -- JSON: {question, options[], answer, explanation}
  fingerprint TEXT NOT NULL,         -- sha256(item_id + type + question)
  created_at  TEXT NOT NULL,
  -- v4（M9）新增：老数据 origin='ai'、number 为 NULL
  origin      TEXT NOT NULL DEFAULT 'ai',  -- ai | imported | manual
  number      TEXT                        -- 原卷题号（"12"、"二.3"）；AI 生成时为 NULL
);
CREATE UNIQUE INDEX idx_q_fp ON question(fingerprint);

-- ── 作答记录 ────────────────────────────────────────────
CREATE TABLE quiz_attempt (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  user_answer TEXT NOT NULL,
  is_correct  INTEGER,               -- NULL = 待人工判断
  feedback    TEXT,
  duration_ms INTEGER,
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_attempt_q ON quiz_attempt(question_id, created_at);

-- ── 复习队列（简单间隔，非 SM-2）────────────────────────
CREATE TABLE review_item (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id   INTEGER NOT NULL REFERENCES question(id) ON DELETE CASCADE,
  due_at        TEXT NOT NULL,
  interval_days INTEGER NOT NULL DEFAULT 1,
  lapses        INTEGER NOT NULL DEFAULT 0,
  last_result   INTEGER,
  updated_at    TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_review_q   ON review_item(question_id);
CREATE INDEX        idx_review_due ON review_item(due_at);

-- ── 番茄钟 ──────────────────────────────────────────────
CREATE TABLE study_session (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  target_type      TEXT,              -- item | quiz | html | free
  target_id        INTEGER,
  start_time       TEXT NOT NULL,
  end_time         TEXT,
  duration_seconds INTEGER NOT NULL DEFAULT 0,
  planned_seconds  INTEGER NOT NULL DEFAULT 1500,
  status           TEXT NOT NULL DEFAULT 'running',
                   -- running | paused | done | abandoned
  note             TEXT,
  created_at       TEXT NOT NULL
);
CREATE INDEX idx_session_time ON study_session(start_time);

-- ── LLM 调用日志 ────────────────────────────────────────
CREATE TABLE llm_call_log (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  agent             TEXT NOT NULL,
  model             TEXT NOT NULL,
  prompt_tokens     INTEGER,
  completion_tokens INTEGER,
  reasoning_tokens  INTEGER,           -- 思考 token，取自 usage.completion_tokens_details.reasoning_tokens
  duration_ms       INTEGER,
  ok                INTEGER NOT NULL,
  error_msg         TEXT,
  effort            TEXT,              -- v3：**实际进请求体**的 reasoning_effort；没发是 NULL（不是 'none'）
  effort_dropped    INTEGER NOT NULL DEFAULT 0,  -- v3：1 = 本来要发却没发（不支持 / 被 400 拒后去掉）
  created_at        TEXT NOT NULL
);

-- ── 问答历史（T3.12，v2 新增）────────────────────────────
-- 一问答一行，**单轮**：不存多轮上下文，也不存 session 概念。
-- sources_json 存的是"当时被引用的片段快照"（含 content），
-- 因为 chunk 可能被重建或删掉，历史要能原样回看。
CREATE TABLE ask_log (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  question          TEXT    NOT NULL,
  answer            TEXT    NOT NULL DEFAULT '',
  sources_json      TEXT,             -- JSON 数组：[{n,item_id,item_title,chunk_id,source,snippet,content}]
  match_type        TEXT,             -- fts | like | none
  fallback          TEXT,             -- none | like_short_query | vector_disabled | vector_below_threshold
  no_result         INTEGER NOT NULL DEFAULT 0,  -- 1 = 检索为空，未调模型
  error_code        TEXT,             -- 非空表示这次问答出错（answer 只含已流出的部分）
  prompt_tokens     INTEGER,
  completion_tokens INTEGER,
  duration_ms       INTEGER,
  created_at        TEXT    NOT NULL
);
CREATE INDEX idx_ask_time ON ask_log(created_at DESC);

-- ── v4（M9）工作区：一层平级，不嵌套 ──────────────────────
-- 同名允许，不做唯一约束；删工作区不删内容（SET NULL）。
CREATE TABLE workspace (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,                  -- 展示名，≤20 字
  color       TEXT,                           -- 主题色 id；空 = 默认色
  sort_order  INTEGER NOT NULL DEFAULT 0,     -- 手动排序，只影响左栏显示
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_ws_sort ON workspace(sort_order, id);

-- ── v4（M9）原件元数据 ────────────────────────────────────
-- 独立成表：一份试卷可挂「卷面 + 答案」两个文件；文件元数据（页数、识别状态）
-- 变化频繁，与内容字段的读写节奏不同。
CREATE TABLE item_file (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id        INTEGER NOT NULL REFERENCES knowledge_item(id) ON DELETE CASCADE,
  role           TEXT NOT NULL DEFAULT 'main',  -- main | answer | attachment
  original_name  TEXT,                          -- 仅展示与导出用
  ext            TEXT,
  mime           TEXT,
  size           INTEGER,                       -- 字节
  sha256         TEXT,                          -- 同文件不重复占盘
  stored_path    TEXT,                          -- 相对数据目录，不存绝对路径
  page_count     INTEGER NOT NULL DEFAULT 0,    -- PDF/PPT 页数；其他为 0
  has_text_layer INTEGER NOT NULL DEFAULT 0,    -- 1 = PDF 有文本层；只用于校验与 L3 定位
  ocr_status     TEXT NOT NULL DEFAULT 'none'   -- none | pending | running | done | partial | failed
);
CREATE INDEX idx_file_item ON item_file(item_id);
CREATE INDEX idx_file_hash ON item_file(sha256);

-- ── v4（M9）逐页文本 ──────────────────────────────────────
-- 识别很贵（实测约 2.8 秒/页）必须缓存；也是 L3「跳到第 N 页」的唯一依据。
-- 文字与页图必须同页配对，这是「认错也看得出来」的唯一保障。
CREATE TABLE item_page (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id       INTEGER NOT NULL REFERENCES knowledge_item(id) ON DELETE CASCADE,
  file_id       INTEGER REFERENCES item_file(id) ON DELETE CASCADE,
  page_no       INTEGER NOT NULL,                 -- 从 1 开始
  text          TEXT NOT NULL DEFAULT '',        -- 主来源是本地识别，永不覆盖
  source        TEXT NOT NULL DEFAULT 'ocr',     -- ocr | text_layer | extract
  avg_conf      REAL,                            -- < 0.85 前端标黄
  image_path    TEXT,                            -- 页图相对路径
  text_reviewed TEXT                            -- 复核/校对结果另存，原始 text 可回退（需求 §8.5）
);
CREATE UNIQUE INDEX idx_page_no   ON item_page(file_id, page_no);
CREATE INDEX        idx_page_item ON item_page(item_id, page_no);
```

## 3. 字段语义要点（容易理解错的地方）

| 字段 | 约定 |
|---|---|
| `title` | 整理 Agent 生成，**≤20 字**（2026-11-06 裁决）。创建时的值只是占位（缺省取正文首行前 40 字），整理成功即被重写——**手填标题也会被覆盖**，要保留请在整理后用 PATCH 改。PATCH 与 AI 同一口径，超 20 字返回 422 |
| `content_hash` | `sha256(raw_content.encode('utf-8'))` 的 hex。用于"同内容不同 URL"的重复识别 |
| `source_url` | 唯一索引带 `WHERE source_url IS NOT NULL`，因为粘贴文本没有 URL |
| `key_points` | JSON 数组字符串 `["点1","点2"]`，不是换行分隔文本。读取时 `json.loads` |
| `tags` | 同上，JSON 数组字符串 |
| `status` | `organizing` 是中间态，用于防止重复触发整理 |
| `truncated` | 送模型时若原文超过 **50,000 字符**采样阈值（前 40,000 + 末 10,000）则置 1，前端详情页需提示。依据 ADR-021：约束是成本而非上下文能力（1M token） |
| `agent_task.progress` | 0–100 整数。转录按音频时长百分比，抓取按阶段固定值（10/50/90） |
| `llm_call_log.reasoning_tokens` | 思考 token 数（ADR-022）。DeepSeek 默认带思考，实测简单任务里它占输出 token 的绝大部分，是成本观测的主要指标；无该字段时记 NULL |
| `llm_call_log.effort` | **实际进请求体**的 `reasoning_effort`。没发就是 `NULL`——**不许写 `'none'`**：「用户关掉思考」与「这服务不支持」是两件事，混成一个值就再也分不开了（ADR-028） |
| `llm_call_log.effort_dropped` | 1 = 本来要发却没发：provider 声明 `supports_effort=false`，或服务 400 拒绝后被自动去掉。这个信息**只在日志里有**，事后靠模型名/耗时推不出来（ADR-028） |
| `question.answer` | 单选 `"A"`；多选 `["A","C"]`（有序数组，比较时转集合）；判断 `true/false`；简答为参考答案文本 |
| `quiz_attempt.is_correct` | 三态：1 正确 / 0 错误 / NULL 待人工判断。**NULL 不等于错** |
| `review_item.due_at` | **UTC** ISO 时间字符串。比较在 Python 侧用 `datetime.fromisoformat()` 转 aware datetime 再做，**不许在 SQL 里比字符串**：本地时间带 `+08:00`、UTC 带 `+00:00`，混在一起字典序必错（2026-11-07 裁决，见 `HANDOFF.md` 待裁决区） |
| `study_session.duration_seconds` | 累计**有效**时长，暂停期间不计入。以 `start_time` 为基准推算 |
| `structured_note` | Markdown 源码。**用户可编辑**（源码编辑 + 实时预览，不是富文本） |
| `note_edited` | 1 表示用户手改过。重新整理会覆盖它，所以前端必须先确认 |
| `chunk.source` | `raw` / `note`。检索不区分，但重建时按 source 分别删 |
| `chunk_vec.embedding` | 512 维 float32，**已做 L2 归一化**，因此余弦相似 = 点积。换 embedding 模型必须重建此表 |
| `chunk_vec` 的存在性 | 该表**可能不存在**（sqlite-vec 加载失败时）。任何读它的代码必须先判断，不能假设一定在 |
| `ask_log.sources_json` | **片段快照**，不是外键。存了 `content` 全文，所以 chunk 被重建或删除后历史仍能原样回看 |
| `ask_log.no_result` | 1 = 检索判空、**没有调用 LLM**（`prompt_tokens` 为空）。这批记录是 M4 出题时"该补什么内容"的现成线索 |
| `ask_log.error_code` | 非空表示这次问答中途失败，此时 `answer` 只含已经流出的部分，不得当作完整答案回放 |
| `knowledge_item.kind` | `material` / `exam` / `image` / `note`。**决定「整理」怎么跑**：试卷不写笔记、只出卷面概览；图片只出文字 + 一句说明（需求文档 §5.6） |
| `knowledge_item.workspace_id` | NULL = 未归类。删工作区走 `ON DELETE SET NULL`，内容回落到未归类，不跟着删 |
| `item_file.stored_path` | **相对数据目录**，不存绝对路径；整个数据目录复制到另一台机器仍可用（v0.3 验收第 5 条） |
| `item_file.has_text_layer` | 1 只表示 PDF 里有文本层，**仅用于交叉校验与 L3 定位**；`0` 不阻止识别、`1` 也不跳过识别（ADR-033） |
| `item_file.ocr_status` | `none`/`pending`/`running`/`done`/`partial`/`failed`；`partial` = 有页面一个字都没认出来，原文页标「没认出来，可重试」 |
| `item_page.page_no` | 从 1 开始；与 `image_path` 的页图**永远同页配对**，不许分开存（红线：认错也看得出来的唯一保障） |
| `item_page.source` | `ocr`（默认）/`text_layer`（**仅当整页识别为空时的兜底**，前端要标出来）/`extract`（docx/pptx/xlsx 抽取） |
| `item_page.avg_conf` | 识别平均置信度；< 0.85 前端标黄，复核时默认展开 |
| `item_page.text` / `text_reviewed` | 原始识别文本**永不覆盖**；校对/复核结果另存 `text_reviewed`，任何时候能回退（需求文档 §8.5） |
| `question.origin` / `number` | `imported` = 试卷导入，按 `number`（原卷题号）排序供「按卷练」；AI 生成时 `origin='ai'`、`number` 为 NULL |

## 4. 复习间隔规则（M4 实现，刻意保持简单）

```
答错：interval = 1, lapses += 1, due_at = now + 1 天
答对且 interval < 7：interval *= 2（1→2→4）
答对且 interval >= 7：interval = 15
待复习列表：WHERE due_at <= now ORDER BY due_at LIMIT 20
```

不做 SM-2 / FSRS。此规则的收益/成本比已经足够，复杂算法留 v2。

## 5. 级联与清理

- 删 `knowledge_item` → `chunk` 靠外键 CASCADE；`chunk_fts` 靠触发器同步；`question` 靠 CASCADE；`review_item` 靠 `question` 的 CASCADE 连带
- 删条目后必须验证 `chunk` 与 `chunk_fts` **均无残留**（`verify_m1.py` 覆盖此项）
- `html_artifact` 不随条目删除而删除（它是独立产物，可能已下载分享）
- `ask_log` **不跟任何表级联**，也不随条目删除而清理：它是「当时的问答快照」，
  条目删了但"我问过什么、当时答了什么"仍应可查（配合 `sources_json` 存片段正文）
- 删 `workspace` → 只把 `knowledge_item.workspace_id` 置 NULL，**不删任何内容**
- 删 `knowledge_item` → `item_file` / `item_page` 靠 CASCADE 连带；磁盘上的原件与页图由**应用层**清理，
  DB 不管文件（删库记录不等于删文件，反过来也不许只删文件留记录）

## 6. 派生数据的重建规则（重要，容易漏）

| 触发动作 | 必须做的事 |
|---|---|
| 创建条目 / 更新 `raw_content` | 删除该条目 `source='raw'` 的 chunk，用 chunker 重新切块写入 |
| 保存 `structured_note`（PATCH） | 删除 `source='note'` 的 chunk，用**同一个** chunker 重新切，`source='note'`；同时置 `note_edited=1` |
| 重新整理（organize） | 写入新的 `structured_note` → 按上一条重建 note chunk；若 `note_edited=1`，前端必须先让用户确认"将覆盖手改内容" |
| 删除条目 | 外键级联，无需手动 |

**不变量**

- `chunk_fts` 只由触发器维护，任何代码都不许直接写它
- 「删除后 `chunk_fts` 无残留」按 **SQL 可查询**判定：主虚拟表按 `rowid` 查不到、按 `MATCH` 搜不到即为干净。影子表 `chunk_fts_data` 里留下的明文 term 属 FTS5 实现细节，**不计入残留**，也不因此去执行 `optimize`（那会直接写 `chunk_fts`，与上一条冲突）。2026-11-06 裁决，验收脚本 `verify_m1.py` 按此口径实现
- `position` 在各自 `source` 内部独立递增，不要求全局连续
- 用户笔记进 chunk 的意义：**手写的内容也能被搜到、能进问答上下文**。否则"我辛苦补的笔记搜不到"会很难受

## 7. 思维导图不落库

`GET /api/knowledge/{id}/mindmap` **每次现场生成**，不存表。

**理由**：`structured_note` 可被随时编辑，存快照必然与正文不一致。生成成本约 2–5ms，不值得为它引入缓存与失效逻辑。

**派生规则（确定性，不经 LLM）**

1. 按行扫描 `structured_note`，`^(#{1,6})\s+(.+)$` 取为节点，层级 = `#` 个数
2. 第一个节点为根；若整篇无标题，则以条目 `title` 为根，把 `key_points` 的每一项作为一级子节点
3. 每个标题下紧邻的 `-` / `*` 列表项，作为该标题的叶子节点（最多取 8 个，防止爆炸）
4. 节点文字超过 24 个字符截断为 22 字 + `…`
5. 层级深的节点超过 4 级的，折叠进第 4 级（导图是概览，不是全文）

**约束**

- 输出严格为 `<svg viewBox="0 0 W H">…</svg>` 片段，不含 `<script>`、不含外链
- 所有文本节点必须 XML 转义（`& < > " '`）
- 颜色与字体全部内联，不依赖 CSS 变量——因为这段 SVG 要被原样嵌进离线 HTML

## 9. 配置文件 `settings.json`（非表结构，但同样受本契约约束）

位置：`<数据目录>/settings.json`（源码 = `./data/settings.json`，安装包 = `%APPDATA%/Cairn/settings.json`）。
密钥**不在**这里，只在 `.env`（红线 7）。

```json
{
  "version": 1,
  "llm": {
    "active": "deepseek",
    "providers": {
      "deepseek": {"label": "DeepSeek", "base_url": "https://api.deepseek.com",
                   "key_env": "LLM_API_KEY", "supports_effort": true,
                   "models": ["deepseek-flash", "deepseek-reasoner"]},
      "custom":   {"label": "OpenAI 兼容", "base_url": "",
                   "key_env": "ALT_API_KEY", "supports_effort": false, "models": []}
    },
    "tasks": {
      "organizer": {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "asker":     {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "quizzer":   {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"},
      "grader":    {"provider": "deepseek", "model": "deepseek-flash", "effort": "low"}
    }
  },
  "appearance": {"theme": "paper", "mode": "system", "font_size": "md"},
  "components": {}
}
```

**字段语义**

| 字段 | 取值 | 说明 |
|---|---|---|
| `llm.active` | `deepseek` \| `custom` | 新任务的默认 provider；`tasks[*].provider` 缺省时回落到它 |
| `providers.<id>.key_env` | 环境变量名 | 该 provider 的 Key 存在 `.env` 的哪个键里；只存**变量名**，不存值 |
| `providers.<id>.supports_effort` | bool | `false` 时请求体**不带** `reasoning_effort`（多数第三方兼容服务会 400，ADR-026） |
| `providers.<id>.models` | string[] | 上次探测到的候选；可为空，空则允许手输 |
| `tasks[*].provider/model` | string | 空串 = 用 `llm.active` / 该 provider 的 `models[0]` |
| `tasks[*].effort` | `none`\|`low`\|`medium`\|`high` | 映射到 `reasoning_effort`；`none` 表示不带该字段 |
| `appearance.theme` | `paper`\|`notes`\|`chestnut`\|`docs`\|`study`\|`teal` | 6 套预设，见 M6 §3 |
| `appearance.mode` | `light`\|`dark`\|`system` | `system` 跟随 `prefers-color-scheme` |
| `appearance.font_size` | `sm`\|`md`\|`lg` | 三档字号，改 `--fs-*` 的缩放基准 |
| `components` | object | 组件安装状态，M8 填充；M6 阶段恒为 `{}` |

**读写规则（`services/prefs.py` 独占，别处不许直接读这个文件）**

1. **缺省即合并**：`默认值 ← 文件` 深合并，文件缺哪个键就补默认值。手改坏一个键不影响其余配置
2. **损坏即备份**：JSON 解析失败 → 原文件改名 `settings.json.bad-<时间戳>`，用默认值继续跑，日志记 WARN
3. **原子写**：先写 `settings.json.tmp` 再 `os.replace`，断电不会留半截文件
4. **按 mtime 失效缓存**：用户手改 JSON 后下一次读取就生效，不用重启
5. **未知键保留**：文件里有、默认值里没有的键原样保留（向前兼容），但不下发到前端

## 10. 组件目录布局（M8 用，M6 只登记）

M8 把向量 / 语音 / 浏览器三个重组件从安装包里挪出来，装到数据目录下：

```
<数据目录>/components/
├─ <id>/                 # id ∈ embed | asr | browser | ocr（M9 起第四个，仍是按需下载）
│  ├─ manifest.json      # {id, version, min_app_version, files:[{path, sha256, size}]}
│  └─ ...                # 组件自身的文件（venv / 模型 / 浏览器内核）
└─ .staging/             # 下载中的临时目录，成功后整体 rename 成 <id>/
```

- `manifest.json` 的 `min_app_version` 由启动时校验，版本漂移就提示重装该组件
- 缺组件时后端必须走降级路径（向量 → 纯全文检索并回 `fallback=vector_component_missing`、
  转录 → 报 `COMPONENT_MISSING`（`detail=asr`）、浏览器渲染 → 报 `FETCH_BROWSER_UNAVAILABLE`）。
  **M8 定案**：不再新增 `TRANSCRIBE_NO_ASR`（本文件旧版写法），"缺组件"统一用一个码，
  前端按 `code` 就能给出「去设置 → 下载」这一条人话
- 卸载 = 删除 `components/<id>/`；**不影响 `data.db` 与模型之外的任何用户数据**
