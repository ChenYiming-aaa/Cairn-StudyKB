# Cairn v0.1.0 · 真机实测手册

> **作用域**：v0.1.0 安装版的真机实测清单，只对 0.1.0 这一版有效。做 v0.2 的优化不必读它；需要复验 v0.1.0 交付态时按本文逐条走。
> **测什么**：已经装好的桌面版（`D:\知识库\Cairn`），不是源码环境。
> **为什么测**：开发期跑的是 `verify_m1..m5`（接口层、临时数据目录）。安装版是另一条链路：
> Electron 壳 + 打包后的 Python 后端 + 用户自己配的 Key + 用户自己的库。**只有这条链路跑通，才算能交付。**
> **产出**：一份「能不能推荐给别人用」的结论；不能的话，卡在哪条、附复现步骤和日志。

## 1. 三条铁律

1. **先备份再动手。** 后面有删条目、改 `.env`、改复习时间、卸载重装这类动作，
   一次 `Copy-Item` 就能省掉重来一遍的代价。
2. **每步留证据。** 光说"我看它是好的"没用。证据三件套：
   - 截图：`阶段-编号-结果.png`，例如 `05-C2-采集失败.png`
   - 日志片段：`shell.log` / `app.log` 里对应的那几行
   - 对账输出：`python tools\audit_kb.py` 的文本（贴进记录）
3. **已知限制不报缺陷。** 第 14 节列的都是"设计如此"，验到就当 OBSERVE 记一行，别开缺陷单。

---

## 2. 判定口径

| 标记 | 含义 | 后续动作 |
|---|---|---|
| **PASS** | 与预期一致 | 记录实测值（尤其是耗时、条数） |
| **FAIL** | 与预期不符，且不是已知限制 | 开缺陷单（第 15 节模板），附证据 |
| **BLOCKED** | 前置条件不具备（如模型下载失败、断网） | 记录原因，先跳过，别硬判 |
| **OBSERVE** | 能用，但体验/表现值得记一笔 | 只记录，不判定 |

严重级别：**P0** 装不上/打不开/数据丢失/核心链路断；**P1** 主要功能不可用或有错；
**P2** 可用但明显别扭；**P3** 文案、样式、边角。

**冒烟（S 组）任何一条 P0 级 FAIL，就停下来修，不要继续往下测**——后面的用例都建立在这条链路上。

## 3. 开工前 5 分钟

### 3.1 备份（必做）

```powershell
# 先关掉 Cairn（见 3.2），再备份
$dst = "$env:USERPROFILE\Desktop\Cairn-备份-$(Get-Date -Format yyyyMMdd-HHmm)"
Copy-Item "$env:APPDATA\Cairn" $dst -Recurse
"备份到 $dst"
```

备份里最重要的两个文件：`data.db`（全部内容）和 `.env`（Key）。`logs\` 也一起带上，出问题时能翻。

### 3.2 关干净

关窗口后确认进程真的退了：

```powershell
Get-Process Cairn,cairn-backend -ErrorAction SilentlyContinue | Select-Object Name,Id
```

还在就 `Stop-Process -Name Cairn,cairn-backend -Force`。**只要留着一个后端进程，重启就会有端口/锁冲突，
测出来的现象全是假的。**

### 3.3 一条命令对账（随时可用）

```powershell
cd C:\Users\cwqjk\Desktop\知识库agent开发
python tools\audit_kb.py
```

它只读 `%APPDATA%\Cairn\data.db`，打印「条目 / 索引 / 任务 / 题目 / 作答 / 复习 / 专注 / 学习页」的真实计数，
并做一致性检查（有 ready 条目却没有 chunk、任务卡住 15 分钟、条目 failed 等）。

用法：
- `python tools\audit_kb.py --json` → 存档一份对比用
- `python tools\audit_kb.py --make-due 3` → **写操作**：把复习到期时间整体前移 3 小时（第 9 节时间旅行用）
- 退出码 0 = 没发现异常；2 = 有需要留意的地方

现在跑一次，应该是全 0。**记住这个基线**，后面每完成一组就再跑一次，界面上看到的东西要和它对得上。

### 3.4 素材准备

| 用途 | 素材 | 说明 |
|---|---|---|
| 长文本（测整理质量） | 本仓库 `README.md` 全文 | 约 4000 字，有标题层级，整理效果可判断 |
| 结构化文本（测笔记层级） | `docs\dev\运行与打包.md` | 有二级标题和代码块，能看 AI 有没有读懂结构 |
| 短文本（测下限） | 随便 20 来字 | 看它会不会拒绝，或者整理出一堆废话 |
| 网页文章（测抓取） | 你自己常看的一篇技术长文 | 优先静态站；MDN 中文、阮一峰博客较稳 |
| 已知会失败的链接 | `https://example.com/this-page-does-not-exist-12345` | 测失败路径 |
| 视频（P2，可跳过） | B 站有字幕的视频 | 首次要下 539 MB 语音模型，见第 13 节 |

## 4. 冒烟（S 组 · 15 分钟）

**这一组过了，才谈得上能用。**

### S1 冷启动

- **做什么**：确认无残留进程 → 双击桌面 `Cairn` → 秒表开始计
- **应看到**：窗口出现，没有白屏；顶栏右侧是绿色「已连接」；左侧分类树显示「全部条目 0」
- **证据**：`shell.log` 末尾三行关键日志
  ```
  握手成功：N 次 / XXXXms
  首屏加载完成：距进程启动 XXXXms
  ```
- **判定**：热启动（刚关就开）≤ 5000 ms 为 PASS；冷启动（重启机器后第一次）放宽到 ≤ 8000 ms，
  **实测值必须记下来**——这是发布说明里唯一的性能硬指标
- **不合格先看**：日志里有没有 `spawn D:\知识库\Cairn\resources\backend\cairn-backend.exe`；
  `app.log` 有没有 `ERROR` / `Traceback`；窗口是不是变成了"启动失败"页（那页会直接给你日志路径）

### S2 界面自检

- **做什么**：逐个点导航；按 `Alt` 呼出菜单 → `View` → `Toggle Developer Tools` → Console 页签
- **应看到**：7 个页签（知识库 / 仪表盘 / 检索问答 / 学习页 / 练习 / 复习 / 任务）切换不白屏；
  右上角有「专注」和「＋ 采集内容」；Console 没有红字
- **判定**：Console 错误 0 条为 PASS。有红字就截图，并把它当成缺陷线索，不要忽略

### S3 空库文案

- **应看到**：
  - 知识库：「知识库还是空的 / 点右上角「采集内容」开始」
  - 仪表盘：今日待整理 0、今日待复习 0、连续学习 0 天
  - 复习：「今天没有要到期的题」
  - 练习左栏：「还没有可出题的条目（需要先整理成 ready）」
- **判定**：文案准确、没有 0/NaN/空白块。空库不崩，是很多同类产品翻车的地方

### S4 粘贴入库

- **做什么**：`＋ 采集内容` → 「粘贴文本」→ 正文粘贴 README 全文 → **标题留空** → 「加入知识库」
- **应看到**：右下角绿色提示「已加入「…」」；面板关闭；列表出现 1 条，状态徽章「待整理」
- **对账**：`items.total = 1`，`by_status = {pending: 1}`，`chunk_raw = 0`（还没整理，正常）
- **判定**：标题留空也能入库，说明有临时标题兜底

### S5 单条整理（这一步在验证 Key）

- **做什么**：选中该条目 → 右上「开始整理」
- **应看到**：状态变「整理中」（徽章在闪）→ 约 20–90 秒后变「就绪」；
  摘要页签出现：AI 重写的标题（≤20 字）、摘要、3–6 条要点；分类和标签出现在标题下方
- **同时看**：任务页出现 `整理` 任务（完成）+ `向量索引` 任务
- **首次会有一次 92 MB 的向量模型下载**：`app.log` 出现 `加载 embedding 模型 …`。
  网慢时这一步要几分钟，**不是卡死**；期间界面照常用，问答会走全文检索
- **判定**：三项都齐全（摘要 / 要点 / 笔记）才算 PASS。只有摘要没有笔记，说明整理链路断了
- **失败必看**：任务页该任务的错误码。`LLM_NO_KEY` = Key 没生效；`LLM_HTTP_401` = Key 错；
  `LLM_HTTP_402` / `429` = 余额或限流；`LLM_TIMEOUT` = 网络或模型太慢

### S6 问一次

- **做什么**：检索问答 → 问一个这份材料里**确实有答案**的问题（例：「这个工具的数据存在哪里？」）
- **应看到**：答案分条，每条末尾带 `[n]`；右侧「来源」列出被引用的片段；点 `[n]` 跳到条目原文并高亮该段
- **判定**：引用能点、能跳、能对上原文。只给答案不给来源 = FAIL（这是产品的核心承诺）

### S7 出 5 道题做完

- **做什么**：练习 → 选中该条目（默认已是「单选」「5 题」）→ 难度改「基础」→ 点「出题」
- **应看到**：题面逐题浮现；一题一屏；选完点「确认作答」立刻给对错和解析；最后一题按钮变「交卷并看结果」；
  结果页给出正确率 + 逐题回看 + 「再来一组」
- **对账**：`quiz.questions = 5`（或更多，可能去重后少于 5），`attempts = 5`
- **判定**：答错的题在结果页能被指出来，且 `audit` 里 `wrong ≥ 1`（后面复习要靠它）

**S1–S7 全过 → 这个版本"能用"。** 下面按兴趣深挖，不用全做。

## 5. 采集（C 组）

### C1 拖文件入库

拖一个 `.md` 到窗口任意位置 → 面板自动切到「粘贴文本」并带上正文 → 改个标题 → 「加入知识库」。
**预期**：正文完整、字数统计对得上；标题能改；入库后状态「待整理」。

### C2 文章链接采集

`＋ 采集内容` → 「链接采集」→ 粘贴文章 URL → 「开始采集」。
**预期**：按钮变「正在采集…」；任务页出现 `网页采集`，阶段依次走 `抓取正文` → `写入库`；
完成后提示「采集完成，已加入知识库」，面板不自动关，可以点「去看看」跳过去并选中它。
**判定**：正文抽得干净（没有导航、广告、版权尾巴）；标题是文章标题而不是站点名。

### C3 同一条链接再采一次

同一个 URL 再走一遍「开始采集」。
**预期**：提示「该链接已在知识库中（条目 #N）」，**不新增条目**，面板切成完成态。
**对账**：`items.total` 不变。

### C4 坏链接

粘贴 `https://example.com/this-page-does-not-exist-12345`。
**预期**：明确告诉你失败原因（不是转圈到天荒地老）；任务页该任务 `失败` 并有错误码；
任务行上有「重试」；**不产生**一条空内容的 pending 条目。
**对账**：`items.total` 不变；`tasks.recent_failed` 里有这一条。

### C5 极短正文

粘贴 20 来个字入库。**预期**：允许入库；整理后大概率得到很空的结果——记 OBSERVE，不算缺陷
（设计上没做最小长度限制，这是取舍）。

### C6 超长正文

找一段 > 5 万字的内容粘贴（没有就跳过）。
**预期**：入库后详情页出现提示「原文超过 50,000 字符，整理时只采样前 40,000 字与末 10,000 字。」
**对账**：`items.truncated = 1`。

### C7 重复内容（不同 URL）

把同一篇文章的 `?utm_source=xxx` 版本也采一次。**预期**：变成两条 —— 这是**已知限制**，记 OBSERVE。

## 6. 整理（O 组）

### O1 字段完整性

对 3 条不同类型的内容各整理一次，逐条检查：

| 字段 | 期望 |
|---|---|
| 标题 | 被重写成短标题（≤20 字），不是原文第一句 |
| 摘要 | 2–4 句，说清"这篇讲了什么"，不是目录复述 |
| 关键点 | 3–6 条，能独立看懂 |
| 笔记 | Markdown，有 `##` 层级，不是把原文再抄一遍 |
| 分类 | 一个合理的中文分类名 |
| 标签 | 若干，不带 `#` 前缀（界面上会加） |

**判定**：6 项里 5 项合格算 PASS；笔记只是原文复读 = FAIL（它没"理解"，只是搬运）。

### O2 批量整理

左侧列表上方出现「整理待处理 N」→ 点它。
**预期**：提示「已派发 N 个整理任务」；任务页一次性出现 N 个 `整理` 任务，互不阻塞；
全部完成后列表状态都变「就绪」。

### O3 手改笔记与「重新整理」（有坑，按事实测）

**先看这段，别按 README 记。** README 写的是「手改过的笔记不会被覆盖」，但代码里
`save_organize_result()` 是**无条件覆盖** `structured_note` 的，也不把 `note_edited` 复位；
条目详情页的徽章提示反而写对了：「整理会覆盖手改内容」。所以按下面这组事实测：

1. 条目详情 → 「结构化笔记」页签 → 改两行 → 保存
2. **预期**：标题下出现「笔记已手改」徽章；索引自动重建（几秒）
3. 再点「重新整理」
4. **预期（按代码）**：AI 生成的笔记覆盖你的修改，但「笔记已手改」徽章**仍然在**

第 4 步的「内容被覆盖了、徽章还说你改过」是状态自相矛盾，记 **P2 缺陷**（不是已知限制）。
**对账**：`items.note_edited` 覆盖前后都是 1。

> 这条同时是一个文档缺陷：README 的承诺与实现不符。测完把结论给我，改文案还是改跳过逻辑，需要你定。

### O4 无 Key 时的表现（可选，P2）

临时把 `%APPDATA%\Cairn\.env` 里的 Key 改坏 → 重启 → 点整理。
**预期**：明确提示去配 Key，**不留下一条注定失败的任务**。
验完记得改回来（或用备份的 `.env` 覆盖）。

## 7. 检索问答（A 组）

### A1 命中

问 5 个库里有答案的问题（跨条目问更好，例如"两份材料都提到了什么"）。
**预期**：答案按点分条；每条带 `[n]`；右侧来源能点。

### A2 引用跳转

点任意 `[n]`。**预期**：跳到对应条目 + 自动切到「原文」页签 + 高亮那一句。

### A3 零命中（重点）

问一个**库里绝对没有**的问题（例如「量子色动力学的渐近自由是什么」）。
**预期**：直接说库里没有相关内容，**不编造、不给万能答案**；历史里这条标「无结果」。
**判定**：这一条 FAIL 的话，整个问答功能不可信——它等于在编。

### A4 关键词搜原文

输入两字词（例如「番茄」「索引」）回车。
**预期**：右侧列出命中的原文片段，带条目名；没有就说「没有匹配…的原文片段」。

### A5 历史回看

去别的页面转一圈再回来 → 打开问答历史 → 点一条旧记录。
**预期**：能还原当时的回答和来源；**不重新调模型**（看 `llm_call_log` 计数不变）。

### A6 向量降级（可选）

把 `%APPDATA%\Cairn\models\embedding` 改名 → 重启 → 再问一次。
**预期**：界面**明说**当前是纯全文检索（不是静默降级）；检索仍能用。

## 8. 练习（P 组）

| 编号 | 做什么 | 应看到 |
|---|---|---|
| P1 | 四种题型各出一组（单选/多选/判断/简答） | 题面格式正确，选项没有「A. A. xxx」这种双编号 |
| P2 | 三档难度各一轮（基础/理解/应用） | 应用档的题明显要推理，不是换个说法问同一件事 |
| P3 | 题数 5 / 10 / 20 | 出题数与选择一致（去重后略少可接受） |
| P4 | 简答题写一半、答偏 | 交卷后由模型批改，指出漏掉的要点；批改失败时标「待人工判断」，不直接判错 |
| P5 | 出题中点「停止生成」 | 立刻停，已生成的题保留，界面回到可再出题的状态 |
| P6 | 结果页 | 正确率、逐题回看（含你的答案与正确答案）、「再来一组」都能用 |

**多选专项（OBSERVE）**：README 里自己写了"偶尔出现四个选项全对"。出 3 组多选，
记下是否复现。**复现了不算缺陷**，但要记下条目和题目 id，方便后面调 prompt。

## 9. 复习（R 组，含时间旅行）

新答错的题**明天**才到期，所以当天要闭环得动一次库。顺序别乱：

### R1 先制造错题

在 P 组里故意答错 3 道（客观题）+ 1 道简答答偏。
**对账**：`review.tracked ≥ 3`、`review.due_now = 0`、`review.last_wrong ≥ 3`。

### R2 今天看不到到期题

## 14. 已知限制（验到只记 OBSERVE，不报缺陷）

1. 安装包未签名，SmartScreen 会拦一次（更多信息 → 仍要运行）
2. 冷启动 6–7 秒（热启动 4 秒左右），首启要建表 + 杀软扫 1.4 GB
3. 卸载耗时长（约 10 分钟），体积大
4. URL 只去 fragment 不去 query，`?spm=` / `?utm_source=` 会让同一篇变两条
5. 多选偶尔出现"四个选项全对"
6. 题目 / 作答 / 复习记录无保留策略，长期会一直长
7. 只有 Windows x64 安装包
8. 在线试用（github.io）是静态演示，生成类操作会提示"请下载桌面版"
9. 前端视觉与交互还有优化空间——这版优先保证功能正确

## 附录 B · 故障对照

| 现象 | 先查什么 | 常见原因 |
|---|---|---|
| 窗口显示"启动失败"页 | 页面上给的日志路径，`shell.log` 末尾 | 后端没起来（缺文件 / 端口被占 / 杀软拦截） |
| 顶栏"未连接"红点 | `app.log` 有没有 `Cairn 启动完成` | 后端崩溃，或重启时旧进程没退 |
| 整理一直"整理中" | 任务页进度；`llm_call_log` 最近一条 | Key 错 / 余额不足 / 网络慢 / 模型超时 |
| 整理报 `LLM_NO_KEY` | `.env` 里有没有 `LLM_API_KEY`；重启一次 | Key 没写进去，或写了但没热加载 |
| 问答总说"库里没有" | `chunk_raw` 是否为 0 | 条目没整理完，或索引没建起来 |
| 向量一直用不上 | `models\embedding` 是否有 `.safetensors` | 模型没下完（网断）——会降级成全文检索，不算故障 |
| 复习页空 | `review.due_now` | 新错题明天才到期，用 `--make-due` 验证 |
| 卸载卡住 | 任务管理器看安装器进程 | 1.4 GB 文件 + 杀软扫描，等 10 分钟 |
